Before You Start — Cost & Safety

Do not start, trigger, or run any Databricks pipeline, job, or SQL warehouse from the UI or CLI as part of this HOL beyond what's in these notebook cells. Everything here runs as ordinary notebook cells on your already-running cluster.

If a cell asks you to wait for a streaming query, that query stops itself once it's processed the available files — trigger(availableNow=True) does not run indefinitely.

Phase 1 — customers (CSV, the Worked Example)

Read carefully — Phases 2 and 3 reuse this exact pattern
customers_df = (
    spark.readStream
    .format("cloudFiles")
    .option("cloudFiles.format", "csv")
    .option("cloudFiles.schemaLocation", SCHEMA_PATH)
    .option("cloudFiles.inferColumnTypes", "true")
    .option("cloudFiles.schemaEvolutionMode", "addNewColumns")
    .option("header", "true")
    .load(SOURCE_PATH)
    .withColumn("_source_file", col("_metadata.file_path"))
    .withColumn("_ingested_at", current_timestamp())
)
customers_df.writeStream.format("delta").outputMode("append") \
    .option("checkpointLocation", CHECKPOINT_PATH) \
    .option("mergeSchema", "true") \
    .trigger(availableNow=True) \
    .toTable("gbmart.bronze.customers")

If you already did Day 3 HOL 2: this cell targets the exact same table and checkpoint. Re-running is safe — the checkpoint means no duplicate rows land.

Phase 2 — addresses (CSV, With a Multi-Line Gotcha)

Same pattern as Phase 1, plus one real-world wrinkle

Imagine a spreadsheet cell containing a street address that wraps onto a second line. A naive CSV reader sees that line break and thinks it's a brand-new row — splitting one real address into two broken ones.

Some AddressLine1 values contain embedded line breaks. Without handling this, a plain CSV parser would split them into extra, wrong rows.

.option("header", "true")
.option("multiLine", "true")
.option("escape", '"')

Bronze preserves nested structs/arrays as-is — no flattening. Access directly: df.select("specs.warranty_months", "supplier_info.name"). Silver decides whether to flatten.

Key Takeaways

One Pattern, Two Formats

cloudFiles.format is the only thing that changes between CSV and JSON — checkpoint, schema location, and audit columns are identical.

Nested JSON Lands As-Is

Struct and array columns are preserved; dotted access works directly. Silver decides whether to flatten.

CDC Tables Aren't Rebuilt
