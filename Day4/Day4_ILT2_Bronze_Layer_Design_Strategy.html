Bronze Is Not a Staging Area

Staging Area (wrong mental model)Bronze Layer (correct)
Temporary — deleted after processingPermanent — kept forever
No audit trailFull audit trail (when + from where)
No time travelDelta time travel across all historical loads
Can't reprocessCan always reprocess Silver from Bronze
Bronze is your insurance policy. If Silver has a bug, reprocess from Bronze — faster, cheaper, and the source may have already changed.

The 3 Golden Rules of Bronze

1. Land Raw, Transform NeverNo renaming, no casting, no joins, no filters, no aggregation. The only columns Bronze adds are audit columns.
2. Idempotent WritesRe-running produces the same result — no duplicates. Autoloader uses checkpoints; CDC uses the WAL replication-slot offset.
3. Never Delete, Only AppendA source DELETE becomes a DELETE event row, not a row removal. No table in GlobalMart's Bronze ever uses overwrite mode.

Audit Columns — Kept Minimal

GlobalMart's real tables deliberately don't add _source_system or _batch_id — every extra column is one more thing to keep correct forever. Add a column only when a real query will filter or group by it.

Unity Catalog Naming — the Real, Live Pattern

-- Fully qualified: CATALOG.SCHEMA.TABLE gbmart.bronze.orders gbmart.bronze.products gbmart.silver.orders -- cleaned, conformed gbmart.gold.fact_sales -- business-ready -- Catalog = gbmart (the whole GlobalMart project) -- Schema = bronze/silver/gold (the medallion layer) -- Table = the entity, plain — no source-system prefix needed

Why no prefix? gbmart.bronze.bronze_adls_products is redundant — the schema already says "bronze." Just gbmart.bronze.products.
