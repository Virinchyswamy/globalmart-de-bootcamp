Day 4 — Hands-On Lab 2: Partitioning, Z-ORDER/Liquid Clustering & Caching

GlobalMart Data Engineering Bootcamp  |  Quick Reference Cheatsheet  |  3:30 PM – 5:30 PM

2 hours Hands-on Personal practice table only 5 phases No writes to shared gbmart tables
Cost & safety: every command in this HOL runs against a personal practice table in main.YOUR_SCHEMA — never against the shared gbmart.bronze/silver/gold tables. Never run VACUUM ... RETAIN 0 HOURS — it permanently deletes file history. Nothing here starts a cluster, job, or pipeline.

Setup

PRACTICE_SCHEMA = "main.YOUR_SCHEMA" # ← replace with a schema you own spark.sql(f"CREATE SCHEMA IF NOT EXISTS {PRACTICE_SCHEMA}") PRACTICE_TABLE = f"{PRACTICE_SCHEMA}.orders_partitioning_practice"

Why Bronze, not Gold? By Day 4, only the Bronze layer exists — Silver (Day 5), the dimension tables (Day 6), and fact_sales (Day 7) haven't been built yet. Every table this HOL reads is gbmart.bronze.* for that reason.

Phase 1 Create the Small-File Problem on Purpose

source_df = spark.table("gbmart.bronze.customers") # read-only, safe source_df.repartition(200).write.format("delta").mode("overwrite") \ .saveAsTable(PRACTICE_TABLE) # repartition(200) forces 200 tiny files — simulates months of small streaming writes

Phase 2 Measure the Baseline

Time a filtered query against the fragmented table and record the file count via DESCRIBE DETAIL — this is the number every later phase compares against.

Phase 3 OPTIMIZE + Z-ORDER

spark.sql(f"OPTIMIZE {PRACTICE_TABLE} ZORDER BY (CustomerID)") # Re-run the same filtered query and compare the timing to the baseline

Phase 4 Liquid Clustering as an Alternative

spark.sql(f""" CREATE TABLE {LIQUID_TABLE} CLUSTER BY (CustomerID) AS SELECT * FROM {PRACTICE_TABLE} """) spark.sql(f"OPTIMIZE {LIQUID_TABLE}") # no ZORDER BY needed — clusters incrementally
RunWhat you're measuring

Phase 5 Caching

dim_df = spark.table("gbmart.bronze.payment_methods").cache() # small, lookup-shaped table dim_df.count() # first access materializes the cache for _ in range(5): dim_df.count() # subsequent access reads from memory — much faster dim_df.unpersist() # always free cache memory when done
Cache small tables read repeatedly in one session. A single scan of a large table gets no benefit and just wastes cluster memory.
