The Two Real Pathways

GlobalMart's production footprint has exactly two real source systems — not four. "4 sources" refers to the four files that drop into ADLS, not four separate systems.

Pathway 1 — Postgres (Supabase) via Lakeflow Connect CDC Tables: orders, order_items
Mechanism: WAL / logical replication slot
Captures deletes: Yes
Built: Day 2 HOL 1
Pathway 2 — ADLS File Drops via Auto Loader Tables: products, customers, addresses, payments
Mechanism: cloudFiles streaming source
Exactly-once via: checkpoint
Built: Day 4 HOL 1 (today)
Not part of this pipeline: the REST API and Neo4j/GraphDB patterns from Day 3 ILT 1 are deliberate side-explorations — useful patterns for other projects, but GlobalMart's real architecture only has the two pathways above.

Bronze Landing Map

gbmart.bronze.orders ← CDC (Lakeflow Connect) gbmart.bronze.order_items ← CDC (Lakeflow Connect) gbmart.bronze.products ← Auto Loader (JSON, nested) gbmart.bronze.customers ← Auto Loader (CSV) gbmart.bronze.addresses ← Auto Loader (CSV, multiLine) gbmart.bronze.payments ← Auto Loader (CSV)

Bronze Rules — Same for Both Pathways

1. Never transformLand raw data as close to source shape as possible.
2. Always add audit columns_ingested_at, plus _source_file or _cdc_op.
3. Never deleteBronze is append-only; a source DELETE lands as a DELETE event, not a row removal.
4. All Delta formatRegardless of pathway — no CSV/Parquet-only tables anywhere in Bronze.
