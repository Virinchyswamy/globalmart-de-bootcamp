Phase A

Create Your GitHub Repository

A1–A2 · Repository + Personal Access Token

A1 — Create the repo

  1. Go to github.com and log in (or create a free account)
  2. Click + New repository
  3. Name it globalmart-lakehouse, set it to Private
  4. Check "Add a README file" → Create repository

A2 — Generate a Personal Access Token

  1. Settings → Developer Settings → Personal Access Tokens → Tokens (classic)
  2. Generate new token → 90-day expiry → check repo scope
  3. Generate token → copy it immediately

Common mistake: closing the token page before copying it. If that happens, just generate a new one — there's no way to recover the old value.

Phase B

Connect GitHub to Databricks

B1–B2 · Link Your Account, Then Clone the Repo

B1 — Link your GitHub account

  1. Databricks → username (top right) → Settings
  2. Linked Accounts → Git Integration → select GitHub
  3. Paste your Personal Access Token from A2
  4. Enter your GitHub username → Save

B2 — Clone the repo into Databricks

  1. Left sidebar → click Repos
  2. Click Add Repo
  3. Paste: https://github.com/YOUR_USERNAME/globalmart-lakehouse
  4. Click Create Repo

Verify: your repo appears in Databricks under Repos, with a README.md inside it.

Phase C

Create Your dev Branch

Never write code directly on main — same discipline as the dev → test → prod pattern from ILT 3.

Create the Branch, Then Verify From a Notebook

1. Open your repo in Databricks Repos
2. Click the Git button (branch icon)
3. Click Create Branch → name it: dev
4. Confirm the branch selector shows "dev"
# C1: confirm you're inside a Git repo
notebook_path = dbutils.notebook.entry_point
    .getDbutils().notebook().getContext().notebookPath().get()

if "/Repos/" in notebook_path:
    print("Git tracking is active.")
else:
    print("NOT in a Repo — go back to Phase B.")

Verify: the branch indicator in the Databricks Repos UI reads dev, not main.

Phase D

Build the Shared Config Notebook

One config/setup notebook every future notebook calls with %run — using the External Location pattern from HOL 1, not a hardcoded key.

D1 — Create the Folder and Notebook

  1. Inside your repo (on the dev branch), create a folder called config
  2. Inside config/, create a new notebook called setup
  3. Copy the config code (next slide) into that notebook, filling in your own storage account name from Day 1

D2 — config/setup: Shared Connection Config

No storage key anywhere in this notebook or in git history
STORAGE_ACCOUNT_NAME = "YOUR_STORAGE_ACCOUNT_NAME"   # ← your storage account from Day 1
CONTAINER_NAME        = "YOUR_CONTAINER_NAME"        # ← your container from Day 1

# No spark.conf.set() needed — your External Location from HOL 1
# already covers this path; Unity Catalog handles authentication.
BASE_PATH = f"abfss://{CONTAINER_NAME}@{STORAGE_ACCOUNT_NAME}.dfs.core.windows.net"
RAW_PATH  = f"{BASE_PATH}/raw-data"   # one subfolder per entity below this

# Bronze/Silver/Gold are NOT ADLS folders — they're schemas inside your
# Unity Catalog catalog, referenced by name only, no path at all:
# spark.table(f"{CATALOG}.bronze.customers")
CATALOG = "YOUR_CATALOG"   # ← your catalog from Day 1

D3 — Confirm %run Picks Up the Shared Config

Run from a DIFFERENT notebook in the same repo — not config/setup itself
%run ../config/setup

# After this line runs, RAW_PATH / CATALOG are both available —
# no redefining needed.

Adjust the relative path if your notebook doesn't sit directly beside the config/ folder.

Phase E

Commit and Push

Get config/setup from your local Databricks Repo into GitHub, on the dev branch. This is the exact workflow you'll repeat every day.

The Commit → Push Workflow

  1. Databricks Repos → click the Git button on your repo
  2. config/setup.ipynb appears as a changed file
  3. Stage the file
  4. Write a commit message: "Add shared ADLS config notebook using External Location auth"
  5. Click Commit → Click Push
  6. github.com → your repo → switch to dev → confirm the file is there
BadGood
updateAdd null check for customer email in silver layer
fixFix date format in orders table from MM/DD to YYYY-MM-DD
changesAdd shared ADLS config notebook using External Location auth

⚠️ Personal Access Tokens are entered once in the Databricks UI (Phase B) — never paste one into a notebook cell.

Submission Checklist

  1. GitHub repo created: globalmart-lakehouse (Private)
  2. Personal Access Token generated and saved in Databricks Git Integration
  3. Repo cloned into Databricks under Repos
  4. dev branch created and confirmed active
  5. config/setup notebook created with your own storage account name — no key in it
  6. Committed with a clear message, pushed to GitHub
  7. Confirmed config/setup.ipynb appears under the dev branch on GitHub

⚠️ Replace any real token/secret values with placeholders before uploading this notebook.
