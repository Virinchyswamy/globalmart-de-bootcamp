This Isn't Small Talk With a Chatbot

You've used AI chat before. It's trained on the internet and it can be wrong with total confidence. Genie is a different animal — on purpose.

🧞 Watch Genie Actually Answer Something

Click through this like you would in the real Genie chat UI
"What was our top-selling category last month, and what discount are we giving on it?"
🧞 GENIE

Let me check gbmart.gold.vw_monthly_category_sales...

SELECT category, SUM(total_revenue) AS revenue, AVG(avg_discount_given) AS avg_discount
FROM gbmart.gold.vw_monthly_category_sales
WHERE year = 2026 AND month = 6
GROUP BY category
ORDER BY revenue DESC LIMIT 1;
→ Home & Kitchen — ₹18.4L revenue, 6.2% average discount

Notice what didn't happen: nobody wrote a GROUP BY. Genie didn't invent that number either — it queried an already-built, already-trusted Gold view. That's the whole trick, and it's exactly what Section 2 is about.

What Actually Happens Behind the Scenes

1. Ask

Plain English, into the Genie chat UI. No SQL, no join logic, no table names required.

2. Genie Interprets

Reads the Genie Space's metadata — table/column names, comments, sample questions, instructions — to work out which tables, columns, and joins answer it.

3. SQL + Answer

Runs real SQL against a real SQL warehouse, under your real Unity Catalog permissions, and shows both the SQL and the result.

A Genie Space is a scoped, curated subset of a catalog — deliberately narrower than "the whole catalog," so the LLM isn't guessing across hundreds of unrelated tables. Set up entirely by clicking through Catalog Explorer → Genie → New Space — not by running code. The matching hands-on for that UI setup is a separate, later session against the real gbmart Gold layer; nothing in today's notebook creates one.

What Actually Makes Genie Different — Six Real Features

Every answer comes with the real SQL. Nothing is a black box — a data engineer can verify exactly what ran.

02

Follow-up questions ("now break that down by region") build on the previous question's context — a real conversation, not one-shot Q&A.

03

📊 Auto-visualizes

Genie doesn't just return a table — it can generate a chart from the result shape automatically, no separate BI step.

04

✅ Trusted assets

Admins can pin specific verified queries as ground truth. Once a question is answered right, it can be locked in — not re-guessed every time.

05

🎯 Scoped per audience

A catalog can have multiple Genie Spaces — one for Finance, one for Ops — each seeing only the tables curated for them.

06

🔒 Governance-native

It's not a separate system that might leak data — it queries through Unity Catalog, so every grant, row filter, and mask still applies. Next slide.

The Part Most People Miss

Genie Doesn't Get a Bypass

Everything you learned about row filters and column masks in ILT 4 applies to Genie automatically — because Genie isn't a side door, it's just another reader querying through the same warehouse.

Same table. Same mask function. Same Genie Space. The only thing that changed is who's logged in — because the mask is attached to the column in Unity Catalog, not to Genie. Genie has no way to see the unmasked value even if it wanted to; the data warehouse itself never hands it over.

Two Raw Facts About fact_sales

A column named Sales_amount (type decimal), and a column named Actual_price (type decimal). To an LLM — or a new analyst — those names alone answer none of the questions that matter.

Without a semantic layerWith a semantic layer
Sales_amountJust a decimal column. Safe to SUM? Pre- or post-discount? Unknown."Revenue in INR for this order line item — quantity × discounted price. Safe to SUM."
Actual_priceJust a decimal column. Looks summable like any other number."Original list price per unit, in INR. Non-additive — never SUM directly across products."

GlobalMart Already Has 2 Semantic-Layer Artifacts

Day 7 HOL 2 built two real Gold views on top of fact_sales — neither built with Genie in mind. They exist because category managers and regional ops leads needed one agreed-upon number to report against.

ViewWhat it answers
vw_monthly_category_salesYear/month/category revenue, quantity, orders, avg. discount

That is precisely what a semantic layer is. A Genie Space built on gbmart.gold would point straight at these two views for exactly the questions they already answer — instead of asking Genie to reconstruct the same join and GROUP BY from raw fact_sales, every single time. This is also literally the query Slide 3's demo used.

The Part We CAN Script Today

Genie Space setup is UI-only. Table + column comments underneath it are real, runnable SQL.
YOUR_SCHEMA = "main.YOUR_SCHEMA"
PRACTICE_TABLE = f"{YOUR_SCHEMA}.fact_sales_practice"

# CREATE OR REPLACE -- idempotent, safe to re-run
spark.sql(f"""CREATE OR REPLACE TABLE {PRACTICE_TABLE}
    AS SELECT * FROM gbmart.gold.fact_sales LIMIT 100""")

The only touch against the real table anywhere in this notebook — one read-only SELECT ... LIMIT 100. Every COMMENT/ALTER TABLE statement runs against your own practice copy, never the real one.

Add Real Table + Column Comments

Must stay additivity-correct — a wrong comment is worse than no comment
MeasureAdditivityWhat the comment must say
Quantity_purchasedAdditiveSafe to SUM across any dimension
Sales_amountAdditiveSafe to SUM — this is the revenue measure
Actual_priceNon-additiveNever SUM/AVG directly across products
Discounted_priceNon-additiveDerive avg. selling price as SUM(Sales_amount)/SUM(Quantity_purchased)
spark.sql(f"COMMENT ON TABLE {PRACTICE_TABLE} IS '...'")

for column_name, comment_text in column_comments.items():
    spark.sql(f"ALTER TABLE {PRACTICE_TABLE} ALTER COLUMN {column_name} COMMENT '{comment_text}'")

Sample Questions — Bootstrapping Genie's Matching

Illustrative only — not executed in this session. Every sample question maps to one of the two already-built Gold views, not a fresh query against raw fact_sales.

Sample questionMaps to
"What was our revenue by category last month?"SELECT category, SUM(total_revenue) FROM vw_monthly_category_sales ... GROUP BY category
"Which states generate the most revenue?"SELECT state, SUM(total_revenue) FROM vw_regional_sales GROUP BY state ORDER BY total_revenue DESC
"What is our average discount by category?"SELECT category, AVG(avg_discount_given) FROM vw_monthly_category_sales GROUP BY category
"How many orders came from each region?"SELECT state, city, total_orders FROM vw_regional_sales

This is Power #4 from Slide 5 in action — a worked question/SQL pair registered on a Genie Space becomes a Trusted Asset: Genie leans on a known-good pattern instead of reconstructing the join from scratch, every time someone asks something similar.
