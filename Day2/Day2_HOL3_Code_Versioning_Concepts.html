Day 2 — HOL 3: Code Versioning — Databricks Repos + GitHub

GlobalMart Data Engineering Bootcamp  |  Set Up the Repo You'll Use for the Rest of the Bootcamp

2 hours Follows ILT 3 Output: GitHub repo + dev branch + 1 real commit

Phase A Create Your GitHub Repository

1. github.com → + New repository → name: globalmart-lakehouse → Private → Add README
2. Settings → Developer Settings → Personal Access Tokens → Tokens (classic)
3. Generate new token → scope: repo → COPY IT NOW (you cannot see it again)

Phase B Connect GitHub to Databricks

1. Databricks → username → Settings → Linked Accounts → Git Integration → GitHub
2. Paste Personal Access Token + GitHub username → Save
3. Repos → Add Repo → paste: https://github.com/YOUR_USERNAME/globalmart-lakehouse
Verify: your repo appears in Databricks under Repos, with a README.md inside it.

Phase C Create Your dev Branch

Git button → Create Branch → name: dev → switch to it

Phase D Build the Shared Config Notebook

One config/setup notebook every future notebook calls with %run — using the External Location pattern from HOL 1, not a hardcoded key.

# config/setup — no storage key anywhere in this notebook or in git history
STORAGE_ACCOUNT_NAME = "YOUR_STORAGE_ACCOUNT_NAME"  # ← your storage account from Day 1
CONTAINER_NAME = "amazon-data"

# No spark.conf.set() — your External Location from HOL 1 already covers this
BASE_PATH = f"abfss://{CONTAINER_NAME}@{STORAGE_ACCOUNT_NAME}.dfs.core.windows.net"
BRONZE_PATH = f"{BASE_PATH}/raw"
GBMART_CATALOG = "gbmart"  # the shared catalog, referenced by name — no path needed

Phase E Commit and Push

1. Git button → config/setup.ipynb shows as changed
2. Stage the file
3. Commit message: "Add shared ADLS config notebook using External Location auth"
4. Commit → Push
5. github.com → your repo → dev branch → confirm the file is there
⚠️ Personal Access Tokens are entered once in the Databricks UI (Phase B) — never paste one into a notebook cell.
