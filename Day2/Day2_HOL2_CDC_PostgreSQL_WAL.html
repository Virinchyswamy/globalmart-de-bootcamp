Watermark Ingestion vs WAL/CDC

Watermark (updated_at filter)WAL / CDC (this HOL)
Captures new rowsYesYes
Captures updatesYes, if column changesYes
Captures deletesNo — row is goneYes — WAL records it
Requires updated_atYesNo

Pre-Work — Create Table + Enable CDC

-- No updated_at column — intentional. Watermark won't work here.
CREATE TABLE public.poc_orders (order_id TEXT PRIMARY KEY, ...);

-- After 200 rows loaded, before Day-2 changes:
CREATE PUBLICATION poc_orders_pub FOR TABLE public.poc_orders;
SELECT pg_create_logical_replication_slot('poc_orders_slot', 'test_decoding');
⚠️ Timing matters: create the slot AFTER the initial load and BEFORE Day-2 changes, or you'll flood the WAL or miss the changes entirely.

CDC Capture

# Drains the slot — .cache() so count() and show() read the same snapshot
cdc_raw_df = jdbc_read(
  "(SELECT * FROM pg_logical_slot_get_changes('poc_orders_slot', NULL, NULL)) AS cdc_events"
).cache()

Each statement = 3 WAL rows (BEGIN + event + COMMIT). 5 INSERTs + 2 UPDATEs + 1 DELETE = 24 rows total, parsed down to 8 real events by _cdc_op.
