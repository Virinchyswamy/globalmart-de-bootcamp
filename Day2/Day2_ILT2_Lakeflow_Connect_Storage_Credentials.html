From Watermarks to a Managed Pipeline

A watermark filter (WHERE updated_at > last_run) misses DELETEs and only catches an UPDATE if the table has an updated_at column. The gold-standard fix — reading the WAL through a replication slot — is what we did by hand in ILT 1. Lakeflow Connect can run either strategy as a managed pipeline — GlobalMart's real pipeline uses the query-based one, not WAL.

ModeHow it detects changesCatches DELETEs?
Log-based (WAL / replication slot)Reads the database's write-ahead log directlyYes
Query-based (cursor column) — GlobalMart's real pipelineRuns WHERE cursor_col > last_value on a scheduleNo — same blind spot as a watermark
GlobalMart's real, running pipeline (orders_data_ingestion_cdc) is query-based on updated_at — not WAL replication. Databricks still manages the connection, scheduling, retries, and schema handling for you, but it does not capture DELETEs for free just because it's Lakeflow Connect.
Manual JDBC + WAL (ILT 1 / HOL 2)Lakeflow Connect — query-based (GlobalMart's real pipeline)
You open the JDBC connectionDatabricks manages the connection
You create the replication slotNo replication slot — polls with a cursor column instead
You call pg_logical_slot_get_changes()Databricks runs the cursor query on a schedule
You parse INSERT/UPDATE/DELETE textDatabricks applies INSERT/UPDATE only — no DELETE capture
You write to Bronze yourselfLands as a governed, managed Unity Catalog table

  Someone updates order O-10021 status to 'shipped'

Why Hardcoded Storage Keys Are a Problem

# Since Day 1, every notebook has started with this pattern:
storage_account_name = "YOUR_STORAGE_ACCOUNT_NAME"
storage_account_key = "YOUR_STORAGE_ACCOUNT_KEY"  # ← 88-character secret
spark.conf.set(...)
ProblemWhat It Means
Security riskAnyone who opens the notebook sees a key with full read/write access
Git exposureA committed key stays in git history even after being deleted from the file
Key rotationRotating the key breaks every notebook that hardcodes it, all at once
No audit trailAzure sees "the key was used" — not which user, from which notebook

The Two Unity Catalog Building Blocks

Storage CredentialDatabricks' identity card for Azure — wraps an Azure Managed Identity (Access Connector). No password, no key, nothing that can leak.
External LocationRegisters an ADLS path + which Storage Credential to use for it. Maps a specific room (path) to a specific badge (credential).
