What Is Cloud Computing?

Think of Azure like a huge office building with hundreds of floors. Each floor offers a different service — storage, computing power, databases, security. You don't buy the building. You just rent the floors you need, for as long as you need them.

That's the whole idea of cloud computing

  • Servers, storage, databases, and software delivered over the internet
  • On demand — spin resources up in minutes, not months
  • Pay-as-you-go — pay only for what you actually use
  • No physical hardware for GlobalMart to buy or maintain

Formal definition: cloud computing is the delivery of computing services over the internet, on demand, with pay-as-you-go pricing — instead of owning physical servers, you rent capacity from a provider like Microsoft Azure, AWS, or Google Cloud.

For this bootcamp: GlobalMart runs on Microsoft Azure — specifically ADLS Gen2 for storage and Azure Databricks for processing.

Before the Cloud: On-Premises vs Cloud

Before cloud computing, every company bought and ran its own physical servers. Here's what changed:

On-Premises (Traditional)

  • Buy servers upfront — a huge capital expense
  • 3–6 months to provision new hardware
  • Pay for full capacity even when idle
  • Your own team manages hardware, cooling, networking
  • Single location — a disaster there means data loss

Cloud (Azure)

  • No hardware to buy — pure pay-as-you-go
  • Provision resources in minutes
  • Pay only for what you use — scale to zero when idle
  • Microsoft manages the hardware and infrastructure
  • Geo-redundant — data survives a regional outage

Three Ways to Consume the Cloud

IaaS — Infrastructure as a Service

You rent raw compute, storage, and networking. You still install and manage the OS and apps yourself.

Examples: Azure Virtual Machines, Azure Blob Storage

PaaS — Platform as a Service

Microsoft manages the infrastructure AND the platform. You just deploy your code or pipelines.

Examples: Azure Databricks, ADLS Gen2, Azure SQL Database

SaaS — Software as a Service

Fully managed software delivered via browser. No servers, no installs, no patches.

Examples: Microsoft 365, Power BI, GitHub

For GlobalMart's pipeline: we use PaaS almost entirely — Azure Databricks for processing and ADLS Gen2 for storage. Microsoft manages the infrastructure; we focus on writing data pipelines.

Three Reasons Cloud Saves Time and Money

💰 Cost Efficiency

No upfront server purchases. Pay only for what you use — per second, per GB, per query. GlobalMart's ADLS storage costs fractions of a cent per GB per month.

⚡ Elasticity & Scalability

Scale compute up for a year-end sales rush, scale down to zero overnight. Databricks clusters spin up in minutes and auto-terminate when idle.

🛡️ High Availability

Azure guarantees 99.9%–99.99% uptime. Data is automatically replicated across multiple data centers.

Three More Reasons: Reach, Security, Speed

🌏 Global Reach

Azure has 60+ regions worldwide. GlobalMart can serve customers from a data center close to them, with millisecond response times.

🔐 Enterprise Security

Built-in encryption at rest and in transit. Microsoft holds ISO 27001, SOC 2, HIPAA, GDPR, and PCI-DSS certifications.

🚀 Speed of Innovation

300+ managed services — AI, ML, IoT, analytics — available on day one. Teams prototype a new pipeline in hours, not weeks.

ADLS Gen2 — The Storage Foundation

Every layer of GlobalMart's Lakehouse — raw, Bronze, Silver, Gold — lives inside one ADLS Gen2 account. This is the single most important storage service in the whole bootcamp.

ADLS Gen2, In Plain Words

Regular Blob Storage is like a giant pile of paper dumped in a warehouse — everything is technically "in there," but there are no real folders, just labels pretending to be folders. ADLS Gen2 turns that pile into an actual filing cabinet with labeled drawers by turning on a feature called Hierarchical Namespace.

Azure Blob Storage

  • Folders are fake — just name prefixes
  • No folder-level permissions
  • Slower for analytics workloads
  • Uses wasbs:// in Spark

ADLS Gen2

  • Real folder hierarchy, like a file system
  • Folder-level access control (RBAC + ACLs)
  • 10–100× faster for Spark reads
  • Uses abfss:// in Spark

Key ADLS Gen2 Features

FeatureDetails
Storage tiersHot (frequent access), Cool (infrequent), Archive (rarely accessed, cheapest)
RedundancyLRS (one data center), ZRS (across zones), GRS (two regions)
Encryption256-bit AES at rest by default — Microsoft-managed keys or your own via Key Vault
Access controlRBAC at container level, POSIX-style ACLs at file/folder level — Unity Catalog manages this from Databricks
Soft deleteDeleted files recoverable for up to 365 days — critical for GDPR requests and accidental deletes
VersioningKeeps previous versions of every file; restore if data is accidentally overwritten

GlobalMart's ADLS Structure

Storage Account: <your-storage-account>
   Container: <your-container>

      raw-data/            ← the ONLY folder ADLS holds for this project
                    customers/  addresses/  payments/
                    payment_methods/  products/  returns/

Unity Catalog (inside <your-catalog>) — NOT ADLS folders:

      bronze schema   ← raw data converted to Delta, never modified
                    <your-catalog>.bronze.customers, .orders, .order_items, ...

      silver schema   ← cleaned, validated, deduplicated Delta tables
                    <your-catalog>.silver.dim_customer, .dim_product, ...

      gold schema     ← business-ready star schema for Genie + reports
                    <your-catalog>.gold.fact_sales, .dim_date, .dim_address, ...

One container, one raw folder, three catalog schemas. GlobalMart uses a single container (<your-container>) with just a raw-data/ folder — one storage key authenticates the whole landing zone. bronze, silver, and gold are Unity Catalog schemas inside your catalog, not ADLS folders.

Section 4

Three Ways to Store & Query Data at Scale

Picture three restaurants: one is fine dining that only serves fully cooked, plated food (a Data Warehouse). One is a grocery store with raw ingredients everywhere (a Data Lake). One runs both side by side (Hybrid). Seeing why the Hybrid restaurant is exhausting to run explains why GlobalMart picked a fourth option — the Lakehouse.

Data Warehouse vs Data Lake

Data Warehouse — "Fine Dining"

  • Structured, schema-on-write data only
  • ACID transactions — UPDATE, DELETE, MERGE
  • Very fast SQL queries
  • High storage cost, proprietary format
  • Cannot store raw files, JSON, or ML features

Examples: Snowflake, Azure Synapse, Redshift

Data Lake — "Grocery Store"

  • Stores anything — CSV, JSON, images, logs
  • Very cheap object storage
  • Schema-on-read — define structure at query time
  • No ACID — no UPDATE or DELETE on files
  • Often becomes an ungoverned "data swamp"

Examples: raw ADLS, raw S3

The Hybrid Compromise — Why It's Painful

Most large companies still run a Data Lake and a Data Warehouse side by side, connected by an overnight batch job. Here's what that actually looks like:

Sources (Postgres, files, APIs)
    ↓
DATA LAKE (raw ADLS/S3 — cheap, unstructured)
    ↓  overnight ETL batch job (can take hours)
DATA WAREHOUSE (Synapse/Snowflake — structured, queryable)
    ↓
Business reports (always 12–24 hours stale)

ML team reads DATA LAKE directly        ← different access controls
Analytics team reads DATA WAREHOUSE     ← sees a different version of the data

The problems: same data stored twice (pay for both) · ML and analytics teams see different numbers · a failed ETL job leaves the warehouse stale for a day · two separate governance systems · no DELETE in the lake makes GDPR requests painful.

The Lakehouse — One Platform for Everything

The Lakehouse combines cheap lake storage with warehouse-grade reliability by adding a transaction layer — Delta Lake — directly on top of the files. One system replaces both.

Sources (Postgres via Lakeflow Connect + ADLS file drops via Autoloader)
    ↓
BRONZE (raw Delta on ADLS — cheap storage, ACID protection)
    ↓  PySpark transformations
SILVER (clean Delta — schema enforced, deduped, SCD applied)
    ↓  star schema build
GOLD — fact_sales (business-ready, fast to query)
    ↓
GENIE + Reports (same data, same access controls, no duplication)

ML team reads Silver/Gold too — same tables, no copy
Unity Catalog governs access for everyone in one place

One-sentence takeaway: the Lakehouse gives you the low cost and flexibility of a Data Lake with the reliability and performance of a Data Warehouse — with no duplication.
