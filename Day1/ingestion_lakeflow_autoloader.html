Ingestion — Lakeflow Connect vs Autoloader

ILT 4  |  Day 1  |  60 min  |  Beginner  |  Tags: lakeflow-connect, autoloader, CDC, cloudFiles, bronze

1. Why Two Different Tools?

GlobalMart data comes from two fundamentally different places. One is a live PostgreSQL database where orders are being inserted and updated right now. The other is a storage folder in Azure where CSV files land periodically. These two situations require completely different approaches.

LAKEFLOW CONNECT

For: Live databases (Postgres)

  • Source is a running database with rows being inserted, updated, and deleted in real time
  • You cannot JDBC-query a large table every few minutes without destroying performance
  • Need to capture the history of changes, not just the current state
  • Reads the database's Write-Ahead Log (WAL) continuously
  • Delivers change events to Bronze as a streaming table

GlobalMart tables: orders, order_items
AUTOLOADER

For: File drops in ADLS

  • Source is CSV/JSON/Parquet files landing in raw/ folder in ADLS
  • Files arrive on a schedule (daily, hourly, on-demand)
  • Once landed, files do not change
  • Need to avoid re-reading the same files on every run
  • Uses a checkpoint to track which files have already been processed

GlobalMart tables: customers, payments, products, addresses, returns, payment_methods, shipping_tier, suppliers

2. How Both Feed Bronze

Supabase PostgreSQL (live orders DB)
    → Lakeflow Connect (reads WAL, continuous CDC)
    → Bronze streaming table (bronze/orders/, bronze/order_items/)

ADLS raw/ (file drops: CSVs from upstream systems)
    → Autoloader (cloudFiles) (checkpoint-based incremental scan)
    → Bronze Delta tables (bronze/customers/, bronze/products/, …)

Both Bronze layers
    → Silver (clean, deduped, SCD)
    → Gold (fact_sales + dimensions)
    → Genie (self-serve Q&A for business)

3. Lakeflow Connect — CDC from PostgreSQL

How CDC Works (via PostgreSQL WAL)

1. An order is updated in Supabase: UPDATE orders SET status = 'shipped' WHERE order_id = 'O1001'
2. PostgreSQL writes this change to the Write-Ahead Log (WAL) before applying it to the table — this is how Postgres guarantees durability
3. Lakeflow Connect holds a replication slot in Postgres. It tails the WAL continuously and sees this UPDATE event
4. Lakeflow Connect delivers a row to the Bronze streaming table: { operation: "UPDATE", order_id: "O1001", status: "shipped", _cdc_timestamp: "..." }
5. Bronze now has a complete history of every INSERT, UPDATE, DELETE — Silver can replay this to get the current state

You configure Lakeflow Connect as a DLT pipeline in Databricks. No manual code to read Postgres — Databricks handles the WAL connection, retries, and checkpointing.

4. Autoloader — Incremental File Ingestion from ADLS

How Autoloader Works

1. A new file customers_2024-06-02.csv lands in raw/
2. Autoloader uses Azure Event Grid (or directory listing) to detect the new file
3. It checks the checkpoint folder — has this file been processed before? No → process it
4. Reads the CSV, applies schema, appends rows to Bronze Delta table
5. Writes the file name to the checkpoint — next run will skip it
6. When another file lands tomorrow, only the new file is read — not the entire folder

Autoloader Code Pattern

# Autoloader reads new files from raw/ and appends to Bronze
df = (
  spark.readStream
    .format("cloudFiles")                        # Autoloader format
    .option("cloudFiles.format", "csv")
    .option("cloudFiles.schemaLocation", checkpoint_path + "schema")
    .option("header", "true")
    .load(raw_path + "customers_*.csv")
)

(
  df.writeStream
    .format("delta")
    .option("checkpointLocation", checkpoint_path)
    .trigger(availableNow=True)            # process all new files, then stop
    .toTable("bronze.customers")
)

Two Trigger Modes

availableNow=True (batch-like) Processes all new files waiting in the folder, then stops. Run this on a schedule (e.g., every hour via Databricks Workflows). Good for: most GlobalMart ADLS tables.
continuous=True (streaming) Stays running and picks up files the moment they land. Uses more cluster time. Good for: near-real-time requirements, like payments that need to appear in Bronze within minutes.

7. Decision Rule

Is the source a live database with INSERT / UPDATE / DELETE?
    → Lakeflow Connect

Is the source a file that lands in ADLS and never changes?
    Does the table grow over time (new rows accumulate)?
        → Autoloader + Incremental Load (append + watermark)
    Is the table small and fully refreshed each time?
        → Autoloader + Full Load (overwrite)
