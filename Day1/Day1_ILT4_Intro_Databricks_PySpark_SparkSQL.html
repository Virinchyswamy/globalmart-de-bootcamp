1. What is Databricks?

Databricks is a cloud platform built on top of Apache Spark. It gives Data Engineers a managed environment to run large-scale data processing jobs — with notebooks, clusters, Delta Lake, and job scheduling all in one place. GlobalMart uses it to build and run the full Bronze → Silver → Gold pipeline.

📓 Notebooks Interactive cells mixing code (Python, SQL, Scala) and text. Where you write and test your pipeline logic. Shared with your team.
⚡ Clusters A group of VMs that run your code in parallel. You create one, attach it to your notebook, and Spark distributes your job automatically.
🏔️ Delta Lake The storage format for every table in the pipeline. Parquet files + a transaction log = ACID, time travel, streaming + batch.
📁 Unity Catalog Central metadata store. Controls who can access which table, column, or row. Tracks lineage from ADLS raw file to Gold table.
⚙️ Workflows Scheduled multi-task pipelines (DAGs). Replaces Airflow for simple orchestration. Runs your ingestion → Silver → Gold chain on a timer.
💬 Genie Natural-language Q&A interface on top of Gold tables. Business users ask questions in plain English — no SQL required.

2. Cluster Architecture — Driver + Workers

Every Spark job runs on a cluster. The driver is the brain (plans the job, tracks progress). The workers are the hands (process partitions of data in parallel). Both read from and write to ADLS — the data never fully moves into the cluster.

Your Notebook Code
    ↓
Driver Node  (plans the job, builds execution plan, tracks task completion)
    ↓ distributes partitions
Worker Node 1  (processes rows 1–1M)    reads/writes ↔ ADLS
Worker Node 2  (processes rows 1M–2M)  reads/writes ↔ ADLS
Worker Node 3  (processes rows 2M–3M)  reads/writes ↔ ADLS
    ↓ results back to driver
Output (displayed in notebook / written to Delta table)

Adding more workers = faster processing on large datasets. A 100 GB file that takes 10 min on 2 workers may take 3 min on 6 workers.

4. PySpark vs Pandas — Key Differences

pandas

  • Runs on a single machine
  • Data lives in memory (RAM limit)
  • Good for datasets under ~1 GB
  • Lazy? No — executes immediately
  • Familiar Python syntax

PySpark (Spark DataFrame)

  • Runs on a cluster (distributed)
  • Data lives in ADLS, not RAM
  • Handles TB-scale data
  • Lazy — builds a plan, executes only on an action
  • Similar API to pandas — .select(), .filter(), .groupBy()

Lazy evaluation means writing df.filter(df.status == "pending") does NOT run anything — it just adds a step to the plan. The plan executes when you call an action like .show(), .count(), or .write.

6. Writing to Delta (Bronze / Silver / Gold)

# Write as Delta — Full Load (overwrite)
df.write.format("delta").mode("overwrite").save(bronze_path + "payment_methods/")

# Write as Delta — Incremental Load (append)
df.write.format("delta").mode("append").save(bronze_path + "customers/")

# Write and register in Unity Catalog (recommended)
df.write.format("delta").mode("overwrite").saveAsTable("bronze.payment_methods")

7. Spark SQL — SQL on Delta Tables

Once a DataFrame is written as a Delta table and registered in Unity Catalog, you can query it directly using SQL. This is the same SQL syntax analysts already know — but running on Spark across a distributed cluster.

-- In a %sql cell:
SELECT status, COUNT(*) AS order_count
FROM bronze.orders
GROUP BY status
ORDER BY order_count DESC;

-- Time travel: query a previous version of a Delta table
SELECT * FROM bronze.orders VERSION AS OF 1;

-- DESCRIBE HISTORY: see all versions of a Delta table
DESCRIBE HISTORY bronze.orders;

Use spark.sql("...") inside a Python cell to run SQL and get back a PySpark DataFrame — then you can chain more transformations on the result.
