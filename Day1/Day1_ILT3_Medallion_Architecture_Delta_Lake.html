1. Why Three Layers?

Raw data from GlobalMart's two sources (Postgres CDC + ADLS file drops) has problems: null values, duplicate rows, inconsistent date formats, columns named differently in different files. You cannot run business reports directly on raw CSV files without getting wrong numbers.

The Medallion Architecture solves this by passing data through three quality layers — each one making the data more trustworthy and more useful than the last.

2. Bronze → Silver → Gold

🥉 Bronze
amazon-data/bronze/
Raw — exactly as received

  • Never modified after landing
  • Append-only (new data added, old never deleted)
  • Adds ingestion_timestamp + source_file
  • Format: Delta (converted from CSV on arrival)
  • Who: Data Engineers only

GlobalMart examples:
bronze/orders/ — raw CDC events
bronze/customers/ — raw file drop rows
→
🥈 Silver
amazon-data/silver/
Clean — validated and standardised

  • Delta format only
  • Nulls filled or flagged
  • Dates → YYYY-MM-DD
  • Deduplication applied
  • SCD Type 1/2 for dimension tables
  • Who: Data Engineers + Analysts

GlobalMart examples:
silver/dim_customer/
silver/dim_product/
→
🥇 Gold
amazon-data/gold/
Business-ready — the deliverable

  • Delta format only
  • Star schema (facts + dimensions)
  • Column names make sense to non-technical users
  • Optimised for fast query (Z-order, statistics)
  • Who: Business + Genie

GlobalMart output:
gold/fact_sales/ — the whole point

3. Delta Lake — What Makes It Different

Delta Lake is NOT a separate database. It is a storage layer that lives on top of Parquet files in ADLS. The secret ingredient is a folder called _delta_log/ that sits alongside the data files and records every change ever made.

silver/customers/ ← this is your Delta table path
    _delta_log/ ← Delta Lake's brain — JSON files, one per version
        00000000000000000000.json (version 0 — first write)
        00000000000000000001.json (version 1 — second write)
        00000000000000000002.json (version 2 — an update or delete)
    part-00000-abc123.parquet ← actual data, stored as Parquet
    part-00001-def456.parquet

Every time something changes (write, update, delete), Delta writes a new JSON entry in _delta_log. That log gives Delta all of its superpowers.

4. ACID — What It Means in Plain English

A Atomicity All-or-nothing. If a write fails halfway through, zero rows are visible. No partial data.
C Consistency Data always moves from one valid state to another. Schema rules are never violated.
I Isolation Two jobs writing at the same time do not interfere with each other. No corruption.
D Durability Once written and confirmed, data is never lost — even if the cluster crashes.

5. Delta Table vs CSV vs Parquet

Feature CSV Parquet Delta Table
ACID transactionsNoNoYes
Schema enforcementNoPartialYes
UPDATE rowsNoNoYes
DELETE rowsNoNoYes
MERGE (upsert)NoNoYes
Time travelNoNoYes
Audit historyNoNoYes
Streaming + BatchBatch onlyBatch onlyBoth
Handles large dataPoorYesYes

In one sentence: Delta = Parquet files + a transaction log. That transaction log changes everything.

6. GlobalMart's Layer Format Map

Layer Format Path Reason
Bronze Delta (from CSV/CDC) amazon-data/bronze/ Converted on arrival — preserves raw values but with ACID protection
Silver Delta only amazon-data/silver/ Need to UPDATE rows (SCD), enforce schema, and validate quality
Gold Delta only amazon-data/gold/ Need fast queries, statistics, Z-ordering for Genie performance

7. fact_sales — The Gold Deliverable

Why this table is the point of the whole pipeline

Grain: one row per order line item

Measures:
  • quantity
  • unit_price
  • line_total
Connects to:
  • dim_customer — who bought it
  • dim_product — what was sold
  • dim_date — when
  • dim_address — where it shipped
  • dim_payment_method — how it was paid
Answers:
  • Revenue by product category
  • Top customers by spend
  • Payment method breakdown
  • Regional sales trends
  • Return rate by product
