1. Why Azure Cloud?

GlobalMart's data pipeline runs on Microsoft Azure — Microsoft's cloud computing platform. Instead of buying and managing physical servers, Azure lets you rent exactly the compute and storage you need, pay only for what you use, and scale in minutes.

For a Data Engineer at GlobalMart, two Azure services are the foundation of everything: ADLS Gen2 (where data lives) and Azure Databricks (where data gets processed).

3. ADLS Gen2 — The Storage Foundation

ADLS Gen2 (Azure Data Lake Storage Generation 2) is cloud file storage optimised for big-data analytics. It stores any format — CSV, JSON, Parquet, Delta — cheaply and at massive scale, and connects natively with Databricks via the abfss:// protocol.

Blob Storage
  • Flat key-value store (fake folder prefixes)
  • No real folder hierarchy
  • No folder-level permissions
  • Slower analytics access
  • Default when you create a storage account
ADLS Gen2
  • True hierarchical folder structure
  • Folder-level access control (RBAC + ACLs)
  • Optimised for Spark / Databricks analytics
  • 10–100× faster than Blob for large reads
  • Enabled by turning on Hierarchical Namespace

4. Data Warehouse vs Data Lake vs Lakehouse

Three different ways organisations store and query data. GlobalMart uses the Lakehouse model.

Feature Data Warehouse Data Lake Lakehouse (GlobalMart)
Storage Cost High Very Low Very Low (ADLS)
Data Types Structured only Any format Any format
ACID Transactions Yes No Yes — via Delta Lake
Schema Enforcement Yes (rigid) No Yes (flexible)
UPDATE / DELETE rows Yes No Yes — via Delta MERGE
Query Performance High Low High — Delta statistics + Z-order
ML / AI Ready No Yes Yes
Real-world Examples Snowflake, Synapse Raw S3 / ADLS Databricks Lakehouse + ADLS

6. Connecting Databricks to ADLS — Three Methods

Method Security When to use Code needed
Storage Account Key Low (full access) Learning / dev environments spark.conf.set("fs.azure.account.key…", key)
SAS Token Medium (time-limited) Sharing temporary access Use SAS token in the path or spark.conf
Unity Catalog External Location Highest Production — team setups No spark.conf.set needed — UC manages auth

For this bootcamp we use the Storage Account Key method. In a real production system you would use Unity Catalog External Locations so that no key ever appears in notebook code.
