Part 1 REST API: Beyond a Single Call

ILT 1 called https://api.frankfurter.app/latest once, for the default base currency (EUR). Two realistic extensions: multiple base currencies, and historical rates (frankfurter.app accepts a date in place of latest: https://api.frankfurter.app/2026-01-01).

# ─── Setup: same Unity Catalog External Location as ILT 1 ─────────────────────
EXTERNAL_LOCATION = "abfss://ecom-gbmart-data@ecomadlsdata.dfs.core.windows.net"
sandbox_path = f"{EXTERNAL_LOCATION}/sandbox/api_graphdb"

base_currencies = ["USD", "EUR", "GBP"]  # GlobalMart's storefront currencies
all_rows = []

for base in base_currencies:
    response = requests.get("https://api.frankfurter.app/latest", params={"base": base})
    if response.status_code != 200:
        raise RuntimeError(f"API call failed for base={base}")
    # ... flatten data["rates"] into Row objects, append to all_rows ...

multi_base_df = spark.createDataFrame(all_rows)
Don't silently skip a failed call — a DE pipeline should always know when a source didn't return what was expected. That's why we raise instead of just printing a warning.

Step 2 — Save to Sandbox

multi_base_df.write.format("delta").mode("overwrite").save(f"{sandbox_path}/fx_rates_multi_base")
YOUR TURN — Historical Rates. Loop over two dates, call https://api.frankfurter.app/{date} for each, keep both the requested date and the API-returned date as separate columns (they can differ on weekends/holidays), and write with mode("append") — not overwrite — into sandbox_path/fx_rates_historical. This is the "accumulate history" case ILT 1 flagged.

Step 2 — Seed the Graph (in Neo4j Browser)

3 customers, 3 products, 2 suppliers, 3 orders — wired with the same relationships ILT 1 introduced: PLACED, CONTAINS, SUPPLIED_BY.

// Nodes
CREATE (c1:Customer {customer_id: 'CUST-001', name: 'Raj Patel', city: 'Mumbai'})
CREATE (p1:Product {product_id: 'PRD-001', name: 'Wireless Mouse'})
CREATE (s1:Supplier {supplier_id: 'SUP-001', name: 'TechDistributors Inc'})
CREATE (o1:Order {order_id: 'ORD-001', order_date: '2026-06-01'})
// ... 2 more of each, see the notebook for the full 11-node / 9-relationship seed script ...

// Relationships — wire nodes together with MATCH + CREATE
MATCH (c:Customer {customer_id: 'CUST-001'}), (o:Order {order_id: 'ORD-001'})
CREATE (c)-[:PLACED]->(o)

Run MATCH (n) RETURN n afterwards to see the graph visualization — 11 nodes, 9 relationships.

Step 3 — Query in the Neo4j Browser

// Which products did each customer buy?
MATCH (c:Customer)-[:PLACED]->(o:Order)-[:CONTAINS]->(p:Product)
RETURN c.name, p.name, o.order_id
YOUR TURN (in Neo4j Browser). Write a Cypher query that counts how many orders each customer placed, sorted highest first — same shape as ILT 1's pattern #4: MATCH ... RETURN ... COUNT(o) ... ORDER BY.

Part 3 Read the Graph Into Databricks

# ─── Install the driver and connect ────────────────────────────────────────────
%pip install neo4j

from neo4j import GraphDatabase

NEO4J_URI = "neo4j+s://YOUR_INSTANCE_ID.databases.neo4j.io"  # ← replace
NEO4J_USER = "neo4j"
NEO4J_PASSWORD = "YOUR_AURADB_PASSWORD"  # ← replace

driver = GraphDatabase.driver(NEO4J_URI, auth=(NEO4J_USER, NEO4J_PASSWORD))

def run_cypher(query, params=None):
    with driver.session() as session:
        result = session.run(query, params or {})
        return [dict(record) for record in result]
# ─── Run the same query, land the result as Delta ─────────────────────────────
rows = run_cypher("MATCH (c:Customer)-[:PLACED]->(o:Order)-[:CONTAINS]->(p:Product) RETURN ...")
graph_df = spark.createDataFrame(rows)
graph_df.write.format("delta").mode("overwrite").save(f"{sandbox_path}/graph_customer_orders")
YOUR TURN — Supplier Traversal. Write a Cypher query that returns, for every product, which supplier it comes from — a 2-hop traversal (Product -[:SUPPLIED_BY]-> Supplier) plus which orders contained that product. Save the result to sandbox_path/graph_product_suppliers.
Before submitting: replace NEO4J_URI and NEO4J_PASSWORD with placeholders again, and remember to call driver.close() when done — an open driver holds a connection pool open on AuraDB's side.
