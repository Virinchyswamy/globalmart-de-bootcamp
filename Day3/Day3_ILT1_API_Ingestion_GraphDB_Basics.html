Section 1 — What Is a REST API?

An API (Application Programming Interface) is a way for one system to talk to another over the internet. A REST API is a specific style of API that uses HTTP — the same protocol as websites.

The DE Ingestion Flow for APIs

1Call API → get JSON response
2Check status code → 200 = continue, anything else = raise error
3Parse JSON → convert to Spark DataFrame
4Add audit columns → ingestion_timestamp, source_url

Live Demo — Call the frankfurter.app API

import requests, json

api_url = "https://api.frankfurter.app/latest"
response = requests.get(api_url)

print(f"Status code : {response.status_code}")

if response.status_code == 200:
    data = response.json()  # parse JSON string into Python dict
    print(json.dumps(data, indent=2))
JSON fieldMeaning
amountBase amount the rates apply to (default 1.0)
baseThe base currency, e.g. "EUR"
dateThe date these rates are valid as of
ratesDict of 30+ target currencies → exchange rate

Flatten JSON → Spark DataFrame

from pyspark.sql import Row
from datetime import datetime

# One row per currency — flatten the nested rates dict
rows = [
    Row(base_currency=data["base"], target_currency=currency,
        exchange_rate=float(rate), rate_date=data["date"])
    for currency, rate in data["rates"].items()
]
fx_df = spark.createDataFrame(rows)
Idempotency for API data. APIs return live data — calling twice gives different results (rates change daily). Use mode("overwrite") for a live snapshot; use mode("append") with a rate_date column if you need history over time.

Schema changeAPI adds/removes fields without warningValidate response shape before parsing
API downtimeAPI returns 500 or 503Add retry logic with try/except
Auth expiryAPI key or token expiresRefresh token before each run

Section 4 — Introduction to Graph Databases

A graph database stores data as nodes (entities) and relationships (connections between entities) — instead of rows in tables joined by foreign keys.

NodeRelationshipNode
CustomerPLACED →Order
OrderCONTAINS →Product
ProductSUPPLIED_BY →Supplier
CustomerLIVES_IN →Address
OrderRETURNED_AS →Return
Illustrative only. This table is a familiar example to build intuition — not a real deliverable. Nothing here writes back into Bronze/Silver/Gold, and fact_sales does not depend on it. The payoff: "Which suppliers connect to customers who returned products?" is a 4-table join in SQL, but a single Cypher traversal in a graph.

Section 5 — Cypher Query Language Basics

Cypher is Neo4j's query language, designed to look like an ASCII drawing of the graph.

SQL: SELECT * FROM customers WHERE city = 'Mumbai'
Cypher: MATCH (c:Customer {city: 'Mumbai'}) RETURN c

Cypher Syntax — 4 Key Patterns

-- 1. Find all customers
MATCH (c:Customer)
RETURN c.name, c.city LIMIT 10

-- 2. Find all products a customer bought
MATCH (c:Customer {name: 'Raj'})-[:PLACED]->(o:Order)-[:CONTAINS]->(p:Product)
RETURN p.name, p.price

-- 3. Find customers who returned something
MATCH (c:Customer)-[:PLACED]->(o:Order)-[:RETURNED_AS]->(r:Return)
RETURN c.name, r.reason

-- 4. Count orders per customer (like GROUP BY)
MATCH (c:Customer)-[:PLACED]->(o:Order)
RETURN c.name, COUNT(o) AS total_orders
ORDER BY total_orders DESC

Reading From Neo4j Into Databricks

# pip install neo4j
from neo4j import GraphDatabase

driver = GraphDatabase.driver(NEO4J_URI, auth=(NEO4J_USER, NEO4J_PASSWORD))

with driver.session() as session:
    result = session.run("MATCH (c:Customer)-[:PLACED]->(o:Order) RETURN c.id, COUNT(o)")
    rows = [dict(r) for r in result]

# Land in the SAME sandbox/ location as the API demo, never bronze/
graph_df = spark.createDataFrame(rows)
graph_df.write.format("delta").mode("overwrite").save(sandbox_path + "/graph_customer_orders")
