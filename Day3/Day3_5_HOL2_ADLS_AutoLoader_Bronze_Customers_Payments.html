What Is Autoloader?

Without Autoloader (manual approach):
  Read all files every time → expensive
  Or manually track new files → complex code

With Autoloader:
  Run 1: customers_010626.csv → reads it, saves checkpoint
  Run 2: customers_020626.csv → reads ONLY the new file
  Run 3: no new files         → does nothing (very fast)

Autoloader = incremental file ingestion made easy

  • Automatically detects new files dropped in the ADLS folder
  • Remembers which files it already processed — no duplicates
  • Infers schema automatically — you don't define columns by hand
  • Built for incremental ingestion — production-grade from day one

Key Autoloader Concepts

TermWhat It Means
cloudFilesThe Autoloader format — like format("delta") but for reading files incrementally
cloudFiles.formatWhat kind of files you're reading — csv, json, parquet
cloudFiles.schemaLocationWhere Autoloader stores the inferred schema — consistent across runs
checkpointLocationWhere Autoloader tracks which files have been processed — the "memory"
trigger(availableNow=True)Process all available new files and stop — like a batch job
trigger(processingTime='1 minute')Process new files every minute — like a streaming job
.toTable(...)Registers the stream's output as a real Unity Catalog managed table

Part 1 — Ingest customers With Autoloader

STEP 1: DEFINE THE STREAM · STEP 2: WRITE TO BRONZE
customers_stream = (
    spark.readStream
    .format("cloudFiles")
    .option("cloudFiles.format", "csv")
    .option("cloudFiles.schemaLocation", customers_schema_path)
    .option("cloudFiles.inferColumnTypes", "true")
    .load(customers_source_path)
    .withColumn("_source_file", col("_metadata.file_path"))
    .withColumn("_ingested_at", current_timestamp())
)
customers_stream.writeStream \
    .format("delta") \
    .option("checkpointLocation", customers_checkpoint_path) \
    .option("mergeSchema", "true") \
    .trigger(availableNow=True) \
    .toTable(customers_target_table)  # gbmart.bronze.customers

.toTable() registers the output as a real Unity Catalog table. Anyone with catalog access can query it by name — no ADLS path needed.

Step 3 — Inspect the Result

customers_bronze = spark.table(customers_target_table)
customers_bronze.printSchema()
customers_bronze.show(5, truncate=True)

What to check

  • Schema was inferred automatically — real types, not everything-as-string
  • Audit columns present: _source_file, _ingested_at
  • Every Bronze table in this course carries these two audit columns

Part 2 — Ingest payments With Autoloader

Same pattern as Part 1 — swap customers for payments throughout. One Autoloader stream per source table is the production pattern: each table gets its own schema location, checkpoint, and target table.

payments_stream = (
    spark.readStream.format("cloudFiles")
    .option("cloudFiles.format", "csv")
    .option("cloudFiles.schemaLocation", payments_schema_path)
    .option("cloudFiles.inferColumnTypes", "true")
    .load(payments_source_path)
    .withColumn("_source_file", col("_metadata.file_path"))
    .withColumn("_ingested_at", current_timestamp())
)
payments_stream.writeStream.format("delta") \
    .option("checkpointLocation", payments_checkpoint_path) \
    .option("mergeSchema", "true") \
    .trigger(availableNow=True).toTable(payments_target_table)

Part 3 — The Magic of Autoloader: Run It Again

SAME FILES, SAME CHECKPOINT · WHAT HAPPENS?
customers_before = spark.table(customers_target_table).count()

# Re-define and re-run the IDENTICAL stream —
# same schema/checkpoint paths as before
...
customers_after = spark.table(customers_target_table).count()

if customers_after == customers_before:
    print("File(s) already processed — Autoloader SKIPPED them!")

Expectation: zero new rows. Autoloader checks its checkpoint, sees these files were already processed, and skips them — no duplicate rows land in Bronze.

Checkpoint Folder Contents

FolderWhat It Tracks
commits/List of completed micro-batches
offsets/Tracks progress through the source
sources/Tracks which exact files have been read
metadataQuery metadata

This is why Autoloader never re-reads the same file: every file's path and size is recorded in the checkpoint after processing.
