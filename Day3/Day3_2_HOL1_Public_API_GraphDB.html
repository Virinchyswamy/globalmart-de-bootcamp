Part 1 · 45 min

REST API: Beyond a Single Call

ILT 1 called frankfurter.app/latest once, for the default base currency (EUR). Two realistic extensions: multiple base currencies, and historical rates.

Step 1 — Multiple Base Currencies

SAME SETUP AS ILT 1 · ONE API CALL PER CURRENCY
# Same Unity Catalog External Location as ILT 1
EXTERNAL_LOCATION = "abfss://<your-container>@<your-storage-account>.dfs.core.windows.net"
sandbox_path = f"{EXTERNAL_LOCATION}/sandbox/api_graphdb"

base_currencies = ["USD", "EUR", "GBP"]  # GlobalMart's storefront currencies
all_rows = []

for base in base_currencies:
    response = requests.get("https://api.frankfurter.app/latest",
                            params={"base": base})
    if response.status_code != 200:
        raise RuntimeError(f"API call failed for base={base}")
    # ... flatten data["rates"] into Row objects, append to all_rows ...

multi_base_df = spark.createDataFrame(all_rows)

Why raise instead of skip? Don't silently skip a failed call — a DE pipeline should always know when a source didn't return what was expected.

Step 2 — Save to Sandbox

multi_base_df.write.format("delta").mode("overwrite") \
    .save(f"{sandbox_path}/fx_rates_multi_base")

overwrite is correct here — like ILT 1 explained, this is a live snapshot, not something we want to accumulate duplicate-but-stale rows for.

Your Turn — Historical Rates

frankfurter.app accepts a date in place of latest: https://api.frankfurter.app/2026-01-01.

  1. Loop over the two dates in historical_dates
  2. Call the API for each date (base currency EUR is fine)
  3. Keep both the requested date and the API-returned date as separate columns — they can differ on weekends/holidays
  4. Write with mode("append") — not overwrite — into sandbox_path/fx_rates_historical

This is the "accumulate history" case ILT 1 flagged. APIs give live snapshots — if you need history over time, you append with a date column instead of overwriting.

Part 2 · 75 min

GraphDB: Build a Small GlobalMart Graph

Create a free Neo4j AuraDB instance, seed it with GlobalMart-shaped data, and query it — before ever touching Databricks.

Step 1 — Create Your Free Neo4j AuraDB Account

You don't have a GraphDB account yet — here's exactly how to get real, usable credentials.

  1. Go to neo4j.com/cloud/aura, click Start Free — sign up with email or Google/GitHub (no credit card required)
  2. In the Aura Console, click Create instance → choose AuraDB Free
  3. Name it, e.g. globalmart-graph-demo → Create instance
  4. A dialog shows the URI, username (always neo4j), and generated password — the password is shown only once. Click Download credentials now.
  5. Wait ~1–2 minutes for status to turn from "Creating" to "Running"
  6. Click Open to launch the Neo4j Browser

These 3 values are the real credentials you'll paste into the notebook later — replacing the YOUR_INSTANCE_ID / YOUR_AURADB_PASSWORD placeholders.

Step 2 — Prepare the 4 CSV Files You'll Upload

Instead of typing Cypher by hand, build this graph the way you'd actually get real data: upload CSV files.

Same 11-node, 9-relationship graph as before — just delivered as files, the way you'd actually receive graph data on a real project.

Step 3 — Upload & Build the Graph With Neo4j Data Importer

NO-CODE TOOL — MAPS CSV COLUMNS TO NODES + RELATIONSHIPS
  1. From the Aura Console, open your instance → Import Data (or data-importer.neo4j.io, connect with your URI/username/password)
  2. Add data source → Upload files → select all 4 CSVs at once
  3. Map each file to a node table: customers→Customer, suppliers→Supplier, products→Product, orders→Order — each keyed on its _id column
  1. Draw 3 relationships on the canvas: Customer→Order (PLACED), Order→Product (CONTAINS), Product→Supplier (SUPPLIED_BY)
  2. Click Run import — writes every node + relationship into AuraDB in one batch, no Cypher typed by hand
  3. Back in the Neo4j Browser: MATCH (n) RETURN n — confirm 11 nodes, 9 relationships

Step 4 — Query in the Neo4j Browser

// Which products did each customer buy?
MATCH (c:Customer)-[:PLACED]->(o:Order)-[:CONTAINS]->(p:Product)
RETURN c.name, p.name, o.order_id

Your Turn (in the Neo4j Browser): write a Cypher query that counts how many orders each customer placed, sorted highest first — same shape as ILT 1's pattern #4: MATCH ... RETURN ... COUNT(o) ... ORDER BY.

Part 3

Read the Graph Into Databricks

Back in the notebook now — connect to AuraDB using the official neo4j Python driver, and land a query result as a sandbox Delta table.

Install the Driver and Connect

LIVE CODE · RUN IN DATABRICKS
%pip install neo4j

from neo4j import GraphDatabase

NEO4J_URI      = "neo4j+s://YOUR_INSTANCE_ID.databases.neo4j.io"  # replace
NEO4J_USER     = "neo4j"
NEO4J_PASSWORD = "YOUR_AURADB_PASSWORD"  # replace

driver = GraphDatabase.driver(NEO4J_URI, auth=(NEO4J_USER, NEO4J_PASSWORD))
def run_cypher(query, params=None):
    """Run one Cypher query, return a list of plain dicts."""
    with driver.session() as session:
        result = session.run(query, params or {})
        return [dict(record) for record in result]

Never commit real credentials. Replace these placeholders locally, then swap them back to placeholders before you upload or submit this notebook.

Run the Query and Save to Sandbox

rows = run_cypher("MATCH (c:Customer)-[:PLACED]->(o:Order)-[:CONTAINS]->(p:Product) RETURN ...")
graph_df = spark.createDataFrame(rows)
graph_df.write.format("delta").mode("overwrite") \
    .save(f"{sandbox_path}/graph_customer_orders")

Before Submitting

Good hygiene checklist

  • Replace NEO4J_URI and NEO4J_PASSWORD with placeholders again
  • Call driver.close() when done

An open driver holds a connection pool open on AuraDB's side — closing it is good hygiene, not optional cleanup.
