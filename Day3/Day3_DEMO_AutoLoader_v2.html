Scope note. This demo ingests every CSV in a private sandbox _demo/raw/ folder, including a stand-in orders.csv, purely to get a large-enough file set and a stable ID column (OrderID) to prove exactly-once processing live. In the real GlobalMart architecture, orders/order_items arrive via Postgres CDC through Lakeflow Connect (Day 2), not Autoloader. The genuinely Autoloader-sourced entities are products, customers, address, and payments (see HOL 2). Output here is written to a throwaway path under raw-data/_demo/bronze/orders_demo_v2/ — never the real gbmart.bronze.orders.

What We Are Proving

Auto Loader does NOT re-read files it has already processed. When a NEW file lands in ADLS, Auto Loader detects it automatically — zero manual intervention.

How Auto Loader Tracks Files — The Checkpoint

ADLS _demo/raw/ folder:
orders.csv ← Phase 1: processed ✅ (checkpoint remembers this)
orders_new.csv ← Phase 4: we drop this 🔴 (not yet seen)

What happens every trigger (30 seconds):
1. List all files in raw/
2. Compare against checkpoint sources/
3. orders.csv → already in checkpoint → SKIP
4. orders_new.csv → NOT in checkpoint → PROCESS ← this is the moment
5. Write 5 new rows to Bronze Delta
6. Update checkpoint — orders_new.csv now recorded

Phase 1 Load Everything, Rename Bad Columns

# shipping_tier.csv has "Cost (Rs)" — Delta rejects special chars in column names
for c in raw_stream.columns:
    clean = c.replace(" ", "_").replace("(", "").replace(")", "")
    if clean != c:
        raw_stream = raw_stream.withColumnRenamed(c, clean)
"Cost (Rs)" → "Cost_Rs" avoids DELTA_INVALID_CHARACTERS_IN_COLUMN_NAMES. Phase 1 and Phase 3 must use the same renaming logic, or the Bronze table schema won't match between the two writes.

Phase 3 Start the Continuous Stream

Phase 1 checkpoint state: orders.csv + all other CSVs → DONE
Phase 3 first trigger: all files → SKIP (in checkpoint), nothing new → IDLE
Phase 4 (file dropped): orders_new.csv → NEW → PROCESS

The stream runs in the background — you can run subsequent cells while it is active.

Phase 4 THE DEMO MOMENT

dbutils.fs.cp(f"{staging_path}/orders_new.csv", f"{raw_path}/orders_new.csv")

Trigger fires within 30 seconds → count jumps by 5 → _source_file shows orders_new.csv → _ingested_at is LATER than the Phase 1 rows.

Viva Q&A Highlights

QWhat's the main advantage of Auto Loader over spark.read? → Checkpoint = memory. No re-reads, no duplicates.
QavailableNow=True vs processingTime? → One-shot batch vs continuous polling.
QWhy does this demo use a path, not a Unity Catalog table like the real pipeline? → It's disposable — wiped and rebuilt every run via Clean Start. The real pipeline (HOL 2 onward) always registers a proper catalog.schema.table.
