What Is a REST API?

Think of an API like a waiter at a restaurant. You (your code) ask for something — an HTTP GET request. The waiter walks to the kitchen (the server), and brings back exactly what you asked for as a JSON response. You never need to know how the kitchen works.

API (Application Programming Interface) = a way for one system to talk to another over the internet. REST API = a specific style of API that uses HTTP, the same protocol as websites.

Your code                    API Server
   |                             |
   |── HTTP GET /latest ────────►|
   |                             |
   |◄─── JSON response ──────────|
   |
   ▼
Parse JSON → save to a landing table

The DE Ingestion Flow for APIs

  1. Call API — get JSON response
  2. Check status code — 200 = continue, anything else = raise error
  3. Parse JSON — convert to a Spark DataFrame
  4. Add audit columns — ingestion_timestamp, source_url
  5. Save to a landing table — Delta format, sandbox/ for this exploration

Live Demo — Call the frankfurter.app API

LIVE CODE · RUN IN DATABRICKS
import requests, json

api_url = "https://api.frankfurter.app/latest"
response = requests.get(api_url)

print(f"Status code : {response.status_code}")

if response.status_code == 200:
    data = response.json()  # parse JSON into a dict
    print(json.dumps(data, indent=2))
JSON fieldMeaning
amountBase amount the rates apply to (default 1.0)
baseThe base currency, e.g. "EUR"
dateThe date these rates are valid as of
ratesDict of 30+ target currencies → exchange rate

Flatten JSON → Spark DataFrame

from pyspark.sql import Row
from datetime import datetime

# One row per currency — flatten the nested rates dict
rows = [
    Row(base_currency=data["base"], target_currency=currency,
        exchange_rate=float(rate), rate_date=data["date"])
    for currency, rate in data["rates"].items()
]
fx_df = spark.createDataFrame(rows)

fx_df.write.format("delta").mode("overwrite") \
      .save(f"{sandbox_path}/fx_rates")

Idempotency for API data. APIs return live data — calling twice gives different results (rates change daily). Use mode("overwrite") for a live snapshot; use mode("append") with a rate_date column if you need history over time.

Introduction to Graph Databases

A completely different way to store data — as nodes and relationships instead of rows in tables joined by foreign keys.

What Is a Graph Database?

Picture a family tree or a mind-map — circles connected by labelled arrows. A graph database stores data exactly like that: nodes (entities) and relationships (connections between them).

The payoff: "Which suppliers connect to customers who returned products?" is a 4-table join in SQL — but a single Cypher traversal in a graph.

Relational DB (tables):        Graph DB (nodes + edges):

customers table                (Customer: Raj)
+----+---------+                     |
| id | name    |                   BOUGHT
+----+---------+                     |
| 1  | Raj     |              (Product: iPhone)
+----+---------+                     |
                                SUPPLIED_BY
orders table                         |
+----+----+------------+      (Supplier: Apple Inc.)
| id | cid| product_id |
+----+----+------------+

Illustrative Only — Modeling GlobalMart-Shaped Data as a Graph

NodeRelationshipNode
CustomerPLACED →Order
OrderCONTAINS →Product
ProductSUPPLIED_BY →Supplier
CustomerLIVES_IN →Address
OrderRETURNED_AS →Return

Not a real deliverable. This is a familiar example to build intuition for re-modeling entities you already know as a graph. Nothing here writes back into Bronze/Silver/Gold, and fact_sales does not depend on it.

Cypher Query Language Basics

Cypher is Neo4j's query language — designed to look like an ASCII drawing of the graph.

SQL:     SELECT * FROM customers WHERE city = 'Mumbai'
Cypher:  MATCH (c:Customer {city: 'Mumbai'}) RETURN c
-- Find all products a customer bought
MATCH (c:Customer {name: 'Raj'})-[:PLACED]->(o:Order)-[:CONTAINS]->(p:Product)
RETURN p.name, p.price

-- Count orders per customer (like GROUP BY)
MATCH (c:Customer)-[:PLACED]->(o:Order)
RETURN c.name, COUNT(o) AS total_orders
ORDER BY total_orders DESC

Reading From Neo4j Into Databricks

# pip install neo4j
from neo4j import GraphDatabase

driver = GraphDatabase.driver(NEO4J_URI, auth=(NEO4J_USER, NEO4J_PASSWORD))

with driver.session() as session:
    result = session.run("MATCH (c:Customer)-[:PLACED]->(o:Order) RETURN c.id, COUNT(o)")
    rows = [dict(r) for r in result]
# Land in the SAME sandbox/ location as the API demo, never bronze/
graph_df = spark.createDataFrame(rows)
graph_df.write.format("delta").mode("overwrite") \
    .save(sandbox_path + "/graph_customer_orders")
