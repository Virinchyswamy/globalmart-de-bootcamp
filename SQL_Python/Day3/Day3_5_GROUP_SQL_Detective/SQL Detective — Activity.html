ROUND 1Day 1 · CTE · 3 pts if first

Bysani needs to present a delivery heatmap. Find the top 5 cities with the most orders. Use a CTE.

city | state | order_count

5 rows · ordered by order_count DESC

3 tables: ex_orders → ex_customers (customer_id) → ex_locations (postal_code). City and state are in ex_locations.
CTE: GROUP BY l.city, l.state and COUNT(o.order_id). Outer query: SELECT TOP 5 ... WHERE l.city IS NOT NULL ORDER BY order_count DESC.
WITH city_orders AS (SELECT l.city, l.state, COUNT(o.order_id) AS order_count FROM ex_orders o LEFT JOIN ex_customers c ON o.customer_id=c.customer_id LEFT JOIN ex_locations l ON c.postal_code=l.postal_code WHERE l.city IS NOT NULL GROUP BY l.city, l.state) SELECT TOP 5 city, state, order_count FROM city_orders ORDER BY order_count DESC

ex_customerscustomer_id, postal_code

ROUND 2Day 3 · DATEDIFF · 5 pts if first

Now find the top 5 states with the most late deliveries and average days late. An order is late when it arrives after the estimated delivery date.

state | late_orders | avg_delay_days

5 rows · ordered by late_orders DESC

Same 3-table join. ex_orders has both delivery dates. ex_locations has state.
DATEDIFF(day, order_estimated_delivery_date, order_delivered_date) gives days late. Wrap in AVG().
WHERE order_delivered_date > order_estimated_delivery_date AND order_delivered_date IS NOT NULL. GROUP BY l.state. TOP 5. ORDER BY late_orders DESC.

ROUND 1Day 2 · DENSE_RANK · 3 pts if first

Hritin spotted some customers are massive spenders. Using DENSE_RANK(), rank customers by total revenue. Show the top 5 with their rank.

customer_name | total_revenue | revenue_rank

5 rows · ordered by revenue_rank ASC

ex_transactions (Sales_Amount) → ex_orders → ex_customers (customer_name). 3-table join. GROUP BY customer_name.
You cannot apply a window function to an aggregated column in the same SELECT. Aggregate first in a CTE, then apply DENSE_RANK() on top of the CTE result.
WITH customer_rev AS (SELECT c.customer_name, ROUND(SUM(t.Sales_Amount),2) AS total_revenue FROM ex_transactions t LEFT JOIN ex_orders o ON t.Order_ID=o.order_id LEFT JOIN ex_customers c ON o.customer_id=c.customer_id GROUP BY c.customer_name) SELECT TOP 5 customer_name, total_revenue, DENSE_RANK() OVER (ORDER BY total_revenue DESC) AS revenue_rank FROM customer_rev ORDER BY revenue_rank

TableKey columns
ex_transactionsOrder_ID, Sales_Amount, Discount, COGS
ex_ordersorder_id, customer_id
ex_customerscustomer_id, customer_name, segment
ROUND 2Day 3 · CASE WHEN in GROUP BY · 5 pts if first

Now answer Prishita's question — compare Discounted vs Full Price orders. Show order count, total revenue, and average revenue per order for each type.

price_type | order_count | total_revenue | avg_revenue

Exactly 2 rows · ordered by total_revenue DESC

Only ex_transactions — Discount and Sales_Amount are both there. No joins required.
CASE WHEN Discount > 0 THEN 'Discounted' ELSE 'Full Price' END in SELECT creates the two category labels.
Repeat the exact same CASE WHEN in GROUP BY — SQL Server does not allow GROUP BY by alias. Use COUNT(DISTINCT Order_ID) for order_count.

ROUND 1Day 1 · HAVING + subquery · 3 pts if first

Payal is building a loyalty targeting plan. Find customer segments whose average order value is above the overall average. Use HAVING with a subquery.

segment | avg_order_value

Only above-average segments · ordered by avg_order_value DESC

ex_transactions (Sales_Amount) → ex_orders → ex_customers (segment). GROUP BY c.segment.
You cannot filter aggregates with WHERE. Use HAVING AVG(t.Sales_Amount) > [something].
The "something" = (SELECT AVG(Sales_Amount) FROM ex_transactions). Put this scalar subquery directly inside the HAVING clause.

ROUND 2Day 3 · Profit margin · 5 pts if first

Now check all 3 segments — show total revenue, COGS, profit, and profit margin %. Prove or disprove leadership's vibes about Home Office.

segment | total_revenue | total_cogs | total_profit | profit_margin_pct

3 rows · ordered by total_profit DESC

Same 3-table join. COGS is in ex_transactions, segment is in ex_customers.
total_profit = ROUND(SUM(t.Sales_Amount - t.COGS), 2). Calculate inside SUM — not row-level then summed.
profit_margin_pct = ROUND(SUM(t.Sales_Amount - t.COGS) / SUM(t.Sales_Amount) * 100, 2). Divide aggregate sums — not average of row-level ratios.

ROUND 1Day 2 · Running total window function · 3 pts if first

Santosh is building a monthly ops dashboard. Show monthly order count and a running total of orders across all months using a window function.

yr | mo | monthly_orders | running_total

One row per month · ordered by yr, mo ASC

Only ex_orders. YEAR(order_purchase_date) and MONTH(order_purchase_date). Filter WHERE order_purchase_date IS NOT NULL.
SUM(monthly_orders) OVER (ORDER BY yr, mo) — cumulative sum that grows with each month row. This is your running_total.
CTE: GROUP BY YEAR and MONTH, COUNT(order_id). Outer SELECT: add the window function on top of the CTE columns.

ROUND 2Day 3 · DATEDIFF ×2 · 5 pts if first

Now answer Amardeep's real question — for each ship mode, show total orders, avg days to dispatch, and avg days to deliver. Fastest mode first.

ship_mode | total_orders | avg_days_to_dispatch | avg_days_to_deliver

3 rows · ordered by avg_days_to_deliver ASC (fastest first)

Only ex_orders. All columns needed: ship_mode, order_purchase_date, order_dispatched_date, order_delivered_date. No joins.
Two DATEDIFF() in SELECT: DATEDIFF(day, order_purchase_date, order_dispatched_date) and DATEDIFF(day, order_purchase_date, order_delivered_date). Both wrapped in AVG().

ROUND 2Day 3 · Subquery in SELECT · 5 pts if first

Give Hritin what he needs — each region's total revenue and its % share of GlobalMart's total. Most revenue first.

region | total_revenue | revenue_pct
