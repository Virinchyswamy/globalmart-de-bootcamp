Task 1: Total Sales per State & City

Tables: ex_transactions, ex_orders, ex_customers, ex_locations · mskl-masterclass · Kriti, four JOINs deep already
mskl-masterclass
-- Join chain: transactions → orders → customers → locations
-- Each join gets us one level closer to geographic data
SELECT
    l.state,
    l.city,
    SUM(t.sales_amount) AS total_sales
FROM ex_transactions t
-- LEFT JOIN: keep all transactions even if order data missing
LEFT JOIN ex_orders o
    ON t.order_id = o.order_id
LEFT JOIN ex_customers c
    ON o.customer_id = c.customer_id
LEFT JOIN ex_locations l
    ON c.postal_code = l.postal_code
-- GROUP BY both: we want one row per state+city combination
GROUP BY l.state, l.city;

Why LEFT JOIN here?

We want ALL transactions — even if there are any data integrity gaps (e.g. a transaction with no matching order due to a system issue). INNER JOIN would silently drop those rows.

Note: For ranking purposes, the difference is usually minimal. But LEFT JOIN is the safer, more professional choice.

Why can't we just JOIN ex_transactions directly to ex_locations?

✅ There's no direct FK between transactions and locations. We must navigate: transactions has order_id, orders has customer_id, customers has postal_code, locations has postal_code → state/city.

Task 2: Rank Cities Within Each State 🏆

2-CTE solution · mskl-masterclass
mskl-masterclass
-- CTE 1: Aggregate total sales per city per state
WITH city_sales AS (
    SELECT
        l.state,
        l.city,
        SUM(t.sales_amount) AS total_sales
    FROM ex_transactions t
    JOIN ex_orders o     ON t.order_id = o.order_id
    JOIN ex_customers c ON o.customer_id = c.customer_id
    JOIN ex_locations l  ON c.postal_code = l.postal_code
    GROUP BY l.state, l.city
),
-- CTE 2: Add rank within each state
-- PARTITION BY state → rank resets to 1 for each state
-- ORDER BY total_sales DESC → highest sales = rank 1
ranked_cities AS (
    SELECT
        state,
        city,
        total_sales,
        RANK() OVER (
            PARTITION BY state
            ORDER BY total_sales DESC
        ) AS city_rank
    FROM city_sales
)
-- Keep only top 3 cities per state
-- city_rank is a plain column here → WHERE works fine
SELECT
    state, city, total_sales,
    city_rank AS rank
FROM ranked_cities
WHERE city_rank <= 3;

What happens if PARTITION BY state is MISSING from RANK()?

✅ Rank becomes global — all cities across all states compete in one ranking. California's #1 city gets rank 1, Texas's #1 gets rank 2 or 3, etc. This is WRONG — each state should have its own rank 1.

Task 3 — Pivoting with MAX(CASE WHEN)

We need to turn three ranked rows per state into one row with three city columns. Instead of the PIVOT keyword, we use a flexible MAX(CASE WHEN) pattern.

Why MAX(CASE WHEN) Instead of PIVOT?

PIVOT requires the pivot values (1, 2, 3) to be known strings or numbers in column headers. CASE WHEN gives us full flexibility — we can rename columns (rank_1, rank_2) and it works reliably in T-SQL for any data type.

The pattern:

-- For each state row, CASE returns the city name
-- when it's rank 1, else NULL.
-- MAX() picks the non-NULL value (there's only one per state)
MAX(CASE WHEN city_rank = 1 THEN city END) AS rank_1,
MAX(CASE WHEN city_rank = 2 THEN city END) AS rank_2,
MAX(CASE WHEN city_rank = 3 THEN city END) AS rank_3

Why MAX()? Why Not Just CASE?

After filtering to top 3 cities, we GROUP BY state. Within each state group, we need to collapse 3 rows into 1. MAX() grabs the only non-NULL value per rank column.

Per state group after filtering:

citycity_rankCASE rank=1CASE rank=2
Los Angeles1Los AngelesNULL
San Francisco2NULLSan Francisco
San Diego3NULLNULL

MAX() per column → Los Angeles, San Francisco. Collapsed into 1 row.

Task 3: Full 4-CTE Pivot Report

Complete solution · all 4 ex_ tables · mskl-masterclass
mskl-masterclass
WITH city_sales AS (
    -- Step 1: Aggregate sales by state + city
    SELECT l.state, l.city,
           SUM(t.sales_amount) AS total_sales
    FROM ex_transactions t
    JOIN ex_orders o     ON t.order_id = o.order_id
    JOIN ex_customers c ON o.customer_id = c.customer_id
    JOIN ex_locations l  ON c.postal_code = l.postal_code
    GROUP BY l.state, l.city
),
ranked_cities AS (
    -- Step 2: Rank cities within each state
    SELECT state, city, total_sales,
        RANK() OVER(
            PARTITION BY state
            ORDER BY total_sales DESC
        ) AS city_rank
    FROM city_sales
),
top_3_cities AS (
    -- Step 3: Keep only top 3 per state
    -- Critical: filter BEFORE the pivot — otherwise all cities appear
    SELECT state, city, city_rank
    FROM ranked_cities
    WHERE city_rank <= 3
)
-- Step 4: Pivot the 3 ranked rows into 3 columns per state
-- MAX() + CASE WHEN pattern — standard T-SQL pivot technique
SELECT
    state,
    MAX(CASE WHEN city_rank = 1 THEN city END) AS rank_1,
    MAX(CASE WHEN city_rank = 2 THEN city END) AS rank_2,
    MAX(CASE WHEN city_rank = 3 THEN city END) AS rank_3
FROM top_3_cities
GROUP BY state
ORDER BY state;

(Illustrative — run query for actual values)

Why is it essential to filter city_rank <= 3 in top_3_cities BEFORE the final GROUP BY and CASE WHEN?

✅ If you skip the filter, ALL ranked cities go into the GROUP BY. The CASE WHEN for rank_1/2/3 still works, but you process hundreds of unnecessary rows — and rank 4, 5, 6... cities are included in the join scan. Always filter BEFORE aggregating.
