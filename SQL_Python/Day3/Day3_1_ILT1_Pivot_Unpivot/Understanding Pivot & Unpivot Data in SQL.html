🔄 What Does PIVOT Actually Do?

PIVOT takes data that's stacked in rows and rotates one column's unique values so each becomes its own column — the same reshaping an Excel pivot table does, just written as SQL.

Before PIVOT — rows format:

month_nameorder_yearorder_placed
January2017211
January2018264
February2017198
February2018310
→

After PIVOT — columns format:

month_name[2017][2018]
January211264
February198310

PIVOT takes unique values from one column (order_year → 2017, 2018) and turns each into its own column, applying an aggregate function (SUM of order_placed) to fill the cells.

The 3-Part PIVOT Syntax

mskl-masterclass
PIVOT(
    SUM(order_placed)   -- what to aggregate
    FOR [order_year]     -- which column to rotate
    IN (
        [2017],          -- each unique value becomes a column
        [2018]           -- square brackets are MANDATORY
    )
) AS pvt             -- alias is required

Building the PIVOT Query Step by Step

Table: orders · mskl-masterclass · Prem, live, no pressure

Step 1: Build the base data first (the "long" format)

mskl-masterclass
WITH base_data AS (
    SELECT
        o.order_id,
        -- DATENAME gives "January", "February"...
        -- Use month NAME in SELECT, month NUMBER for ORDER BY
        DATENAME(month, o.order_purchase_date) AS month_name,
        MONTH(o.order_purchase_date)             AS month_seq,
        YEAR(o.order_purchase_date)              AS order_year
    FROM orders o
    -- 2016 data is incomplete — exclude it
    WHERE YEAR(o.order_purchase_date) <> 2016
),
-- Step 2: Aggregate to one row per month per year
order_summary AS (
    SELECT
        month_name,
        month_seq,
        order_year,
        COUNT(order_id) AS order_placed
    FROM base_data
    GROUP BY month_name, month_seq, order_year
)
-- Run this first to see the "long" format output ↑
SELECT * FROM order_summary ORDER BY order_year, month_seq;

Step 2: Replace the final SELECT with PIVOT

mskl-masterclass
-- Replace "SELECT * FROM order_summary" with this:
SELECT
    month_name,
    [2017],
    [2018]
FROM order_summary
    PIVOT(
        SUM(order_placed)
        FOR [order_year]
        IN (
            [2017],
            [2018]
        )
    ) AS pvt
-- Note: month_seq no longer available after PIVOT
-- Can't ORDER BY month_seq here — include it before
-- or just accept alphabetical month ordering in output
ORDER BY month_name;

After running this PIVOT, which month in 2017 had the HIGHEST number of orders?

✅ November 2017 — the highest order count in the 2017 column. Run the query and look for the biggest value in [2017].

What is the number of orders placed in August 2018?

✅ 360 — look at the August row in the [2018] column.

⚠️ PIVOT Rules You Must Know

RuleWhy It Matters
Values in IN() must use [square brackets]Numbers like 2017 can't be bare column names — mandatory
Alias after PIVOT is required (AS pvt)SQL requires the derived table to have a name
Years in IN() must be hard-codedPIVOT needs exact known values — can't use a subquery inside IN()
Only ONE aggregate function allowedPIVOT applies one function across all pivoted columns
month_seq disappears after PIVOT if not selectedYou can't ORDER BY month_seq outside the PIVOT unless it's kept

The month ordering trap: If you ORDER BY month_name, months sort alphabetically (April, August, December...). To get Jan → Dec order you need to either keep month_seq in the PIVOT output or accept alphabetical order for this demo.

✅ TRUE or ❌ FALSE?

PIVOT rotates unique values from one column into multiple columns — TRUE or FALSE?

✅ TRUE — this is the core behavior of PIVOT.

NULL values in the value column ARE considered when computing a PIVOT aggregation — TRUE or FALSE?

✅ FALSE — NULLs are ignored in aggregations. PIVOT with SUM treats a NULL group as 0 in the output cell.

UNPIVOT rotates a table by turning unique values from one column into multiple columns — TRUE or FALSE?

✅ FALSE — that's PIVOT's job. UNPIVOT does the OPPOSITE: it turns multiple columns back into rows.

🔃 UNPIVOT — The Reverse Operation

When would you use UNPIVOT?
When data arrives pre-pivoted (e.g. from Excel, a legacy report, or an external system) but you need it in rows format for further SQL analysis, joining, or filtering. UNPIVOT un-flattens the data so SQL can work with it naturally.

UNPIVOT Syntax

Table: unpivot_example · mskl-masterclass · Raghul narrating, unbearably calm
mskl-masterclass
-- Step 1: Look at the source table (already in column format)
SELECT * FROM unpivot_example;

-- Step 2: Write the column names out explicitly
-- (required — UNPIVOT needs to know which columns to melt)
SELECT
    month_name,
    [2017],
    [2018]
FROM unpivot_example;

-- Step 3: Wrap in subquery and apply UNPIVOT
-- The subquery becomes the "source" table
-- UNPIVOT melts [2017] and [2018] columns into rows
SELECT
    month_name,
    order_year,    -- new column: holds the year value ("2017" or "2018")
    order_count    -- new column: holds the numeric count from the old columns
FROM (
    SELECT
        month_name,
        [2017],
        [2018]
    FROM unpivot_example
) p
UNPIVOT (
    order_count           -- name for the VALUE column
    FOR order_year        -- name for the KEY column (holds "2017", "2018")
    IN ([2017], [2018]) -- which columns to melt into rows
) AS result;

PIVOT vs UNPIVOT at a Glance

OperationDirectionUse When
PIVOTRows → ColumnsData is in rows, you want columns for comparison
UNPIVOTColumns → RowsData arrives pre-pivoted, you need rows for SQL analysis

Both require:
• Square brackets around year values
• An alias on the operation block
• Hard-coded column/value names

Remember the structure:
UNPIVOT has 3 parts too:
1. order_count — name for the values column
2. FOR order_year — name for the key column
3. IN ([2017], [2018]) — which columns to melt

🚫 Common Mistakes — Module 9

MistakeWhat Goes WrongFix
Missing square brackets on valuesSQL error — numeric literals can't be bare column namesAlways write [2017], not 2017
Missing alias after PIVOT/UNPIVOTSQL error — derived table must have aliasAdd AS pvt or AS result
Using a subquery inside IN()PIVOT does not support dynamic values in IN() — errorHard-code the values: IN ([2017],[2018])
ORDER BY month_name (string)Alphabetical order — August before JanuaryInclude month_seq in order_summary and ORDER BY it before PIVOT
Confusing PIVOT and UNPIVOT directionOutput is backwards — columns when you need rows, or vice versaPIVOT: rows→cols · UNPIVOT: cols→rows

Which statement is INCORRECT about PIVOT in SQL?
a) PIVOT converts rows to columns   b) UNPIVOT converts columns to rows   c) UNPIVOT rotates unique values from one column into multiple columns   d) NULL values in aggregations are not considered

✅ c) is INCORRECT — that's the definition of PIVOT, not UNPIVOT. UNPIVOT does the opposite: it melts multiple columns back into rows.

PIVOT — Rows to Columns

SELECT month_name, [2017], [2018]
FROM order_summary
PIVOT(
    SUM(order_placed)
    FOR [order_year]
    IN ([2017], [2018])
) AS pvt;

UNPIVOT — Columns to Rows

SELECT month_name, order_year, order_count
FROM (SELECT month_name, [2017], [2018]
       FROM unpivot_example) p
UNPIVOT(
    order_count
    FOR order_year IN ([2017], [2018])
) AS result;
