## Concept: Parsing and formatting dates with strptime and strftime


Python's built-in `datetime` module gives you two core functions for working with dates stored as strings:

- **`datetime.strptime(date_string, format)`** - reads a string and converts it into a `datetime` object ("string **p**arse **time**")
- **`datetime.strftime(format)`** - takes a `datetime` object and converts it back into a string in the format you specify ("string **f**ormat **time**")

**Analogy:** Think of a raw date string like `"15/03/2024"` as a handwritten note in someone else's shorthand. `strptime` is the translator who reads that shorthand and converts it into a universally understood concept - a `datetime` object. Once you have that universal concept, `strftime` is the publisher who can print it in whatever style each audience needs: formal reports, chart labels, SMS notifications.

**Common format codes:**

| Code | Meaning | Example Output |
|---|---|---|
| `%Y` | 4-digit year | `2024` |
| `%y` | 2-digit year | `24` |
| `%m` | Month as zero-padded number | `03` |
| `%B` | Full month name | `March` |
| `%b` | Abbreviated month name | `Mar` |
| `%d` | Day as zero-padded number | `15` |
| `%A` | Full weekday name | `Tuesday` |
| `%a` | Abbreviated weekday name | `Tue` |
| `%H` | Hour (24-hour clock) | `14` |
| `%I` | Hour (12-hour clock) | `02` |
| `%M` | Minutes | `45` |
| `%S` | Seconds | `00` |
| `%p` | AM or PM | `AM` |


**When to use each function:**

| Task | Function | Direction |
|---|---|---|
| Convert string → datetime | `strptime` | Parsing |
| Convert datetime → string | `strftime` | Formatting |
| Re-format one string into another | Both - parse first, then format | Parse → Format |

>[!IMPORTANT]
> strptime and strftime are never called in isolation when re-formatting. The correct sequence is always: raw string → strptime() → datetime object → strftime() → output string.

>[!TIP]
> To avoid errors, inspect a sample value with print(df["column"].iloc[0]) before writing your format string. Build your strptime pattern character-by-character to match the raw string exactly.

**Solution:** 
**Parse first, format second** -`strptime` converts the raw string into a datetime object that Python can manipulate; `strftime` then renders it in the exact display format required.

```python
import pandas as pd
from datetime import datetime

# Load table
orders = pd.read_csv("https://cdn.enqurious.com/documents/ca1a31d6-b8c9-4f71-8346-36989a1de15f_exorders.csv")

# Define the raw format of order_purchase_date
raw_fmt    = "%Y-%m-%d %H:%M:%S.%f"  # includes microseconds if present
# Define the output format for the operations digest label
output_fmt = "%A, %d %B %Y"

# Parse the raw string → datetime, then format → label string
orders["purchase_label"] = orders["order_purchase_date"].apply(
    lambda val: datetime.strptime(val, raw_fmt).strftime(output_fmt)
)

# Select only the columns needed for the digest report
result = orders[["order_id", "order_purchase_date", "purchase_label"]]

print(result.head())
```

- **`raw_fmt = "%Y-%m-%d %H:%M:%S.%f"`**: Matches the raw string exactly — year, month, day, then a space, then hours, minutes, seconds, and optional microseconds (`.%f`). If the raw string does not have microseconds, use `"%Y-%m-%d %H:%M:%S"`. A mismatch raises `ValueError: time data does not match format`.
- **`output_fmt = "%A, %d %B %Y"`**: `%A` gives the full weekday name, `%d` gives the zero-padded day, `%B` gives the full month name, `%Y` gives the four-digit year. No time codes are included — the time component is intentionally discarded in the output.
- **`.apply(lambda val: ...)`**: `datetime.strptime()` only accepts a single string — it cannot be called directly on a pandas Series. `.apply()` iterates row by row, passing each value individually.
- **Chaining `.strptime().strftime()`**: Doing both in a single lambda avoids creating an intermediate datetime column that would need to be dropped later.

>[!NOTE]
> `%A` (full weekday) and `%B` (full month) are locale-sensitive. In a non-English locale, they may return the weekday or month name in the system language (e.g., `"März"` instead of `"March"`). If your deployment environment may have a non-English locale, use numeric codes and map to English names manually.

**Parse once, format twice** — a helper function that returns a `pd.Series` lets you derive multiple label columns from a single `strptime` call, avoiding redundant parsing.

```python
import pandas as pd
from datetime import datetime

# Load table
orders = pd.read_csv("https://cdn.enqurious.com/documents/ca1a31d6-b8c9-4f71-8346-36989a1de15f_exorders.csv")

raw_fmt        = "%Y-%m-%d %H:%M:%S.%f"
digest_fmt     = "%A, %d %B %Y"
time_label_fmt = "%I:%M %p"   # 12-hour clock with AM/PM

# Helper: parse once, produce both labels
def build_labels(val):
    dt = datetime.strptime(val, raw_fmt)
    return pd.Series({
        "purchase_label"    : dt.strftime(digest_fmt),
        "time_of_day_label" : dt.strftime(time_label_fmt)
    })

labels = orders["order_purchase_date"].apply(build_labels)

# Concatenate labels back to the original DataFrame
result = pd.concat([orders[["order_id", "order_purchase_date"]], labels], axis=1)

print(result.head())
```

- **`time_label_fmt = "%I:%M %p"`**: `%I` is the 12-hour clock hour (01–12), `%M` is minutes, and `%p` is the AM/PM indicator. Using `%H` here would produce 24-hour values like `"14:10"` instead of `"02:10 PM"`.
- **`%I` vs `%H`**: The raw data stores hours in 24-hour format. `strptime` with `%H` correctly parses `"14"` as 2 PM. When outputting, switching to `%I` + `%p` converts it to 12-hour display format automatically.
- **`pd.Series({...})` in helper function**: Returning a `pd.Series` with named keys from `.apply()` causes pandas to automatically expand it into two new columns. This is cleaner than running `.apply()` twice on the same column.
- **`pd.concat(..., axis=1)`**: Joins the original identifier columns with the two new label columns horizontally. `axis=1` means column-wise concatenation, not row-wise.

```python
import pandas as pd
from datetime import datetime

# Load table
campaigns = pd.read_csv("https://cdn.enqurious.com/documents/fb6f45f8-91cc-4b68-8de8-2e2e97734839_excampaigns.csv")

# Define formats once — raw input and desired output
raw_fmt    = "%Y-%m-%d"
output_fmt = "%d/%m/%Y"

# Reusable helper: parse then format
def reformat_date(val):
    return datetime.strptime(val, raw_fmt).strftime(output_fmt)

# Apply to both campaign date columns
campaigns["start_label"] = campaigns["start_date"].apply(reformat_date)
campaigns["end_label"]   = campaigns["end_date"].apply(reformat_date)

# Select columns for the marketing report

                     "start_label", "end_label"]]

print(result.head())
```

- **Reusable `reformat_date()` function**: Defining the logic once in a named function rather than two separate lambdas means the format strings only need to be updated in one place if the raw format changes — a key principle of DRY (Don't Repeat Yourself) code.
- **Applying to two columns**: `.apply(reformat_date)` is called separately on `start_date` and `end_date`. There is no need to write the parse-format logic twice — the function handles both.

**Question:** A colleague runs `datetime.strftime("2024-03-15", "%d %B %Y")` and gets an `AttributeError`. 
What is the most likely cause?

**Options:** 
- The format string `"%d %B %Y"` is invalid and cannot be used with `strftime`

- `strftime` was called directly on a plain string instead of a `datetime` object

- `strptime` should have been used instead of `strftime` for this output format

- The date string `"2024-03-15"` is too short to produce a full weekday name

**Correct Options:** 
- `strftime` was called directly on a plain string instead of a `datetime` object

**Solution:** 
**`strftime` is a method of `datetime` objects — not strings** — calling it on a raw string raises `AttributeError` because Python strings do not have a `strftime` method.

- **`strftime` on a string ✅** — The error occurs because `"2024-03-15"` is a plain Python string, and strings have no `strftime` method. The correct sequence is: `datetime.strptime("2024-03-15", "%Y-%m-%d").strftime("%d %B %Y")` — parse first to get a `datetime` object, then format.
- **Invalid format string ❌** — `"%d %B %Y"` is a perfectly valid `strftime` format string. `%d` is the zero-padded day, `%B` is the full month name, and `%Y` is the four-digit year. The format string is not the problem.
- **`strptime` instead of `strftime` ❌** — `strptime` parses a string into a datetime object; it does not produce formatted output. The colleague's goal is to produce a formatted label, so `strftime` is the correct function — it is just being called on the wrong type.
- **String too short ❌** — String length has no bearing on whether `strftime` can produce a weekday name. The weekday is derived from the parsed datetime object, not from the length of the raw string.

##### Input 9
**Type:** Choice

**Question:** Which of the following `strptime` patterns will correctly parse the raw string `"2024-03-15 14:30:00"` without raising a `ValueError`? (Select 2)

**Options:** 
- `"%Y-%m-%d %H:%M:%S"`

- `"%Y/%m/%d %H:%M:%S"`

- `"%Y-%m-%d %H:%M:%S.%f"`

- `"%Y-%m-%d"`

**Correct Options:** 
- `"%Y-%m-%d %H:%M:%S"`

- `"%Y-%m-%d %H:%M:%S.%f"`

**Solution:** 
**The `strptime` pattern must match the raw string character-for-character** — any separator mismatch or missing component raises `ValueError`.

- **`"%Y-%m-%d %H:%M:%S"` ✅** — This pattern matches the raw string exactly: four-digit year, hyphen, two-digit month, hyphen, two-digit day, space, two-digit hour, colon, two-digit minute, colon, two-digit second. No `ValueError` is raised.
- **`"%Y-%m-%d %H:%M:%S.%f"` ✅** — This pattern also parses correctly. `%f` matches microseconds, but when the raw string has no microseconds (`.000000`) the pattern still works — pandas and Python's `datetime` treat the absence of microseconds as `0` when `%f` is included. This makes it a safe default for timestamp columns that may or may not include microseconds.
- **`"%Y/%m/%d %H:%M:%S"` ❌** — The separators between year, month, and day are forward slashes (`/`) in this pattern, but the raw string uses hyphens (`-`). This mismatch raises `ValueError: time data '2024-03-15 14:30:00' does not match format '%Y/%m/%d %H:%M:%S'`.
- **`"%Y-%m-%d"` ❌** — This pattern only accounts for the date portion. After parsing `"2024-03-15"`, the remaining `" 14:30:00"` is left unconsumed, which raises `ValueError: unconverted data remains: 14:30:00`. When a time component is present in the raw string, the `strptime` pattern must include it.

>[!NOTE]
> Always inspect the raw string with `print(df["column"].iloc[0])` before writing your `strptime` pattern. The most common source of `ValueError` is a mismatch between the separator characters (hyphens vs slashes vs spaces) or a missing time component.
