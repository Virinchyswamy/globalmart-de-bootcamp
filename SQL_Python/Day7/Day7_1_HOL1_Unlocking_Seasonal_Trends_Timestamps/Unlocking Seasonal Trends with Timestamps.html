Unlocking Seasonal Trends
with Timestamps

Use the .dt accessor to extract date components, map to seasons, pivot/unpivot for analysis, and rank within groups

🎯 The Goal

GlobalMart wants to understand revenue by product category across seasons — which category dominates in Summer? Which season is best for Technology sales?

The pipeline:

  1. Join orders → transactions → products
  2. Extract month + season from order date
  3. Compute monthly revenue per category
  4. Pivot (long → wide) for cross-category view
  5. Melt (wide → long) for ranking and sorting
  6. Rank categories within each season

SQL Mental Model — Visualise the Pipeline Before Writing Python

Every Python step in this module has a direct SQL equivalent. Understand the SQL first — Python is just a different syntax for the same idea.

-- Step 1: JOIN the three tables
SELECT o.order_id, o.order_purchase_date,
       t.Sales_Amount, p.category
FROM   orders o
LEFT JOIN transactions t ON o.order_id = t.Order_ID
LEFT JOIN products     p ON t.Product_ID = p.product_id;

-- Step 2: Extract month number + assign season
SELECT *,
  EXTRACT(MONTH FROM order_purchase_date) AS month_num,
  CASE
    WHEN EXTRACT(MONTH FROM order_purchase_date) IN (12,1,2)
         THEN 'Winter'
    WHEN EXTRACT(MONTH FROM order_purchase_date) IN (3,4,5)
         THEN 'Spring'
    WHEN EXTRACT(MONTH FROM order_purchase_date) IN (6,7,8)
         THEN 'Summer'
    ELSE 'Autumn'
  END AS season
FROM joined;

-- Step 3: Aggregate monthly revenue
SELECT month_num, season, category,
       SUM(Sales_Amount) AS revenue
FROM   enriched
GROUP BY month_num, season, category;
-- Step 4: Pivot — SQL needs CASE per category (verbose!)
SELECT month_num, season,
  SUM(CASE WHEN category='Furniture'
       THEN revenue ELSE 0 END) AS Furniture,
  SUM(CASE WHEN category='Technology'
       THEN revenue ELSE 0 END) AS Technology,
  SUM(CASE WHEN category='Office Supplies'
       THEN revenue ELSE 0 END) AS OfficeSupplies
FROM monthly GROUP BY month_num, season;
-- Python: pivot_table(columns='category') — one line!

-- Step 5: Melt = SQL UNION ALL (very verbose!)
SELECT month_num, season, 'Furniture' AS category,
       Furniture AS revenue FROM wide
UNION ALL
SELECT month_num, season, 'Technology', Technology FROM wide
UNION ALL
SELECT month_num, season, 'Office Supplies', OfficeSupplies FROM wide;
-- Python: .melt() does this in one line!

-- Step 6: Rank within season
SELECT season, category,
       SUM(revenue) AS seasonal_revenue,
       DENSE_RANK() OVER (
         PARTITION BY season
         ORDER BY SUM(revenue) DESC
       ) AS category_rank
FROM melted GROUP BY season, category;
-- Python: groupby('season').rank(method='dense', ascending=False)

Step 1 — Load Data and Join the Three Tables

Parse the date column at load time using parse_dates, then chain the three tables: orders → transactions → products.

import pandas as pd

# parse_dates converts the column to datetime at load time
orders = pd.read_csv(
    "exorders.csv",
    parse_dates=["order_purchase_date"]
)
transactions = pd.read_csv("extransactions.csv")
products     = pd.read_csv("exproducts.csv")

# ─── Join chain ──────────────────────────────────────────
# NOTE: column names are case-sensitive across tables
# orders.order_id ≠ transactions.Order_ID — use left_on/right_on

orders_txn = orders.merge(
    transactions,
    left_on='order_id', right_on='Order_ID',
    how='left'
)

df = orders_txn.merge(
    products,
    left_on='Product_ID', right_on='product_id',
    how='left'
)
# df now has: order_id, order_purchase_date (datetime),
#             Sales_Amount, category

parse_dates at load time — why?

Without parse_dates, the date column loads as plain strings — the .dt accessor won't work. Passing parse_dates=["col_name"] tells pandas to automatically parse that column as datetime during the read — saving a separate conversion step.

Join logic diagram

    ↕ (left_on / right_on — case differs)
transactions.Order_ID ←→ .Product_ID
                              ↕
                    products.product_id → .category

💡 Think in SQL first — how do you JOIN these 3 tables when column names differ in case?

SQL:
SELECT * FROM orders o
LEFT JOIN transactions t ON o.order_id = t.Order_ID
LEFT JOIN products p ON t.Product_ID = p.product_id;

Python: When column names differ in casing, use left_on='order_id', right_on='Order_ID' — same concept as SQL's ON o.order_id = t.Order_ID.

Step 2 — Extract Date Parts and Map to Seasons

The .dt accessor gives access to date components from a datetime column. A dictionary maps month numbers to season names.

# .dt accessor — extract date components
df["month_num"]  = df["order_purchase_date"].dt.month
# → integers 1–12  (January=1, December=12)

df["month_name"] = df["order_purchase_date"].dt.month_name()
# → "January", "February", ..., "December"
# Note: month is a property, month_name() is a method with ()

# Season mapping dictionary
season_map = {
    12: "Winter",  1: "Winter",  2: "Winter",
     3: "Spring",  4: "Spring",  5: "Spring",
     6: "Summer",  7: "Summer",  8: "Summer",
     9: "Autumn", 10: "Autumn", 11: "Autumn"
}

# .map() applies the dictionary lookup to each value
df["season"] = df["month_num"].map(season_map)

# order_purchase_date | month_num | month_name | season
# 2018-03-15          | 3         | March      | Spring
# 2017-07-20          | 7         | July       | Summer
# 2017-12-01          | 12        | December   | Winter

💡 Think in SQL first — how would you extract the month number and assign a season?

SQL:
SELECT EXTRACT(MONTH FROM order_purchase_date) AS month_num,
  CASE WHEN month_num IN (12,1,2) THEN 'Winter'
      WHEN month_num IN (3,4,5) THEN 'Spring'
      WHEN month_num IN (6,7,8) THEN 'Summer'
      ELSE 'Autumn' END AS season FROM df;

Python: .dt.month = EXTRACT(MONTH); dict + .map() = the CASE WHEN IN (...) block — but written once, applied to every row.

Step 3 — Aggregate Monthly Revenue by Category

Group by month and category to get total revenue. This is the source data for our pivot table.

# Group by month dimensions + category
# Sum the revenue (Sales_Amount) for each combination
# Note: column is 'Sales_Amount' (capital S and A) in the data
base = (
    df
    .groupby(
        ['month_num', 'month_name', 'season', 'category'],
        as_index=False
    )
    .agg(revenue=('Sales_Amount', 'sum'))
    .sort_values('month_num')
    .reset_index(drop=True)
)

print(base.head(12).to_string(index=False))
# month_num month_name season        category     revenue
#         1    January Winter       Furniture  62695.5571
#         1    January Winter Office Supplies  58986.6470
#         1    January Winter      Technology  53778.6280
#         2   February Winter       Furniture  58640.1918
# ...
# This is LONG format — one row per (month, category) combo
# 12 months × 3 categories = 36 rows total

Why include month_num, month_name, and season all in groupby?

  • month_num — needed for sorting (numeric order)
  • month_name — needed for display in the output
  • season — needed for seasonal grouping and ranking
  • Since each row has one unique month, grouping by all three together doesn't change the result — it just preserves all three columns

Long format vs Wide format

Long format (current): one row per month-category combination. Good for groupby and ranking.

Wide format (after pivot): one row per month, columns = categories. Good for side-by-side comparison.

💡 Think in SQL first — how would you aggregate monthly revenue per category?

SQL:
SELECT month_num, month_name, season, category,
  SUM(Sales_Amount) AS revenue
FROM enriched
GROUP BY month_num, month_name, season, category
ORDER BY month_num;

Python:
df.groupby([...]).agg(revenue=('Sales_Amount','sum'))
Named aggregation syntax: (col_name, agg_func) — same as SUM(col) AS name in SQL.

Step 4 — Pivot: Long → Wide Format

pivot_table() reshapes from one-row-per-category to one-row-per-month with categories as columns — ideal for cross-category comparison.

# pivot_table: rotate the 'category' values into column headers
# index = what stays as rows
# columns = which column's values become new column names
# values = which column's values to fill the cells
# aggfunc = 'sum' since we might have duplicate month-category rows
# fill_value = 0 for month-category combos with no sales

pivot_df = (
    base
    .pivot_table(
        index      = ['month_num', 'month_name', 'season'],
        columns    = 'category',
        values     = 'revenue',
        aggfunc    = 'sum',
        fill_value = 0
    )
    .reset_index()
    .sort_values('month_num')
    .reset_index(drop=True)
)

# Remove the "category" axis label from the column header row
pivot_df.columns.name = None

# Result (wide format — 12 rows, one per month):
# month_num | month_name | season | Furniture | Office Supplies | Technology
# 1         | January    | Winter | 62695.56  | 58986.65        | 53778.63
# 2         | February   | Winter | 58640.19  | 64841.39        | 73089.55

pivot_table arguments — what each does

ArgumentRole
indexColumns that stay as row identifiers
columnsColumn whose values become new column names
valuesColumn whose values fill the cells
fill_valueReplaces NaN where no data exists

columns.name = None — why?

After pivot_table, the columns axis has the name "category" (from the source column). Setting pivot_df.columns.name = None removes it for cleaner output — no extra header row.

💡 Think in SQL first — how would you pivot revenue into one column per category?

SQL (manual pivot — very verbose):
SELECT month_num, season,
  SUM(CASE WHEN category='Furniture' THEN revenue ELSE 0 END) AS Furniture,
  SUM(CASE WHEN category='Technology' THEN revenue ELSE 0 END) AS Technology
FROM base GROUP BY month_num, season;

Python (one line!):
base.pivot_table(index=[...], columns='category', values='revenue', aggfunc='sum', fill_value=0)
Python doesn't need one CASE per category — it reads all unique values automatically.

Step 5 — Melt: Wide → Long + Seasonal Revenue

melt() reverses the pivot — converts wide back to long for groupby and ranking. Then compute total seasonal revenue per category.

# Melt the pivot table back to long format
# id_vars = columns that stay as row identifiers (don't melt)
# var_name = new column name for the old column headers
# value_name = new column name for the cell values

melted_df = (
    pivot_df
    .melt(
        id_vars    = ['month_num', 'month_name', 'season'],
        var_name   = 'category',
        value_name = 'revenue'
    )
    .sort_values(['month_num', 'category'])
    .reset_index(drop=True)
)

# month_num | month_name | season | category        | revenue
# 1         | January    | Winter | Furniture        | 62695.56
# 1         | January    | Winter | Office Supplies  | 58986.65
# 1         | January    | Winter | Technology       | 53778.63
# 2         | February   | Winter | Furniture        | 58640.19

# Total revenue per season per category
seasonal = (
    melted_df
    .groupby(['season', 'category'], as_index=False)
    .agg(seasonal_revenue=('revenue', 'sum'))
)

melt() arguments

ArgumentRole
id_varsColumns that stay as identifiers (not melted)
var_nameName for the new column holding old column headers
value_nameName for the new column holding the cell values

Pivot ↔ Melt — symmetric operations

Pivot: many rows → fewer rows, more columns (wide)
Melt: fewer rows → many rows, fewer columns (long)
They are inverses. Long = better for groupby; wide = better for reading.

💡 Think in SQL first — how would you "un-pivot" the wide table back to long format?

SQL (verbose UNION ALL):
SELECT month_num, 'Furniture' AS category, Furniture AS revenue FROM wide
UNION ALL
SELECT month_num, 'Technology', Technology FROM wide
UNION ALL
SELECT month_num, 'Office Supplies', OfficeSupplies FROM wide;

Python (one line!):
pivot_df.melt(id_vars=[...], var_name='category', value_name='revenue')

Step 6 — Rank Within Season + Custom Sort Order

Use groupby().rank() to rank categories by revenue within each season. Then sort seasons in a custom order (not alphabetical).

# Rank each category by seasonal_revenue within each season
# ascending=False → highest revenue gets rank 1
# method='dense' → no gaps (like SQL DENSE_RANK)

seasonal['category_rank'] = (
    seasonal
    .groupby('season')['seasonal_revenue']
    .rank(method='dense', ascending=False)
    .astype(int)
)

# Custom season sort order (not alphabetical)
season_order = {
    "Spring": 1, "Summer": 2,
    "Autumn": 3, "Winter": 4
}
seasonal['season_sort'] = seasonal['season'].map(season_order)

seasonal = (
    seasonal
    .sort_values(['season_sort', 'category_rank'])
    .drop(columns=['season_sort'])
    .reset_index(drop=True)
)
# season | category        | seasonal_revenue | category_rank
# Spring | Technology       | 286617.08        | 1
# Spring | Office Supplies  | 232440.98        | 2
# Spring | Furniture        | 220116.80        | 3
# Summer | Technology       | 229387.52        | 1

rank() methods recap

method=SQL equivalentGaps?
'min'RANK()Yes (ties cause gap)
'dense'DENSE_RANK()No gaps
'first'ROW_NUMBER()Unique per row

Custom sort — the .map() trick

Alphabetical: Autumn → Spring → Summer → Winter.
We want: Spring → Summer → Autumn → Winter.
Solution: map season names to sort numbers (1–4), sort by that column, then drop it.

💡 Think in SQL first — how would you rank categories within each season by revenue?

SQL (window function):
SELECT season, category, SUM(revenue) AS seasonal_revenue,
  DENSE_RANK() OVER (
    PARTITION BY season
    ORDER BY SUM(revenue) DESC
  ) AS category_rank
FROM melted GROUP BY season, category;

Python: groupby('season')['seasonal_revenue'].rank(method='dense', ascending=False)
PARTITION BY season = groupby('season'); DENSE_RANK() = method='dense'.

Complete Solution + Concept Summary

import pandas as pd

# Load
orders       = pd.read_csv("exorders.csv", parse_dates=["order_purchase_date"])
transactions = pd.read_csv("extransactions.csv")
products     = pd.read_csv("exproducts.csv")

# Join (note: case-sensitive column names require left_on/right_on)
orders_txn = orders.merge(transactions, left_on='order_id', right_on='Order_ID', how='left')
df         = orders_txn.merge(products, left_on='Product_ID', right_on='product_id', how='left')

# Date features
df["month_num"]  = df["order_purchase_date"].dt.month
df["month_name"] = df["order_purchase_date"].dt.month_name()
season_map = {12:"Winter",1:"Winter",2:"Winter",3:"Spring",4:"Spring",5:"Spring",6:"Summer",7:"Summer",8:"Summer",9:"Autumn",10:"Autumn",11:"Autumn"}
df["season"] = df["month_num"].map(season_map)

# Aggregate monthly (column is 'Sales_Amount' — capital S and A)
base = (df.groupby(['month_num','month_name','season','category'],as_index=False)
            .agg(revenue=('Sales_Amount','sum'))
            .sort_values('month_num').reset_index(drop=True))

# Pivot: long → wide
pivot_df = (base.pivot_table(index=['month_num','month_name','season'],columns='category',values='revenue',aggfunc='sum',fill_value=0)
              .reset_index().sort_values('month_num').reset_index(drop=True))
pivot_df.columns.name = None

# Melt: wide → long
melted_df = (pivot_df.melt(id_vars=['month_num','month_name','season'],var_name='category',value_name='revenue')
               .sort_values(['month_num','category']).reset_index(drop=True))

# Seasonal totals + rank
seasonal = melted_df.groupby(['season','category'],as_index=False).agg(seasonal_revenue=('revenue','sum'))
seasonal['category_rank'] = seasonal.groupby('season')['seasonal_revenue'].rank(method='dense',ascending=False).astype(int)
season_order = {"Spring":1,"Summer":2,"Autumn":3,"Winter":4}
seasonal['season_sort'] = seasonal['season'].map(season_order)
seasonal = (seasonal.sort_values(['season_sort','category_rank']).drop(columns=['season_sort']).reset_index(drop=True))
