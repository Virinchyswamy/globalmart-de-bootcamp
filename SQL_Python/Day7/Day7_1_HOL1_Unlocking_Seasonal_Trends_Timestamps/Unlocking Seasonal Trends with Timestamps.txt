**Solution:** 
**Build the analytical base bottom-up** - merge first to get a flat table, extract time features next, then aggregate last.

```python
import pandas as pd

#  Load required tables ──────────────────────────────────────────────────────
orders = pd.read_csv(
    "https://cdn.enqurious.com/documents/0518fd79-992c-420c-8580-a7acf31172b6_exorders.csv",
    parse_dates=[
        "order_purchase_date", "order_approved_at",
        "order_dispatched_date", "order_delivered_date",
        "order_estimated_delivery_date"
    ]
)
transactions = pd.read_csv("https://cdn.enqurious.com/documents/c1b6bff1-a6af-431b-bcc8-9618990bc5df_extransactions.csv")
products     = pd.read_csv("https://cdn.enqurious.com/documents/604aa913-c904-4e6c-9d26-fdd443c52482_exproducts.csv")

#  Step 1: Merge Orders → Transactions ──────────────────────────────────────
# NOTE: transactions table may use Order_ID / Product_ID casing
orders_txn = orders.merge(
    transactions,
    left_on="order_id",
    right_on="Order_ID",
    how="left"
)

# Step 2: Merge → Products ──────────────────────────────────────────────────
df = orders_txn.merge(
    products,
    left_on="Product_ID",
    right_on="product_id",
    how="left"
)

# Step 3: Extract Time Components ──────────────────────────────────────────
df["month_num"]  = df["order_purchase_date"].dt.month
df["month_name"] = df["order_purchase_date"].dt.month_name()

season_map = {
    12: "Winter", 1: "Winter",  2: "Winter",
     3: "Spring", 4: "Spring",  5: "Spring",
     6: "Summer", 7: "Summer",  8: "Summer",
     9: "Autumn", 10: "Autumn", 11: "Autumn"
}
df["season"] = df["month_num"].map(season_map)

# Step 4: Aggregate Revenue by Month × Season × Category ───────────────────
base = (
    df
    .groupby(["month_num", "month_name", "season", "category"], as_index=False)
    .agg(revenue=("Sales_Amount", "sum"))
    .sort_values("month_num")
    .reset_index(drop=True)
)

print(base.head(12).to_string(index=False))
```

- **`parse_dates` on load**: Ensures `order_purchase_date` is a datetime object so the `.dt` accessor is immediately available without manual conversion.
- **Left joins throughout**: Preserves all orders even if some have no matching transactions or product records. Inner joins would silently drop unmatched rows.
- **`season_map` dict + `.map()`**: Cleaner and faster than chained `np.where()` or `apply(lambda)`. December is included in "Winter" alongside January and February.
- **`as_index=False` in `groupby()`**: Keeps all grouping columns as regular DataFrame columns-avoiding the MultiIndex that would break subsequent `pivot_table()` and `melt()` calls.
- **Aggregate after merge, not before**: Computing revenue before joining products would prevent grouping by category.

**Solution:** 
**`pivot_table()` spreads categories across columns** — transforming a tall comparison table into a wide, scannable report.

```python
# ── Task 2: Pivot the base table — categories become columns ──────────────────
pivot_df = (
    base
    .pivot_table(
        index      = ["month_num", "month_name", "season"],  # one row per month
        columns    = "category",                              # one column per category
        values     = "revenue",                               # cell values: total revenue
        aggfunc    = "sum",                                   # aggregate if duplicates exist
        fill_value = 0                                        # replace NaN with 0
    )
    .reset_index()          # promote month_num, month_name, season back to columns
    .sort_values("month_num")
    .reset_index(drop=True)
)

# Remove the "category" axis label from the column header row
pivot_df.columns.name = None

print(pivot_df)
```

- **`index=['month_num', 'month_name', 'season']`**: All three columns uniquely identify each row — one per calendar month. Including `month_num` is essential for correct chronological sorting.
- **`columns='category'`**: Each unique value in the `category` column (Furniture, Office Supplies, Technology) becomes a new column in the output.
- **`aggfunc='sum'`**: Although the `base` table already has one row per month-category pair, `aggfunc='sum'` is good practice — it handles any residual duplicates without raising an error (unlike `pivot()`, which fails on duplicates).
- **`fill_value=0`**: Months where a category had no sales would otherwise contain `NaN`, which breaks downstream arithmetic and ranking operations. Zero is the correct substitute — it means no revenue, not missing data.
- **`pivot_df.columns.name = None`**: After pivoting, pandas attaches the string "category" as the column axis name, which prints confusingly as an extra header row. Setting it to `None` removes this label without altering any data.

>[!NOTE]
> Forgetting `reset_index()` after `pivot_table()` leaves `month_num`, `month_name`, and `season` as the DataFrame index rather than regular columns. This makes them invisible to `melt()` in the next step and will break the `id_vars` specification.

**Solution:** 
**`melt()` is the exact inverse of `pivot_table()`** — it collapses column headers back into row values, producing the long format that charting libraries expect.

```python
# ── Task 3: Melt the pivot table back to long format ──────────────────────────
melted_df = (
    pivot_df
    .melt(
        id_vars    = ["month_num", "month_name", "season"],  # stay as row identifiers
        var_name   = "category",   # column headers → values in this new column
        value_name = "revenue"     # cell values → values in this new column
    )
    .sort_values(["month_num", "category"])
    .reset_index(drop=True)
)

print(melted_df.head(15))
```

- **`id_vars=['month_num', 'month_name', 'season']`**: These three columns remain fixed as row identifiers. Each will repeat once per category, preserving the month-season context for every revenue value.
- **`var_name='category'`**: The column headers of `pivot_df` (Furniture, Office Supplies, Technology) become row values in a new column named `category`.
- **`value_name='revenue'`**: The numeric values from each pivot cell become row values in a new column named `revenue`. Without this parameter, pandas defaults to the ambiguous name `value`.
- **`value_vars` omitted**: Pandas automatically identifies all columns not in `id_vars` as value columns. This is safe here because `pivot_df` contains only the three identifier columns plus the category columns.
- **`sort_values(['month_num', 'category'])`**: Groups all categories for each month together — producing clean, predictable output for charting tools that iterate row by row.

>[!NOTE]
> If `month_num` is accidentally omitted from `id_vars`, it gets treated as a value column and its integer values (1–12) are mixed into the `revenue` column alongside float revenue figures. Always list every identifier column explicitly in `id_vars`.

**Solution:** 
**Group, then rank within groups** — `groupby().rank()` applies a ranking function independently within each partition, which is exactly what within-season ranking requires.

```python
# ── Season-level revenue with within-season category rank ─────────────────────

# Step 1: Aggregate revenue by season and category
seasonal = (
    melted_df
    .groupby(["season", "category"], as_index=False)
    .agg(seasonal_revenue=("revenue", "sum"))
)

# Step 2: Rank categories within each season (rank 1 = highest revenue)
seasonal["category_rank"] = (
    seasonal
    .groupby("season")["seasonal_revenue"]
    .rank(method="dense", ascending=False)
    .astype(int)
)

# Step 3: Sort by season (custom calendar order) and rank
season_order = {"Spring": 1, "Summer": 2, "Autumn": 3, "Winter": 4}
seasonal["season_sort"] = seasonal["season"].map(season_order)

seasonal = (
    seasonal
    .sort_values(["season_sort", "category_rank"])
    .drop(columns=["season_sort"])
    .reset_index(drop=True)
)

print(seasonal)
```

- **`groupby().rank(ascending=False)`**: Ranks within each season independently — rank 1 is the highest-revenue category in that season. Without `groupby()`, rank would be computed globally across all seasons.
- **`method='dense'`**: Assigns the same rank to tied values and does not skip the next rank. For example, two categories tied at rank 2 both receive rank 2, and the next category receives rank 3 (not rank 4).
- **`season_sort` column**: Python sorts strings alphabetically by default, which would give Autumn → Spring → Summer → Winter rather than calendar order. A numeric mapping corrects this without altering the display values.
- **`drop(columns=['season_sort'])`**: The helper sort column is removed from the final output since it serves no business purpose.

##### Input 7
**Type:** Choice

**Question:** A colleague's `pivot_table()` call raises `ValueError: Index contains duplicate entries, cannot reshape`. Which function should they use instead, and why?

**Options:** 
- Switch to `pivot_table()` with `aggfunc='sum'` - it handles duplicate index-column combinations by aggregating them

- Switch to `pivot()` with `aggfunc='sum'` to handle duplicates

- Add `drop_duplicates()` before calling `pivot()` to eliminate all duplicates first

- Use `groupby().unstack()` with `fill_value=0` as a replacement for pivot operations

**Correct Options:** 
- Switch to `pivot_table()` with `aggfunc='sum'` - it handles duplicate index-column combinations by aggregating them

**Solution:** 
**`pivot()` requires a unique (index, column) combination for every row** - `pivot_table()` was designed specifically to handle duplicates through aggregation.

- **`pivot_table()` with `aggfunc='sum'` ✅** - When multiple rows map to the same (month, category) cell, `pivot_table()` applies the aggregation function (here `sum`) to combine them. This is the correct, pandas-recommended approach for any pivot involving aggregation.
- **`pivot()` with `aggfunc='sum'` ❌** - `pivot()` does not accept an `aggfunc` parameter at all. It is a pure reshape operation that requires every (index, column) pair to be unique. Adding `aggfunc='sum'` would raise a `TypeError`.
- **`drop_duplicates()` before `pivot()` ❌** - `drop_duplicates()` removes rows based on exact row equality, not on index-column uniqueness. It would silently discard valid revenue rows that happen to share the same month and category, producing incorrect totals.
- **`groupby().unstack()` ❌** -  While `unstack()` can produce a wide-format result, it requires the grouping keys to already be set as a MultiIndex and does not support `fill_value` natively. It is more complex and error-prone for this use case than `pivot_table()`.

**Type:** Choice

**Question:** Which of the following mistakes will cause the `.dt` accessor to raise `AttributeError: Can only use .dt accessor with datetimelike values`? (Select 2)

**Options:** 
- Loading `ex_orders.csv` without `parse_dates=["order_purchase_date"]`, leaving the column as a plain string

- Using `.dt.month_name()` instead of `.dt.month` to extract the integer month number

- Manually casting the date column after loading with `pd.to_datetime(df['order_purchase_date'])`

- Running `df['order_purchase_date'].astype(str)` before calling `.dt.month`, converting the datetime back to a string

**Correct Options:** 
- Loading `ex_orders.csv` without `parse_dates=["order_purchase_date"]`, leaving the column as a plain string

- Running `df['order_purchase_date'].astype(str)` before calling `.dt.month`, converting the datetime back to a string

**Solution:** 
**The `.dt` accessor only works on columns with a datetime dtype** - any operation that leaves or converts the column to a string type will cause it to fail.

- **Loading without `parse_dates` ✅** - Without `parse_dates=["order_purchase_date"]`, pandas reads the date column as `object` (string). Calling `.dt.month` on a string column immediately raises `AttributeError`. This is the most common cause of this error in practice.
- **`.astype(str)` before `.dt` ✅** - Explicitly converting a datetime column back to a string with `.astype(str)` removes its datetime dtype. Calling `.dt.month` on the resulting string column raises the same `AttributeError`. This is less common but appears when developers accidentally overwrite the parsed column.
- **`.dt.month_name()` for integer extraction ❌** - This is a usage error, not a dtype error. `.dt.month_name()` returns full month names like "January"; to get the integer you need `.dt.month`. However, this does not raise `AttributeError` - it simply returns the wrong type of value. The accessor itself works fine.
- **`pd.to_datetime()` manual cast ❌** - Manually casting with `pd.to_datetime(df['order_purchase_date'])` correctly converts the string column to datetime dtype. After this, `.dt.month` works without error. This is a valid workaround when `parse_dates` was not used at load time.
