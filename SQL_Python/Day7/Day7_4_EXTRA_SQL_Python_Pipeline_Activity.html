Section 1 — Imagine the Pipeline

Question 1 of 10
You have two tables — transactions and products. You want to compute a discounted price per product category. What must happen first in the pipeline, before any calculation?
AGROUP BY category to aggregate sales
BJOIN transactions and products on product_id
CApply CASE WHEN to classify price tiers
DFilter rows where discount > 0
✓ Correct. You can't compute discounted price without the product's base price — which lives in products. JOIN first, calculate after. The pipeline always starts: Load → Join → Compute → Classify → Aggregate.
✗ You need columns from both tables before any calculation is possible. JOIN is always the first step when data lives in separate tables.
Question 2 of 10
The discount column stores 0.45, not 45. A product has sales_amt = 500 and qty = 2. Which formula gives the correct discounted unit price?
A(500 / 2) * (1 - 0.45 / 100) — divide discount by 100 first
B(500 / 2) * (1 - 0.45) — discount is already a decimal
C(500 / 2) + 0.45 — add the discount fraction to price
D500 * 0.45 — multiply total sales by discount
✓ Correct. 0.45 already means 45% — so price × (1 − 0.45) = price × 0.55. Dividing by 100 would treat it as 0.0045%, giving a nearly unchanged price. Always check the column's scale before writing the formula.
✗ The column stores 0.45, meaning 45% is already encoded. The formula is price × (1 − discount) directly — no division by 100 needed.
Question 3 of 10
You have monthly sales data for 3 categories across 12 months — one row per category per month (long format). You want a table with months as rows and categories as columns, total sales in each cell. Which operation creates this shape?
A.groupby('month').agg(total=('sales','sum')) — aggregates but stays long
B.melt(id_vars='month') — this goes wide → long (unpivot)
C.pivot_table(index='month', columns='category', values='sales', aggfunc='sum')
D.sort_values(['month','category']) — just reorders rows
✓ Correct. .pivot_table() rotates the data — index stays as rows, columns spreads unique values into column headers, aggfunc handles duplicates. The inverse (back to long format) is .melt().
✗ .melt() goes wide → long. .groupby() aggregates but keeps long format. To turn category values into column headers you need .pivot_table(columns='category').

Section 2 — Python → SQL

Question 4 of 10
Which SQL statement is equivalent to this Python?
df.groupby('category').agg(
    avg_orig = ('price',            'mean'),
    avg_disc = ('discounted_price', 'mean')
).reset_index()
A SELECT category, AVG(price) AS avg_orig, AVG(discounted_price) AS avg_disc FROM t GROUP BY category
B SELECT AVG(price), AVG(discounted_price) FROM t WHERE category IS NOT NULL
C SELECT category, SUM(price), SUM(discounted_price) FROM t GROUP BY category
D SELECT category, price, discounted_price FROM t ORDER BY category
✓ Correct. groupby('category') = GROUP BY category. Named aggregation avg_orig=('price','mean') = AVG(price) AS avg_orig. .reset_index() has no SQL equivalent — it just moves the index back to a regular column.
✗ The function name matters — 'mean' maps to AVG(), not SUM(). Also, groupby requires GROUP BY in SQL; WHERE filters rows, not groups.
Question 5 of 10
Which SQL expression produces the same result as this Python?
df['purchase_label'] = (
    df['order_purchase_date'].dt.strftime('%A, %d %B %Y')
)
# Output example: "Monday, 14 January 2019"
ACAST(order_purchase_date AS VARCHAR)
BEXTRACT(DAY FROM order_purchase_date)
CTO_CHAR(order_purchase_date, 'Day, DD Month YYYY')
DDATE_FORMAT(order_purchase_date, '%a %d %b %Y') — MySQL syntax
✓ Correct. Python strftime('%A, %d %B %Y') = SQL TO_CHAR(date, 'Day, DD Month YYYY'). Same two-part idea: input date + output format pattern. DATE_FORMAT is MySQL-only — not standard SQL.
✗ strftime formats a date as a readable string. Its SQL equivalent is TO_CHAR(date, 'format'). EXTRACT returns a number, CAST gives a default string representation — neither lets you control the format.
Question 6 of 10
Which SQL clause does this Python list comprehension translate to?
['Premium'    if p > 200
 else 'Mid-range' if p > 100
 else 'Budget'
 for p in df['discounted_price']]
AWHERE discounted_price > 200 OR discounted_price > 100
B CASE WHEN discounted_price > 200 THEN 'Premium' WHEN discounted_price > 100 THEN 'Mid-range' ELSE 'Budget' END
CHAVING discounted_price IN ('Premium', 'Mid-range', 'Budget')
DGROUP BY discounted_price ORDER BY discounted_price DESC
✓ Correct. The nested if/else chain maps condition-by-condition to CASE WHEN … THEN … WHEN … THEN … ELSE … END. Order matters in both — the first matching condition wins, so put the most specific check first.
✗ This is row-level classification — assigning a label to each row. WHERE filters rows, HAVING filters groups, GROUP BY aggregates. The correct tool is CASE WHEN … THEN … END.
Question 7 of 10
Which SQL statement matches this pandas merge?
result = transactions.merge(
    products[['product_id', 'category', 'sub_category']],
    left_on  = 'Product_ID',
    right_on = 'product_id',
    how      = 'left'
)
ASELECT * FROM transactions CROSS JOIN products
BSELECT * FROM transactions t INNER JOIN products p ON t.Product_ID = p.product_id
C SELECT t.*, p.category, p.sub_category FROM transactions t LEFT JOIN products p ON t.Product_ID = p.product_id
DSELECT * FROM products p RIGHT JOIN transactions t ON t.Product_ID = p.product_id
✓ Correct. how='left' = LEFT JOIN — keeps ALL rows from transactions even with no match in products. Selecting only ['product_id','category','sub_category'] from products maps to SELECT t.*, p.category, p.sub_category. INNER JOIN would silently drop unmatched transactions.
✗ how='left' means keep every row from the left table (transactions) — even if products has no matching row. That's LEFT JOIN. INNER JOIN drops unmatched rows; CROSS JOIN pairs every row with every other row.

Section 3 — SQL → Python

Question 8 of 10
Which Python line is equivalent to this SQL window function?
SELECT vendor_id,
  DENSE_RANK() OVER (ORDER BY avg_delay ASC) AS delay_rank
FROM vendor_summary;
Adf['delay_rank'] = df['avg_delay'].rank(method='dense').astype(int)
Bdf['delay_rank'] = df['avg_delay'].rank(method='min').astype(int)
Cdf = df.sort_values('avg_delay').reset_index(drop=True)
Ddf['delay_rank'] = df['avg_delay'].rank(method='dense', ascending=False).astype(int)
✓ Correct. DENSE_RANK() OVER (ORDER BY col ASC) = .rank(method='dense') — pandas defaults to ascending=True, so rank 1 goes to the smallest value, matching ASC. method='min' is regular RANK (leaves gaps on ties). ascending=False would give rank 1 to the largest delay.
✗ DENSE_RANK() = method='dense' (no gaps on ties). ORDER BY ASC = ascending=True (the pandas default). sort_values just reorders rows — it doesn't create a rank column.
Question 9 of 10
Which Python expression matches this SQL?
SELECT TO_CHAR(joining_date, 'Mon-YYYY') AS joining_cohort
FROM customers;
-- Output example: "Jan-2021"
Adf['joining_cohort'] = df['joining_date'].dt.strftime('%B-%Y') — gives "January-2021"
Bdf['joining_cohort'] = df['joining_date'].dt.strftime('%b-%Y') — gives "Jan-2021"
Cdf['joining_cohort'] = df['joining_date'].dt.month — gives 1, 2, 3...
Ddf['joining_cohort'] = df['joining_date'].dt.strftime('%m-%Y') — gives "01-2021"
✓ Correct. SQL 'Mon' = abbreviated month (Jan, Feb…) → Python '%b'. Full month name (January) = SQL 'Month' → Python '%B'. Numeric month = SQL 'MM' → Python '%m'.
✗ SQL 'Mon' gives abbreviated month (Jan, Feb…). In Python that's '%b'. '%B' gives the full name (January), '%m' gives a number (01), and .dt.month returns an integer — none of these match the "Jan-2021" output.
Question 10 of 10
This SQL uses SUM(CASE WHEN …) — the classic SQL pivot trick — to spread months into columns. Which pandas method is the direct equivalent? 
SELECT category,
  SUM(CASE WHEN month = 1 THEN sales_amt ELSE 0 END) AS Jan,
  SUM(CASE WHEN month = 2 THEN sales_amt ELSE 0 END) AS Feb,
  -- ... one CASE per month
FROM monthly_sales GROUP BY category;
Adf.groupby(['category','month']).agg(total=('sales_amt','sum')) — stays long
Bdf.melt(id_vars='category', value_vars=['Jan','Feb',...]) — this unpivots (opposite direction)
Cdf.pivot_table(index='category', columns='month', values='sales_amt', aggfunc='sum')
Ddf.sort_values(['category','month']) — just reorders, no reshape
✓ Correct. SUM(CASE WHEN month=N THEN …) is the SQL way to pivot — writing one conditional per column manually. .pivot_table(columns='month') does the same automatically for every unique month value. Much cleaner.
✗ The SQL is pivoting — rotating month values (1, 2, …) into column headers. .pivot_table(columns='month', aggfunc='sum') does this automatically. .melt() goes the opposite direction (wide → long).
