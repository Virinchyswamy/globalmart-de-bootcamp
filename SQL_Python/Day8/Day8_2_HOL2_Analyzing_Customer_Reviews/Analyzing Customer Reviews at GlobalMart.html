Python Concept

What Even Is Regex?

Before any code — the one idea every single task in this module is built on.

Normal searching (what you already know)

  • You search for an exact piece of text — "find the word refund"
  • Works great when you know exactly what you're looking for, letter for letter
  • Falls apart when the thing you want has many possible forms — like a phone number, which can be typed a dozen different ways

Pattern searching (regex)

  • You describe the shape of what you want, not the exact text
  • "Find something that looks like 3 digits, a dash, 4 digits" matches 555-1234, 800-9999, or any other number with that same shape
  • "Regex" is short for "regular expression" — think of it as a tiny language whose only job is describing shapes of text
The one-sentence version: Ctrl+F is normal searching. Regex is Ctrl+F for shapes, not exact words. Every task in this module — cleaning text, flagging issues, pulling out phone numbers, counting words — is really just "describe the shape, then let Python find it."
Python Concept

Raw Strings — the r in r"..."

The one thing every single pattern in this module starts with — and why it has to be there.

The problem

  • Backslash \ already means something special to Python, even before regex gets involved
  • \n = new line, \t = tab — Python quietly "eats" the backslash and turns it into that special character
  • Regex also wants to use backslash for its own meanings: \d = a digit, \b = word edge, \s = space
  • If Python eats the backslash first, regex never even sees it — your pattern breaks silently, with no error message to warn you

The fix: put r right before the quotes

# WITHOUT r -- Python may mangle \b before regex ever sees it
bad_pattern = '\bhello\b'      # risky, don't do this

# WITH r -- Python leaves every backslash untouched
good_pattern = r'\bhello\b'    # correct, this is what regex expects

The two characters \ and b now travel untouched into regex, which reads \b as "word boundary" — exactly what you meant.

Rule of thumb: if a string contains regex, put r in front of it — no exceptions. You'll see r'...' at the start of every single pattern in this module.
SQL Mental Model

SQL vs Python for Text Analysis

SQL can filter text — but Python's re module gives you true pattern matching power.

What SQL can do

-- Basic keyword filter (no word boundaries)
SELECT review_id, review_text
FROM   reviews
WHERE  review_text LIKE '%broken%'
   OR review_text LIKE '%defective%';
-- ⚠ matches "unbroken", "defectively" too
--   no word-boundary control

-- Clean text: SQL has no regex replace in most DBs
-- PostgreSQL ONLY: regexp_replace()
SELECT LOWER(REGEXP_REPLACE(review_text,
         '[^\\w\\s]', '', 'g')) AS cleaned
FROM   reviews;

What Python regex adds

# ✅ Word boundaries — exact word match only
pattern = r'\b(broken|defective|damaged)\b'
df['mentions_issue'] = df['cleaned'].str.contains(
    pattern, flags=re.IGNORECASE
)
# \b = boundary: "broken" ✓, "unbroken" ✗

# ✅ Extract phone numbers — impossible in plain SQL
phone = r'\b(?:\+?\d{1,3})?[\-.\s]?\(?\d{3}\)?'
      r'[\-.\s]?\d{3}[\-.\s]?\d{4}\b'
df['contact'] = df['cleaned'].str.extract(f'({phone})')

# ✅ Count word occurrences per row — no SQL equivalent
def count_keyword(text, keyword):
    return len(re.findall(rf'\b{keyword}\b', text,
                            flags=re.IGNORECASE))
Key insight: SQL's LIKE '%word%' is a substring match — it can't distinguish whole words. Python's \b (word boundary) anchors to word edges, so \bbroken\b never matches "unbroken".

Python Concept

re.sub() — Find and Replace, But Smarter

The exact idea behind Task 1's clean_text() function — nothing more than this.

The 3 ingredients of re.sub(pattern, replacement, text)

1

pattern — the shape to look for, e.g. r'[^\w\s]' = "anything that isn't a letter, digit, or space" = punctuation

2

replacement — what to put in its place, often just '' (nothing, i.e. delete it)

3

text — the actual string to search through

Think of it like Word's Find & Replace

  • Find & Replace: type an exact word to find, type what to replace it with
  • re.sub(): same idea, except "what to find" is a pattern instead of exact text
  • It replaces every match, not just the first one — that's the "sub" in "substitute all occurrences"
# "find any punctuation, replace with nothing" = delete all punctuation
re.sub(r'[^\w\s]', '', "Great price!!")
# -> "Great price"
Put it together: clean_text() is just two of these calls back to back — one re.sub() to delete punctuation, one re.sub() to collapse extra spaces into one. That's the whole function.
Task 1

Clean Customer Review Text

Define clean_text() — two regex substitutions that remove noise before any analysis.

SQL equivalent

-- PostgreSQL: two regex passes + LOWER + TRIM
SELECT
  TRIM(LOWER(
    REGEXP_REPLACE(
      REGEXP_REPLACE(review_text,
        '[^\w\s]', '', 'g'),   -- pass 1: remove punct
      '\s+', ' ', 'g')           -- pass 2: collapse spaces
  )) AS cleaned_text
FROM reviews;
-- Most SQL dialects (MySQL, BigQuery, Spark SQL)
-- require UDFs for this — Python is cleaner here

Python: re.sub(pattern, replacement, string)

import re

def clean_text(text):
    # re.sub(pattern, repl, string) replaces ALL matches
    # [^\w\s] = any char that is NOT word-char or space
    #   → removes ! . , " ' ? etc.
    text = re.sub(r'[^\w\s]', '', text)

    # \s+ = one or more whitespace chars (space, tab, newline)
    # replace with single space → collapses "  " to " "
    text = re.sub(r'\s+', ' ', text)

    # .strip() removes leading/trailing spaces
    # .lower() converts to lowercase for uniform matching
    return text.strip().lower()

# .apply() calls clean_text once per row in review_text
df['cleaned_reviews'] = df['review_text'].apply(clean_text)
re.sub(pattern, repl, string) — replaces every match of pattern with repl in string. Two passes: first remove punctuation, then collapse extra spaces. Order matters — do punctuation first.
Python Concept

Word Boundaries \b and "Either/Or" Patterns

The two ideas Task 2 combines to catch whole-word matches only.

\b — invisible fences around a word

  • \b matches a position, not a character — it doesn't "use up" any letters, it just marks a spot
  • Think of it as an invisible fence marking where a word starts or ends
  • r'\bbroken\b' means "the word broken, with fences on both sides" — so it will not match inside "unbroken" (there's no fence between "un" and "broken")
  • Without \b, r'broken' would happily match the middle of "unbroken" too — a false positive

(a|b|c) — pick any one of these

  • The pipe symbol | means "or"
  • (broken|defective|damaged) means "match broken, OR defective, OR damaged — any one of the three"
  • Combine both: r'\b(broken|defective|damaged)\b' = "any one of these three words, and only as a whole word"
pattern = r'\b(broken|defective|damaged)\b'
# matches: "the item was broken"      -> YES
# matches: "totally unbroken product" -> NO (no fence before "broken")
Why this matters: this is exactly why SQL's LIKE '%broken%' gets tricked by "unbroken" but Python's \b doesn't — LIKE has no concept of word edges, it's just a raw substring check.
Task 2

Extract Mentions of Product Issues

Use str.contains() with alternation (a|b|c) and word boundaries to detect exact words.

SQL equivalent (limited)

-- SQL LIKE: matches substrings, not whole words
SELECT review_id,
  (CASE
    WHEN review_text ILIKE '%broken%'
      OR review_text ILIKE '%defective%'
      OR review_text ILIKE '%damaged%'
    THEN TRUE ELSE FALSE
  END) AS mentions_issue
FROM reviews;
-- ⚠ 'unbroken' → TRUE (false positive)
-- ⚠ Python \b boundary catches this correctly

Python: str.contains(pattern, na=False)

# Alternation: (a|b|c) matches broken OR defective OR damaged
# \b ... \b = word boundaries on both sides
# → "unbroken" ✗  "broken" ✓  "Broken!" ✓ (already cleaned)
issue_pattern = r'\b(broken|defective|damaged)\b'

# str.contains() returns True/False per row
# flags=re.IGNORECASE makes Broken == broken
# na=False: if cell is NaN, return False (not NaN)
df['mentions_issue'] = (
    df['cleaned_reviews']
    .str.contains(issue_pattern,
                  flags=re.IGNORECASE,
                  na=False)
)

# Check how many reviews mention product issues
df['mentions_issue'].value_counts()
# False: 1591   True: 6
Warning from notebook: pandas warns that a pattern with groups (broken|...) looks like it should use str.extract(). It still works for str.contains() — the warning is just informational. Add na=False to avoid NaN propagation.
Python Concept

"Yes/No" vs "Show Me The Value"

Why Task 3 needs a different tool than Task 2 — and what f"..." adds to the mix.

str.contains() vs str.extract()

  • str.contains(pattern) → answers True or False: "does this pattern appear somewhere in the text?"
  • str.extract(pattern) → answers with the actual matching text: "show me exactly what matched"
  • Task 2 only needed a flag (mentions_issue: True/False) → contains() was enough
  • Task 3 needs the actual phone number pulled out → extract() is required

Capture groups — the ( ) that says "grab this part"

  • Wrapping part of a pattern in parentheses ( ) marks it as a "capture group" — the piece you want handed back to you
  • str.extract() requires exactly ONE capture group — wrap your whole pattern in one pair of ( )
  • f"..." (an f-string) lets you drop a variable's value into a string — it "fills in the blank"
phone_pattern = r'\d{3}-\d{4}'          # the shape, defined once
df['x'] = df['col'].str.extract(f'({phone_pattern})')
# f"(...)" wraps phone_pattern in parentheses and inserts it
Rule of thumb: need a True/False flag? Use contains(). Need the actual matched text back? Wrap it in ( ) and use extract().
Task 3

Extract Contact Numbers from Reviews

str.extract() returns the first regex capture group per row — perfect for pulling structured data from free text.

Phone pattern breakdown

phone_pattern = (
  r'\b'             # word boundary — start of number
  r'(?:\+?\d{1,3})?' # optional country code: +91, 1, etc.
  r'[.\s-]?'        # optional separator: space, dot, dash
  r'\(?\d{3}\)?'    # area code — optional parens (800)
  r'[.\s-]?'        # optional separator
  r'\d{3}'          # exchange: 3 digits
  r'[.\s-]?'        # optional separator
  r'\d{4}'          # subscriber: 4 digits
  r'\b'             # word boundary — end of number
)
# Matches: 800-555-1234  (800) 555.1234  +1 800 555 1234

Python: str.extract(pattern, expand=False)

# str.extract() needs exactly ONE capture group (...)
# wrap the whole pattern in f"({phone_pattern})"
# expand=False → returns a Series (not a DataFrame)
df['contact_numbers'] = (
    df['cleaned_reviews']
    .str.extract(f'({phone_pattern})', expand=False)
)

# Rows without a phone number → NaN (not empty string)
found = df['contact_numbers'].notna().sum()
print(f"Phone numbers found: {found}")  # → 2

# See which reviews had numbers
df[df['contact_numbers'].notna()][[
    'cleaned_reviews', 'contact_numbers'
]]
str.contains vs str.extract: str.contains() → True/False (does it appear?)  |  str.extract() → the matched text itself (what is it?). Use extract when you need the actual value.
Python Concept

re.findall() — Get Every Match, Not Just the First

Task 4 combines this with one more string trick: rf"..." — raw AND f-string at once.

findall() returns a LIST

  • re.findall(pattern, text) doesn't just say "yes it matched" — it hands back a list of every single match it found
  • "excellent product, excellent service" searched for "excellent" → ['excellent', 'excellent'] (a list with 2 items)
  • len() of a list = how many items are inside it
  • So len(re.findall(pattern, text)) = "how many times did this pattern appear?" — that's the entire idea behind count_keyword()

rf'...' — raw string + f-string, combined

  • You already met r"..." (keep backslashes literal) and f"..." (insert a variable)
  • rf"..." does both at once — needed when your pattern itself contains a variable
  • rf'\b{keyword}\b': the \b's stay as real regex word-boundaries (thanks to r), and {keyword} gets swapped for whatever word is passed in (thanks to f)
keyword = "refund"
pattern = rf'\b{keyword}\b'   # becomes: \brefund\b
len(re.findall(pattern, text, flags=re.IGNORECASE))
Rule of thumb: if you ever need both "don't touch my backslashes" AND "insert a variable" in the same string, that's exactly when you reach for rf"...".
Task 4

Count Keywords in Reviews

re.findall() returns a list of all matches — len() of that list = count. The raw f-string rf"..." lets you inject variables into patterns.

SQL equivalent (aggregate only)

-- SQL can count rows mentioning a word
-- but NOT occurrences per row
SELECT
  COUNT(*) FILTER (WHERE text ILIKE '%excellent%')
    AS rows_with_excellent
FROM reviews;
-- ✗ Cannot count: "excellent product, excellent price"
--   as 2 — SQL sees it as 1 matching row
-- ✅ Python re.findall() counts ALL occurrences

Python: raw f-string rf"\b{keyword}\b"

# re.findall(pattern, string) → list of all matches
# len() of that list = how many times word appears

def count_keyword(text, keyword):
    # rf"..." = raw f-string: raw (\ not escaped) +
    #          formatted ({keyword} substituted in)
    # \b{keyword}\b ensures whole-word match only
    return len(re.findall(
        rf'\b{keyword}\b', text, flags=re.IGNORECASE
    ))

# Count 3 keywords → 3 new columns
keywords = ['excellent', 'poor', 'refund']
for kw in keywords:
    df[f'count_{kw}'] = df['cleaned_reviews'].apply(
        lambda x: count_keyword(x, kw)
    )
Raw f-string rf"...": r = don't interpret backslashes (so \b stays as \b, not backspace). f = substitute {keyword} at runtime. Combine both: rf'\b{keyword}\b' — you get a proper regex with a variable word.
Python Concept

Counting Words the Right Way

Why Task 5 uses \b\w+\b instead of just splitting on spaces — plus a neat Python shortcut.

\w+ — one or more word characters, glued together

  • \w matches a single letter, digit, or underscore
  • \w+ means "one or more of those in a row" — i.e. a whole word token
  • re.findall(r'\b\w+\b', text) returns a list of every real word in the text
  • Compare to text.split(' '): two spaces in a row create an empty '' entry that isn't a real word — it quietly inflates your count. \w+ never has this problem.

Chained comparisons — Python reads like math class

  • Most languages make you write two separate checks joined by "and": n >= 10 and n <= 100
  • Python lets you chain them into one readable line: 10 <= n <= 100
  • Reads exactly like a number line: "is n somewhere between 10 and 100?"
word_count = len(re.findall(r'\b\w+\b', text))
is_valid = 10 <= word_count <= 100   # one line, very readable
Put it together: validate_review_length() is really just: count the real words, then ask "is that number in a sensible range?" — two ideas you've now seen built from scratch.
Task 5

Validate Review Length

Count actual words (not characters) using re.findall(r"\b\w+\b") and flag reviews in the 10–100 word range.

SQL equivalent

-- Word count via array split (standard SQL)
SELECT review_id,
  CARDINALITY(STRING_TO_ARRAY(
      TRIM(review_text), ' ')) AS word_count
FROM reviews;
-- PostgreSQL only. Splits on space, not regex.
-- Double spaces → empty array elements (over-count).
-- Python \b\w+\b is more robust.

-- To filter valid reviews:
SELECT * FROM above_query
WHERE word_count BETWEEN 10 AND 100;

Python: count words with \b\w+\b

def validate_review_length(text):
    # \b\w+\b matches each word token:
    #   \b = word boundary (start)
    #   \w+ = one or more word characters
    #   \b = word boundary (end)
    # re.findall() returns a list — one element per word
    word_count = len(re.findall(r'\b\w+\b', text))

    # Chained comparison: 10 <= n <= 100
    # Returns True if review is long enough but not too long
    return 10 <= word_count <= 100

df['valid_review'] = (
    df['cleaned_reviews'].apply(validate_review_length)
)

df['valid_review'].value_counts()
# False: 813 (too short or too long)
# True:  784 (valid 10-100 word reviews)
Why \b\w+\b instead of .split()? .split(' ') counts empty strings when there are extra spaces. \b\w+\b matches only real word tokens — punctuation, numbers, and gaps are handled correctly.
Full Code

Complete Pipeline

import pandas as pd
import re

df = pd.read_csv("Globalmart_reviews.csv")

# ── Task 1: Clean text ──────────────────────────────
def clean_text(text):
    text = re.sub(r'[^\w\s]', '', text)  # remove punctuation
    text = re.sub(r'\s+', ' ', text)      # collapse spaces
    return text.strip().lower()

df['cleaned_reviews'] = df['review_text'].apply(clean_text)

# ── Task 2: Detect product issues ───────────────────
issue_pattern = r'\b(broken|defective|damaged)\b'
df['mentions_issue'] = df['cleaned_reviews'].str.contains(
    issue_pattern, flags=re.IGNORECASE, na=False
)

# ── Task 3: Extract phone numbers ───────────────────
phone_pattern = r'\b(?:\+?\d{1,3})?[.\s-]?\(?\d{3}\)?[.\s-]?\d{3}[.\s-]?\d{4}\b'
df['contact_numbers'] = df['cleaned_reviews'].str.extract(
    f'({phone_pattern})', expand=False
)

# ── Task 4: Count keywords ──────────────────────────
def count_keyword(text, keyword):
    return len(re.findall(rf'\b{keyword}\b', text, flags=re.IGNORECASE))

for kw in ['excellent', 'poor', 'refund']:
    df[f'count_{kw}'] = df['cleaned_reviews'].apply(lambda x: count_keyword(x, kw))

# ── Task 5: Validate review length ──────────────────
def validate_review_length(text):
    n = len(re.findall(r'\b\w+\b', text))
    return 10 <= n <= 100

df['valid_review'] = df['cleaned_reviews'].apply(validate_review_length)
