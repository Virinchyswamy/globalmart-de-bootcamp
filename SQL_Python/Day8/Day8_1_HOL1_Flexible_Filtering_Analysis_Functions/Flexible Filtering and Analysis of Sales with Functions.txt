## Concept: Function definitions, parameters, and arguments


A Python **function** is a named, reusable block of code that performs a specific task. Instead of writing the same filtering logic repeatedly, you define it once with a `def` statement, give it a name, declare what inputs it needs (parameters), and `return` a result.


**Analogy:** Think of a function like a coffee machine at GlobalMart's office. The machine is built once - the `def` block. Every morning, different people use it by putting in different inputs: "double espresso", "oat milk latte", "no sugar" - the arguments. The machine always runs the same internal logic but produces a customised output based on what was passed in. Nobody rebuilds the machine each time — they just call it with different arguments.

**Key terms:**

| Term | What It Means | Example |
|---|---|---|
| **Parameter** | Variable name declared inside `def` | `def filter_sales(category, min_amount)` |
| **Argument** | Actual value passed when calling the function | `filter_sales("Electronics", 5000)` |
| **Positional argument** | Matched to parameters by position - order matters | `filter_sales("Electronics", 5000)` |
| **Keyword argument** | Matched by name - order does not matter | `filter_sales(min_amount=5000, category="Electronics")` |
| **Default parameter** | Parameter with a pre-set fallback value | `def filter_sales(category, min_amount=0)` |
| **Return value** | The output the function sends back to the caller | `return filtered_df` |


**Anatomy of a function:**

```python
# 1. Define the function with parameters
def get_category_summary(df, category, min_discount=0.0):
    # 2. Function body -logic goes here
    filtered = df[
        (df["category"] == category) &
        (df["discount"] >= min_discount)
    ]
    # 3. Return the result
    return filtered[["sales_amount", "quantity", "discount"]].sum()

# 4. Call it - using positional and keyword arguments
get_category_summary(transactions, "Electronics")               # default min_discount = 0.0
get_category_summary(transactions, "Furniture", min_discount=0.2)  # override default
```

**When to use positional vs keyword arguments:**

| Situation | Recommended Style | Why |
|---|---|---|
| Few parameters, clear order | Positional | Concise and readable |
| Many parameters | Keyword | Avoids order mistakes |
| Optional / rarely changed | Default parameter | Callers only specify when needed |
| Sharing code with others | Keyword | Self-documenting, harder to misuse |

>[!TIP]
> Functions should return data - let the caller decide whether to print it. A function that calls print() internally and omits return cannot be composed: its output cannot be stored in a variable, passed to another function, or used in a pipeline.

```python
import pandas as pd

# Load and merge tables (from Input 3 setup)
transactions = pd.read_csv("https://cdn.enqurious.com/documents/c1783c85-e8de-4ccc-a92e-bfc37f8fbf93_extransactions.csv")
orders       = pd.read_csv("https://cdn.enqurious.com/documents/e232a410-6d01-4c69-b468-4ef821382898_exorders.csv")
products     = pd.read_csv("https://cdn.enqurious.com/documents/c2ac5069-8a28-487f-8aee-05c385222a6a_exproducts.csv")

trans = transactions.merge(
    products[["product_id", "product_name", "category", "sub_category"]],
    left_on="Product_ID", right_on="product_id", how="left"
)
trans = trans.merge(
    orders[["order_id", "ship_mode", "order_status"]],
    left_on="Order_ID", right_on="order_id", how="left"
)

# Function definition ───────────────────────────────────────────────────────
def get_category_summary(df, category, min_discount=0.0):
    """
    Returns a one-row summary of sales metrics for a given product category.

    Parameters
    ----------
    df           : merged transactions DataFrame
    category     : str   — product category (e.g. "Electronics")
    min_discount : float — minimum discount to include (default 0.0 = all)

    Returns
    -------
    pd.DataFrame with columns: category, total_revenue, total_quantity, avg_discount
    """
    # Apply category and discount filters
    filtered = df[
        (df["category"]  == category) &
        (df["Discount"]  >= min_discount)
    ]

    # Build the summary as a single-row DataFrame
    summary = pd.DataFrame([{
        "category"       : category,
        "total_revenue"  : filtered["Sales_Amount"].sum(),
        "total_quantity" : filtered["Quantity"].sum(),
        "avg_discount"   : round(filtered["Discount"].mean(), 2)
    }])
    return summary

# Function calls ────────────────────────────────────────────────────────────
# Positional argument — uses default min_discount = 0.0
print(get_category_summary(trans, "Electronics"))

# Keyword argument — override the default to filter for ≥ 20% discount only
print(get_category_summary(trans, "Electronics", min_discount=0.2))
```

- **`min_discount=0.0` as default**: A threshold of `0.0` means the condition `df["Discount"] >= 0.0` passes every row (all discounts are non-negative). This is the correct "no filter" behaviour -the caller does not need to pass anything when they want all transactions.
- **`pd.DataFrame([{...}])`**: Wrapping the aggregated values in a list-of-dict produces a clean single-row DataFrame. This is preferable to returning a `pd.Series` because the caller can display, export, or chain further DataFrame operations without type conversion.
- **`round(..., 2)`**: Applied to `avg_discount` to prevent floating-point precision noise (e.g., `0.14000000000000001`) in the output.
- **Column name casing**: The solution uses `"Discount"`, `"Sales_Amount"`, and `"Quantity"` - the actual casing from the `ex_transactions` table. Always verify with `trans.columns` in your environment and update accordingly.

>[!NOTE]
> A function without a `return` statement implicitly returns `None`. If you filter and aggregate inside the function but forget `return summary`, the caller receives `None` and gets a confusing `AttributeError` when they try to display or use it.

```python
def get_category_summary(df, category, min_discount=0.0, status=None):
    """
    Returns a one-row sales summary for a given category, with optional
    discount threshold and order status filters.

    Parameters
    ----------
    df           : merged transactions DataFrame
    category     : str or None  - product category (e.g. "Furniture")
    min_discount : float        - minimum discount to include (default 0.0)
    status       : str or None  - order_status to filter on (default None = all statuses)

    Returns
    -------
    pd.DataFrame with columns: category, total_revenue, total_quantity, avg_discount
    """
    # Start with category + discount filters
    filtered = df[
        (df["category"] == category) &
        (df["Discount"] >= min_discount)
    ]

    # Apply optional status filter only when provided
    if status is not None:
        filtered = filtered[filtered["order_status"] == status]

    summary = pd.DataFrame([{
        "category"       : category,
        "total_revenue"  : filtered["Sales_Amount"].sum(),
        "total_quantity" : filtered["Quantity"].sum(),
        "avg_discount"   : round(filtered["Discount"].mean(), 2)
    }])
    return summary

# Uses default min_discount and no status filter - backward-compatible
print(get_category_summary(trans, "Furniture"))

# Keyword arguments — only delivered Furniture orders with ≥ 10% discount
print(get_category_summary(trans, "Furniture", min_discount=0.1, status="delivered"))
```

- **`status=None` default**: Using `None` rather than an empty string `""` avoids accidental matches if any `order_status` value in the data happens to be an empty string. `None` is an unambiguous "not provided" sentinel.
- **Conditional filter `if status is not None:`**: The filter is applied after the primary category and discount filters, so `filtered` shrinks progressively. This keeps each filter step independent and easy to debug.
- **Backward compatibility**: Adding `status=None` at the end of the parameter list means all existing call sites (e.g., `get_category_summary(trans, "Electronics")`) continue to work without modification — a key property of extending functions with optional parameters.

```python
def filter_by_ship_mode(df, ship_mode, min_sales=0):
    """
    Filters transactions by ship mode and an optional minimum sales threshold.

    Parameters
    ----------
    df        : merged transactions DataFrame
    ship_mode : str   - shipment mode to filter on (e.g. "Premium", "Standard")
    min_sales : float - minimum sales_amount to include (default 0 = no threshold)

    Returns
    -------
    pd.DataFrame of filtered transaction rows
    """
    filtered = df[
        (df["ship_mode"]    == ship_mode) &
        (df["Sales_Amount"] >= min_sales)
    ]

    # Return a clean subset of columns with a reset index
    return filtered[[
        "TransactionID", "Order_ID", "product_name",
        "category", "Sales_Amount", "Quantity", "Discount", "ship_mode"
    ]].reset_index(drop=True)

# Positional only — returns all Premium transactions (min_sales defaults to 0)
print(filter_by_ship_mode(trans, "Premium"))

# Positional + keyword — Standard transactions worth at least $3,000
print(filter_by_ship_mode(trans, "Standard", min_sales=3000))

# Keyword arguments only — same result, order-independent
print(filter_by_ship_mode(df=trans, ship_mode="Fastrack", min_sales=1500))
```

- **`min_sales=0` default**: A threshold of `0` means `df["Sales_Amount"] >= 0` passes all transactions (assuming no negative sales values). Callers who only want high-value shipments simply add `min_sales=3000` — the default requires no change to existing call sites.
- **Returning a column subset**: Returning only the eight columns the Logistics team uses keeps the output focused. Returning the entire `trans` DataFrame (with all merge columns) would expose unnecessary data and make the output harder to read.
- **`reset_index(drop=True)`**: After boolean filtering, the index retains the original row numbers from `trans` (e.g., 0, 5, 12, 19...). Resetting gives the caller a clean 0-based index, which is easier to work with in subsequent operations.
- **All-keyword call `filter_by_ship_mode(df=trans, ship_mode="Fastrack", min_sales=1500)`**: Demonstrates that keyword arguments can be passed in any order — a useful pattern when sharing call sites with other analysts who may not remember parameter order.

>[!NOTE]
> Passing arguments in the wrong positional order — `filter_by_ship_mode(trans, 3000, "Standard")` — passes `3000` to `ship_mode` and `"Standard"` to `min_sales`, producing a `TypeError` or silently incorrect results. Use keyword arguments at call sites that others will read or reuse.

```python
def get_top_products(df, category, top_n=5):
    """
    Returns a ranked leaderboard of the top-N products by total sales
    within a given category.

    Parameters
    ----------
    df       : merged transactions DataFrame
    category : str — product category to filter on (e.g. "Electronics")
    top_n    : int — number of top products to return (default 5)

    Returns
    -------
    pd.DataFrame with columns: rank, product_name, category,
                               total_revenue, total_quantity
    """
    # Filter to the requested category
    filtered = df[df["category"] == category]

    # Aggregate total revenue and quantity per product, sort, take top N
    leaderboard = (
        filtered
        .groupby("product_name")
        .agg(
            total_revenue  = ("Sales_Amount", "sum"),
            total_quantity = ("Quantity",     "sum")
        )
        .reset_index()
        .sort_values("total_revenue", ascending=False)
        .head(top_n)
        .reset_index(drop=True)
    )

    # Add rank and category columns at the front
    leaderboard.insert(0, "rank",     range(1, len(leaderboard) + 1))
    leaderboard.insert(2, "category", category)

    return leaderboard

# Positional only — top 5 Electronics (uses default top_n = 5)
print(get_top_products(trans, "Electronics"))

# Positional + keyword — top 3 Furniture products
print(get_top_products(trans, "Furniture", top_n=3))

# Keyword arguments only — top 10 Office Supplies
print(get_top_products(df=trans, category="Office Supplies", top_n=10))
```

- **`.groupby("product_name").agg(...).reset_index()`**: After `groupby().agg()`, `product_name` becomes the DataFrame index. `reset_index()` promotes it back to a regular column so it can be referenced by name in subsequent operations and displayed cleanly.
- **`.sort_values("total_revenue", ascending=False)`**: Sorts products from highest to lowest revenue before slicing — rank 1 is the top seller. `ascending=False` is explicit and prevents the common mistake of sorting ascending by default.
- **`.head(top_n)`**: Slices the sorted DataFrame to the first `top_n` rows. Because the sort is already applied, `.head()` is equivalent to "top N by revenue".
- **`leaderboard.insert(0, "rank", range(1, len(leaderboard) + 1))`**: Assigns sequential rank numbers 1 through N after the DataFrame is finalized. Using `range` rather than pandas `.rank()` here is intentional — the leaderboard is already sorted, so ordinal assignment is transparent and produces no ties.
- **`top_n=5` default**: The most common business ask is "top 5". Making it the default means callers only need to specify it when they want a different count — keeping the common case simple.

**Question:** An analyst calls `filter_by_ship_mode(trans, 3000, "Standard")`. The function signature is `def filter_by_ship_mode(df, ship_mode, min_sales=0)`. What is the most likely outcome?

**Options:**

- The function raises a `TypeError` or produces silently wrong results because `3000` is matched to `ship_mode` and `"Standard"` to `min_sales`

- The function raises a `ValueError` because `3000` is not a valid ship mode string

- The function uses the default `min_sales=0` because `3000` is passed as a keyword argument

**Correct Options:** 
- The function raises a `TypeError` or produces silently wrong results because `3000` is matched to `ship_mode` and `"Standard"` to `min_sales`

**Solution:** 
**Positional arguments are matched by position, not by name** — passing them in the wrong order causes silent logic errors or type errors that can be very hard to debug.

- **Wrong order causes errors ✅** — With the signature `filter_by_ship_mode(df, ship_mode, min_sales=0)`, the call `filter_by_ship_mode(trans, 3000, "Standard")` maps `3000` to the `ship_mode` parameter and `"Standard"` to `min_sales`. Inside the function, `df["ship_mode"] == 3000` will match nothing (producing an empty DataFrame silently) and `df["Sales_Amount"] >= "Standard"` will raise a `TypeError` because you cannot compare a numeric column to a string.
- **Matched by name automatically ❌** — Python does not infer intent from argument values. Positional arguments are always matched by position. Without keyword syntax, `3000` is the second argument and maps to `ship_mode`, not to `min_sales`.
- **`ValueError` for invalid ship mode ❌** — Python functions do not validate parameter types or values by default. The function will not raise a `ValueError` on its own — it simply applies the filter, which either returns zero rows or raises an error when comparing incompatible types.
- **Uses default `min_sales=0` ❌** — The default value for `min_sales` is only used when no argument is provided for that parameter. Here, `"Standard"` is explicitly passed as the third argument, so the default is overridden by `"Standard"` — not by `3000`.

>[!TIP]
> Use keyword arguments at any call site that others will read or reuse: `filter_by_ship_mode(trans, ship_mode="Standard", min_sales=3000)`. This makes the intent unambiguous and eliminates the risk of positional order mistakes.

##### Input 9
**Type:** Choice

**Question:** Which of the following are valid reasons to use `None` as the default value for an optional parameter instead of using an empty string `""` or an empty list `[]`? (Select 2)

**Options:** 
- `None` is an unambiguous sentinel value that cannot be confused with a valid input, making conditional guards like `if status is not None:` reliable

- `None` is faster to evaluate than an empty string in boolean conditions, improving function performance

- Using a mutable default value like `[]` is shared across all function calls — mutations in one call affect subsequent calls, which `None` avoids

- `None` automatically converts to `False` in boolean conditions, removing the need for an explicit `if` guard

**Correct Options:** 
- `None` is an unambiguous sentinel value that cannot be confused with a valid input, making conditional guards like `if status is not None:` reliable

- Using a mutable default value like `[]` is shared across all function calls — mutations in one call affect subsequent calls, which `None` avoids

**Solution:** 
**`None` as a default is a Python best practice for two distinct reasons** — one about semantic clarity, one about a dangerous mutable default bug.

- **`None` as an unambiguous sentinel ✅** — An empty string `""` could be a valid `order_status` value in some datasets. Using `""` as the default would make it impossible to distinguish "caller passed no status filter" from "caller explicitly filtered for orders with an empty status". `None` has no such ambiguity — it unambiguously means "not provided", making `if status is not None:` a reliable guard.
- **Mutable default argument bug ✅** — Python evaluates default parameter values once at function definition time, not at each call. If you write `def my_func(items=[])`, all calls share the same list object. Appending to `items` in one call permanently modifies the default for every subsequent call. Using `None` as the default and creating the list inside the function body (`if items is None: items = []`) avoids this entirely.
- **Performance advantage ❌** — `None` has no meaningful performance advantage over an empty string in boolean evaluation. This is not a valid reason to prefer `None`.
- **Automatic `False` conversion removing the `if` guard ❌** — While `None` is falsy in Python (`bool(None) == False`), relying on this to replace an explicit `if` guard is a code smell. An empty string `""` and an empty list `[]` are also falsy, making `if status:` unreliable as a guard when the caller might legitimately pass a falsy-but-valid value. Always use `if status is not None:` for clarity.
