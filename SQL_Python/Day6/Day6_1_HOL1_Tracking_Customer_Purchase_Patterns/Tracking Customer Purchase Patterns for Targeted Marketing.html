Window Operations — The Key Concept

groupby().agg() collapses N rows → 1 per group. Window operations keep all rows and compute across them — just like SQL's OVER(PARTITION BY ...).

pandas → SQL equivalents

pandasSQLResult
.rank(method='min')RANK()Ties share rank; next skips (1,1,3)
.rank(method='dense')DENSE_RANK()Ties share rank; no gap (1,1,2)
.rank(method='first')ROW_NUMBER()Unique sequential, no ties (1,2,3)
.cumsum()SUM() OVER(...)Running total per group
.expanding().mean()AVG() OVER(...)Running average per group

The critical difference

# agg → collapses to 1 row per group
df.groupby('channel')['conversions'].sum()
# Email Marketing    → 5620 (one number)

# rank → keeps all rows, adds a ranking column
df.groupby('channel')['conversions'].rank(ascending=False)
# campaign 1 Email → rank 1
# campaign 2 Email → rank 3
# campaign 3 Social → rank 1   ← partitioned by channel

❓ You want to rank campaigns where two tied campaigns both get rank 1 and the next gets rank 2 (no gap). Which method?

✅ method='dense' — equivalent to SQL's DENSE_RANK(). Ties share rank, no gap after them. method='min' (SQL RANK) would skip rank 2 and jump to 3.

Step 1 — Aggregate Daily Metrics Per Campaign

ex_campaign_metrics has one row per campaign per day. We need to collapse to one row per campaign.

import pandas as pd
import numpy as np

metrics   = pd.read_csv('ex_campaign_metrics.csv',
                          parse_dates=['metric_date'])
campaigns = pd.read_csv('ex_campaigns.csv',
                          parse_dates=['start_date','end_date'])
channel   = pd.read_csv('ex_channel.csv')

# Aggregate daily → campaign totals
camp_agg = (
    metrics
    .groupby('campaign_id')
    .agg(
        total_impressions = ('impressions', 'sum'),
        total_clicks      = ('clicks',      'sum'),
        total_conversions = ('conversions', 'sum'),
        total_bounces     = ('bounces',     'sum'),
        distinct_dates    = ('metric_date', 'nunique'),
    )
    .reset_index()
)

# avg_daily_conversions = total / number of distinct days
camp_agg['avg_daily_conversions'] = (
    camp_agg['total_conversions'] / camp_agg['distinct_dates']
).round(2)
camp_agg.drop(columns='distinct_dates', inplace=True)

Metrics dictionary

ColumnDescription
impressionsTimes ad was shown
clicksTimes ad was clicked
conversionsDesired actions completed
bouncesSessions where user left immediately
avg_daily_conv.conversions / active days
💡 nunique for distinct dates — Using 'nunique' on metric_date gives the number of active days for the campaign, needed to compute the correct daily average.

❓ What's the difference between 'count' and 'nunique' as an aggfunc?

✅ 'count' counts all rows (including duplicates). 'nunique' counts only distinct unique values. For dates: if a campaign ran for 10 days and each day has 3 records, count=30, nunique=10.

Step 2 — Merge and Compute Derived Metrics

# Merge: campaign_agg + campaigns + channel
df = (
    camp_agg
    .merge(campaigns, on='campaign_id', how='inner')
    .merge(channel,   on='channel_id',  how='inner')
)

# Campaign duration: (end_date - start_date) + 1 day
df['campaign_duration_days'] = (
    df['end_date'] - df['start_date']
).dt.days + 1

# CTR = clicks / impressions × 100
# np.where: safe division (avoid ÷0 error)
df['click_through_rate'] = np.where(
    df['total_impressions'] > 0,
    (df['total_clicks'] / df['total_impressions'] * 100).round(2),
    0.0
)
df['click_through_rate'] = df['click_through_rate'].apply(lambda x: f"{x}%")

# CR = conversions / clicks × 100
df['conversion_rate'] = np.where(
    df['total_clicks'] > 0,
    (df['total_conversions'] / df['total_clicks'] * 100).round(2),
    0.0
)
df['conversion_rate'] = df['conversion_rate'].apply(lambda x: f"{x}%")

np.where() — safe division

# np.where(condition, value_if_true, value_if_false)
# → if impressions > 0: compute CTR
# → else: set to 0.0 (avoid divide-by-zero ZeroDivisionError)
np.where(df['total_impressions'] > 0, formula, 0.0)

❓ What happens if you don't use np.where() and a campaign has 0 impressions?

✅ ZeroDivisionError (or NaN in pandas). Division by zero: clicks/0 = undefined. np.where() short-circuits — if the condition is False (impressions == 0), it returns the fallback value (0.0) without ever attempting the division.

Step 3 — Rank Campaigns Within Each Channel

We want to know which campaigns are top performers within their own channel — not globally. This requires partitioning by channel, just like SQL's RANK() OVER(PARTITION BY channel_name).

# RANK within channel — ties share rank, next skips
# (RANK() in SQL)
df['channel_rank'] = (
    df.groupby('channel_name')['total_conversions']
    .rank(method='min', ascending=False)
    .astype(int)
)

# DENSE_RANK within channel — ties share rank, NO gap
# (DENSE_RANK() in SQL)
df['dense_channel_rank'] = (
    df.groupby('channel_name')['total_conversions']
    .rank(method='dense', ascending=False)
    .astype(int)
)

# ROW_NUMBER within channel — unique, no ties
# (ROW_NUMBER() in SQL)
df['row_num'] = (
    df.groupby('channel_name')['total_conversions']
    .rank(method='first', ascending=False)
    .astype(int)
)

# ascending=False → highest conversions = rank 1

Why .astype(int)?

rank() returns floats by default (e.g., 1.0, 2.0). .astype(int) converts to clean integers (1, 2, 3) for display.

❓ Which method gives 1,1,3 for two tied campaigns (gap after tie)? Which gives 1,1,2 (no gap)?

✅ 1,1,3 = method='min' (SQL RANK). 1,1,2 = method='dense' (SQL DENSE_RANK). Both make ties share the same rank — the difference is whether the next rank skips.

Step 4 — Running Totals and Averages

For daily trend analysis, we want to see cumulative conversions and running average clicks as they build up day by day within each campaign.

# CRITICAL: Sort by campaign + date BEFORE cumulative ops
# Unsorted data gives wrong running totals!
m_sorted = metrics.sort_values(
    ['campaign_id', 'metric_date']
).reset_index(drop=True)

# cumsum() — running total conversions per campaign
# Like SUM() OVER(PARTITION BY campaign ORDER BY date)
m_sorted['cumulative_conversions'] = (
    m_sorted
    .groupby('campaign_id')['conversions']
    .cumsum()
)

# expanding().mean() — running average clicks per campaign
# Like AVG() OVER(PARTITION BY campaign ORDER BY date
#                ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
m_sorted['running_avg_clicks'] = (
    m_sorted
    .groupby('campaign_id')['clicks']
    .expanding()
    .mean()
    .round(2)
    .values   # .values avoids index mismatch
)

⚠️ Always sort before cumulative operations — cumsum() and expanding() process rows in DataFrame order. If dates are unsorted, the running totals will be wrong and impossible to debug visually.

❓ What does groupby().cumsum() return vs groupby().sum()?

✅ groupby().sum() collapses to one total per group. groupby().cumsum() keeps all rows and adds a running total that grows day by day within each group. After the last day it equals the same value as .sum().

Full Pipeline — Campaign Performance Summary

import pandas as pd; import numpy as np

# Load
campaigns = pd.read_csv('ex_campaigns.csv', parse_dates=['start_date','end_date'])
channel   = pd.read_csv('ex_channel.csv')
metrics   = pd.read_csv('ex_campaign_metrics.csv', parse_dates=['metric_date'])

# Aggregate daily → campaign
agg = metrics.groupby('campaign_id').agg(
    total_impressions=('impressions','sum'),
    total_clicks=('clicks','sum'),
    total_conversions=('conversions','sum'),
    total_bounces=('bounces','sum'),
    distinct_dates=('metric_date','nunique')
).reset_index()
agg['avg_daily_conversions'] = (agg['total_conversions']/agg['distinct_dates']).round(2)
agg.drop(columns='distinct_dates', inplace=True)

# Merge metadata
df = agg.merge(campaigns, on='campaign_id').merge(channel, on='channel_id')

# Derived metrics
df['campaign_duration_days'] = (df['end_date']-df['start_date']).dt.days+1
df['click_through_rate'] = np.where(df['total_impressions']>0,
    (df['total_clicks']/df['total_impressions']*100).round(2), 0.0)
df['conversion_rate']   = np.where(df['total_clicks']>0,
    (df['total_conversions']/df['total_clicks']*100).round(2), 0.0)

# Rank within channel
df['channel_rank']       = df.groupby('channel_name')['total_conversions'].rank(method='min',   ascending=False).astype(int)
df['dense_channel_rank'] = df.groupby('channel_name')['total_conversions'].rank(method='dense', ascending=False).astype(int)
df['row_num']            = df.groupby('channel_name')['total_conversions'].rank(method='first', ascending=False).astype(int)

# Running totals (sort first!)
ms = metrics.sort_values(['campaign_id','metric_date']).reset_index(drop=True)
ms['cumulative_conversions'] = ms.groupby('campaign_id')['conversions'].cumsum()
ms['running_avg_clicks']     = ms.groupby('campaign_id')['clicks'].expanding().mean().round(2).values

❓ True or false: groupby().rank() returns the same number of rows as the input DataFrame?

✅ True — rank() is a window operation. It keeps every row and adds a ranking value to each. It does NOT collapse rows. This is the fundamental difference from agg() which reduces N rows to 1 per group.
