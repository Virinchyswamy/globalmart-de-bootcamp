🗺️ Identifying High-Performing States

The Senior VP believes all states are doing well. Your job: use SQL to find which states actually beat the national average in sales — and which ones fall short.

The Challenge

Is the VP Right? Are All States Performing Well? 🤔

GlobalMart operates across 49+ states. The Senior VP is "optimistic about robust sales across all states." The data team needs to validate — or challenge — this belief.

The Business Question

Which states have average sales per transaction that exceed the national average?

This identifies genuine outperformers from the noise — states that are actually above the benchmark, not just "doing OK."

Spoiler: Only 13 states beat the national average. The VP may be surprised.

The SQL Challenge

To compare each state to the national average, we need the national average on every single row alongside the state's average.

The national average is computed from ALL states — not partitioned. This is the empty OVER() use case.

AVG(sales) OVER() — no PARTITION BY, no ORDER BY

Tables (no ex_ prefix — original GlobalMart dataset):
transactions  ·  orders  ·  customers  ·  locations_01

OVER(PARTITION BY state)

Creates one window per state. Each window computes independently. You get a different AVG per state.

Not what we want — this gives state average, not national.

OVER() — empty

Creates ONE window covering ALL rows. Computes a single global value. That value appears on every row.

This is what we want — national average on every state row.

Visualize it:
Imagine 49 state rows. With OVER(), SQL puts the average of ALL 49 states' averages on each row. Now you can compare state vs. national in a simple WHERE clause.

If OVER() had no effect and just returned the avg per row, what would the national_avg column show for Texas?

✅ It would show Texas's own average (same as state_avg_sales). The magic of OVER() is that it uses ALL rows — not just the current state's rows — to compute one shared value.

CTE 1 — TransactionData

Join transactions → orders → customers → locations_01 to get one row per transaction with its state.

Think of this as the "master dataset" — everything needed in one place.

mskl-masterclass
SELECT t.*,
  o.order_purchase_date,
  l.state
FROM transactions t
JOIN orders o
    ON t.Order_ID = o.order_id
JOIN customers c
    ON o.Customer_ID = c.Customer_ID
JOIN locations_01 l
    ON c.postal_code = l.postal_code

CTE 2 — StateSummary

Aggregate to one row per state. Compute average sales per transaction for each state.

After this CTE, each state = one row with one sales value.

mskl-masterclass
SELECT
  state,
  AVG(sales) AS sales
FROM TransactionData
GROUP BY state

-- Result: ~49 rows
-- One average per state

CTE 3 — AvgSales

Add the global national average using AVG() OVER() — one value for all rows.

Now every state row has: its own average AND the national benchmark side by side.

mskl-masterclass
SELECT *,
  -- Empty OVER() = single global avg
  -- Same value on ALL state rows
  AVG(sales)
      OVER()
      AS avg_national_sales
FROM StateSummary

Final SELECT: Filter WHERE sales > avg_national_sales. That's it! The heavy lifting was done by the window function. The final query is just a comparison.

mskl-masterclass
SELECT state, sales
FROM AvgSales
WHERE sales > avg_national_sales; -- numeric compare — works!

Live Demo — Full Solution: High-Performing States 🌟

Tables: transactions, orders, customers, locations_01 (no ex_ prefix) | mskl-masterclass
mskl-masterclass
-- CTE 1: Build master dataset with state per transaction
WITH TransactionData AS (
    SELECT
        t.*,
        o.order_purchase_date AS Order_Date,
        l.state
    FROM transactions t
    JOIN orders o
        ON t.Order_ID = o.order_id
    JOIN customers c
        ON o.Customer_ID = c.Customer_ID
    JOIN locations_01 l
        ON c.postal_code = l.postal_code
),
-- CTE 2: Aggregate to one row per state
-- AVG(sales) = average transaction value in that state
StateSummary AS (
    SELECT
        state,
        AVG(sales) AS sales
    FROM TransactionData
    GROUP BY state
),
-- CTE 3: Add national average using window function
-- OVER() with NO arguments = one window = ALL rows = global value
-- This single value gets stamped on every row in StateSummary
AvgSales AS (
    SELECT
        *,
        AVG(sales) OVER() AS avg_national_sales
    FROM StateSummary
)
-- Final: keep only states whose avg sales beats the national avg
-- sales and avg_national_sales are both numbers → comparison works
SELECT
    state,
    sales
FROM AvgSales
WHERE (
    CASE
        WHEN sales > avg_national_sales THEN 1
        ELSE 0
    END
) = 1;

Comparison

❓ Could We Use a Subquery Instead?

Yes — here are two ways to get the same result:

Option 1 — Subquery in WHERE

mskl-masterclass
WHERE sales > (
    SELECT AVG(sales)
    FROM StateSummary
)
-- Runs AVG() once as a scalar subquery
-- Compares each state row to that scalar

Option 2 — Window Function (our approach)

mskl-masterclass
AVG(sales) OVER() AS avg_national_sales
-- Computes the same value but puts it on
-- every row as a visible column
-- Then WHERE sales > avg_national_sales

Recommendation: In production reports, use the window function. It makes the national average visible and auditable in the output. With a subquery, the benchmark disappears — the reader can't verify what you compared against.
