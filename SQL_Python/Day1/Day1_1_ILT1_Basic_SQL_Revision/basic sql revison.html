The Basic SELECT Statement

Every SQL query starts with a SELECT. Think of it as telling the database: "Hey, show me this information from this table." 

-- Get everything from the customers table
SELECT *
FROM ex_customers;

-- Get only specific columns (better practice)
SELECT
    customer_id,
    customer_name,
    state
FROM ex_customers;

-- Give a column a friendlier name using AS
SELECT
    customer_name AS 'Customer',
    state         AS 'State / Region'
FROM ex_customers;

Why not always use SELECT *?

SELECT * grabs every column — fine for exploration, but slow on large tables. In production code, always name the columns you actually need.

DISTINCT — removes duplicate rows from the result.

-- How many unique states do our customers live in?
SELECT DISTINCT state
FROM ex_customers;

TOP N — gives only the first N rows back.

-- Just want to peek at 5 rows
SELECT TOP 5 * FROM ex_customers;

Filtering with WHERE

-- Orders placed in a specific state
SELECT *
FROM ex_customers
WHERE state = 'California';

-- Multiple conditions with AND
SELECT *
FROM ex_orders
WHERE order_status = 'delivered'
  AND ship_mode = 'First Class';

-- IN clause: instead of many OR conditions
SELECT *
FROM ex_customers
WHERE state IN ('California', 'Texas', 'Arizona');

-- LIKE clause: pattern matching
SELECT *
FROM ex_customers
WHERE customer_name LIKE 'A%';
-- % means "anything can come here"

Live Demo — Text Functions

Run these in SSMS · Database: mskl-masterclass
-- Real data often has messy spaces and inconsistent casing
-- Let's clean the state column in ex_customers

-- TRIM removes leading/trailing spaces
SELECT
    customer_name,
    state                           AS raw_state,
    TRIM(state)                    AS trimmed_state,
    UPPER(TRIM(state))             AS clean_upper,
    LOWER(TRIM(state))             AS clean_lower
FROM ex_customers;

-- LEN tells us how long a string is
SELECT
    customer_name,
    LEN(customer_name) AS name_length
FROM ex_customers
ORDER BY name_length DESC;

-- CONCAT joins two strings together
SELECT
    CONCAT(customer_name, ' — ', state) AS customer_info
FROM ex_customers;

Why this matters

The self-paced content has a scenario where state has typos and inconsistent casing — 'calfornia' instead of 'California'.

These functions are the tools Rahul uses to clean it up before any analysis.

CASE WHEN — works like an IF / ELSE

-- Standardise typos in state names
SELECT
    customer_id,
    CASE
        WHEN TRIM(state) = 'calfornia'
            THEN 'California'
        WHEN TRIM(state) = 'masachusets'
            THEN 'Massachusetts'
        ELSE UPPER(TRIM(state))
    END AS state_clean
FROM ex_customers;

Live Demo — Date Functions

Run these in SSMS · Database: mskl-masterclass
-- YEAR / MONTH / DAY extract parts of a date
SELECT
    order_id,
    order_purchase_date,
    YEAR(order_purchase_date)  AS order_year,
    MONTH(order_purchase_date) AS order_month,
    DAY(order_purchase_date)   AS order_day
FROM ex_orders;

-- DATEDIFF calculates the gap between two dates
-- Syntax: DATEDIFF(unit, start_date, end_date)
SELECT
    order_id,
    order_purchase_date,
    order_delivered_customer_date,

    -- How many days did this delivery take?
    DATEDIFF(day,
        order_purchase_date,
        order_delivered_customer_date
    ) AS delivery_days
FROM ex_orders
WHERE order_status = 'delivered'
ORDER BY delivery_days;

-- Filter to only orders from 2017
SELECT *
FROM ex_orders
WHERE YEAR(order_purchase_date) = 2017;

Math Functions & Calculations

-- ROUND rounds to N decimal places
SELECT
    product_id,
    sales_amount,
    ROUND(sales_amount, 2) AS rounded_sales
FROM ex_transactions;

-- FLOOR always rounds DOWN to nearest integer
-- Used later for avg_basket_size in Loyalty Program
SELECT
    FLOOR(7.9)  -- returns 7
    FLOOR(7.1)  -- returns 7

-- Arithmetic in SQL works just like a calculator
SELECT
    order_id,
    sales_amount,
    quantity,

    -- Price per unit (avoid division by zero in real code)
    sales_amount / quantity         AS price_per_unit,

    -- Apply a 10% discount
    sales_amount * 0.90             AS discounted_price
FROM ex_transactions;

Quick Reference

FunctionWhat it does
ROUND(x, n)Round to n decimals
FLOOR(x)Always round down
CEILING(x)Always round up
ABS(x)Remove negative sign

Integer division gotcha:
In SQL, 7 / 2 = 3 (not 3.5) because both numbers are integers. To get a decimal result, cast one to float: 1.0 * 7 / 2 = 3.5

SQL Order of Execution — The Most Important Concept

We write SQL in one order, but SQL executes it in a completely different order.

How SQL Actually Runs

  1. FROM — pick the table(s) first
  2. JOIN … ON — combine tables; ON condition is evaluated here to match rows
  3. WHERE — filter out individual rows you don't need
  4. GROUP BY — group remaining rows together
  5. HAVING — filter the groups
  6. SELECT — now choose what columns to show
  7. ORDER BY — sort the final result

Why does this matter?

This is why you cannot use an alias defined in SELECT inside a WHERE clause — WHERE runs before SELECT!

Also, JOIN runs before WHERE — so filters placed on the JOIN's ON condition apply during table merging, while WHERE filters the combined result afterwards.

-- This FAILS — alias 'delivery_days' doesn't
-- exist yet when WHERE runs
SELECT
    DATEDIFF(day, order_purchase_date,
        order_delivered_customer_date) AS delivery_days
FROM ex_orders
WHERE delivery_days > 10;  -- ❌ ERROR

-- This WORKS — repeat the expression in WHERE
SELECT
    DATEDIFF(day, order_purchase_date,
        order_delivered_customer_date) AS delivery_days
FROM ex_orders
WHERE DATEDIFF(day, order_purchase_date,
        order_delivered_customer_date) > 10;  -- ✅
