**Question:** ## Task 1: Hierarchical Sales Report with ROLLUP

### Scenario
The VP of Sales needs a **hierarchical summary** of total sales that rolls up from city level to state level to region level, and finally to a grand total. This report will help identify the geographic distribution of sales at each level of the organization.

### Your Task
Write a query that generates a sales report summarizing total sales across regions, states, and cities using the `ROLLUP` function.

**Your report must include:**
- Total sales for each city (within its state and region)
- Subtotals for each state (all cities combined within that state)
- Subtotals for each region (all states combined within that region)
- A grand total for all regions, states, and cities

### Expected Output Format
Your output should look similar to this:

| region | state | city | total_sales |
|--------|-------|------|-------------|
| Central | Illinois | Chicago | 125000.00 |
| Central | Illinois | NULL | 250000.00 |
| Central | Ohio | Columbus | 85000.00 |
| Central | NULL | NULL | 500000.00 |
| East | New York | New York City | 320000.00 |
| NULL | NULL | NULL | 2500000.00 |

>[!IMPORTANT] 
> Use order_status = 'delivered' to ensure you're analyzing completed sales.

**Language:** sql

**Snippet:** 

**Solution:** 
**Understanding the Problem**  
Our goal is to create a **hierarchical sales report** that summarizes total sales across regions, states, and cities using `ROLLUP`. This report will help leadership identify sales performance at each geographic level — from individual cities up to state subtotals, region subtotals, and a grand total.

**Step 1: What information do we need?**

- `region` – To group sales by geographic region.
- `state` – To group sales by state within each region.
- `city` – To group sales by city within each state.
- `sales_amount` – To calculate total sales.
- `order_id` – To link transactions with orders.
- `customer_id` – To link orders with customers.
- `postal_code` – To link customers with locations.
- `order_status` – To filter for delivered orders only.

**Step 2: Where is this data found?**  
We need to combine four tables:

| Table | Column | Purpose |
| --- | --- | --- |
| ex\_transactions | sales\_amount | To calculate total sales |
| ex\_transactions | order\_id | To join with orders |
| ex\_orders | order\_id | To join with transactions |
| ex\_orders | customer\_id | To join with customers |
| ex\_orders | order\_status | To filter delivered orders |
| ex\_customers | customer\_id | To join with orders |
| ex\_customers | postal\_code | To join with locations |
| ex\_locations | postal\_code | To join with customers |
| ex\_locations | region, state, city | To group by geography |

* * *

**Logic Before Building the Solution**

1. **Join all four tables** (`ex_transactions` → `ex_orders` → `ex_customers` → `ex_locations`) using their respective keys.
2. **Filter for delivered orders** using `order_status = 'delivered'` to ensure we only analyze completed sales.
3. **Use ROLLUP** to create hierarchical aggregations: `(region, state, city)` → `(region, state)` → `(region)` → `()`.
4. **Aggregate sales** using `SUM(sales_amount)` grouped by `ROLLUP(region, state, city)`.
5. **Round the result** to 2 decimal places using `ROUND()`.
6. **Sort the results** by region, state, and city for readable output.

* * *

**Building the Solution Step-by-Step**

**Phase 1: Join All Tables**

```sql
SELECT * FROM ex_transactions t
JOIN ex_orders o 
ON t.order_id = o.order_id 
JOIN ex_customers c 
ON o.customer_id = c.customer_id 
JOIN ex_locations l 
ON c.postal_code = l.postal_code;
```
**Phase 2: Add Filter and Select Required Columns**

```sql
SELECT l.region, l.state, l.city, t.sales_amount
FROM ex_transactions t 
JOIN ex_orders o 
ON t.order_id = o.order_id AND o.order_status = 'delivered'
JOIN ex_customers c 
ON o.customer_id = c.customer_id 
JOIN ex_locations l ON c.postal_code = l.postal_code;
```
**Phase 3: Apply ROLLUP and Aggregate**

```sql
SELECT l.region, l.state, l.city, SUM(t.sales_amount) AS total_sales
FROM ex_transactions t 
JOIN ex_orders o 
ON t.order_id = o.order_id AND o.order_status = 'delivered'
JOIN ex_customers c 
ON o.customer_id = c.customer_id 
JOIN ex_locations l 
ON c.postal_code = l.postal_code
GROUP BY ROLLUP(l.region, l.state, l.city);
```
**Phase 4: Add Rounding and Ordering**

```sql
SELECT l.region, l.state, l.city, ROUND(SUM(t.sales_amount), 2) AS total_sales
FROM ex_transactions t 
JOIN ex_orders o 
ON t.order_id = o.order_id AND o.order_status = 'delivered'
JOIN ex_customers c 
ON o.customer_id = c.customer_id 
JOIN ex_locations l 
ON c.postal_code = l.postal_code
GROUP BY ROLLUP(l.region, l.state, l.city)
ORDER BY l.region, l.state, l.city;
```
* * *

**Final Working Solution**
```sql
SELECT l.region, l.state, l.city, ROUND(SUM(t.sales_amount), 2) AS total_sales
FROM ex_transactions t 
JOIN ex_orders o 
ON t.order_id = o.order_id AND o.order_status = 'delivered'
JOIN ex_customers c 
ON o.customer_id = c.customer_id 
JOIN ex_locations l 
ON c.postal_code = l.postal_code
GROUP BY ROLLUP(l.region, l.state, l.city)
ORDER BY l.region, l.state, l.city;
```
* * *

**Common Student Mistakes & Point Deductions**

- Forgetting to **filter for `order_status = 'delivered'`** → includes incomplete/cancelled orders in sales.
- **Incorrect join conditions** → data duplication or missing records.
- **Wrong column order in ROLLUP** → hierarchy doesn’t match business requirements (region → state → city).
- Forgetting `ROUND()` → sales amounts show too many decimal places.
- Not **ordering by region, state, city** → output appears unordered and hard to read.
- **Missing tables in joins** → cannot access all required columns.

✅ Correct approach: Join All Tables → Filter Delivered → Apply ROLLUP → Aggregate → Round → Order.

**Question:** ## Task 3: Custom Sales Report with GROUPING SETS

### Scenario
The Finance team has a **specific reporting requirement**. They don't need all combinations from CUBE, but they want more control than ROLLUP provides. They've requested a custom report with exactly four grouping levels tailored for their budget allocation model.

## Quick Reference: Comparison of All Three Solutions

| Feature | Task 1 (ROLLUP) | Task 2 (CUBE) | Task 3 (GROUPING SETS) |
|---------|-----------------|---------------|------------------------|
| **Groupings Generated** | 4 (n+1 for 3 columns) | 8 (2³ for 3 columns) | 4 (exactly as specified) |
| **Key Syntax** | `ROLLUP(a, b, c)` | `CUBE(a, b, c)` | `GROUPING SETS ((a,b,c), (a,b), (a), ())` |
| **Use Case** | Hierarchical reporting | Exploratory analysis | Custom reporting requirements |
| **Performance** | Moderate | Highest (most combinations) | Most efficient (only needed) |

##### Input 6
**Type:** Short Answer

**Question:** **What are the performance implications of using CUBE vs GROUPING SETS on large datasets?**

**Template:** null

**Solution:** 
CUBE generates **2^n combinations** (exponential growth), which can be very expensive on large datasets with many columns. GROUPING SETS is **more efficient** because it only computes the specific groupings you define, reducing computational overhead and query execution time.
