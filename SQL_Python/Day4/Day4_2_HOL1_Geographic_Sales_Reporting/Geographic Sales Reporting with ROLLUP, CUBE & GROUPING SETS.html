Day 4 · Module 14

Geographic Sales Reporting
with ROLLUP, CUBE & GROUPING SETS

GlobalMart expansion strategy — hierarchical geographic analysis

Business Context

GlobalMart leadership is planning their annual expansion strategy. They need comprehensive sales reports across regions, states, and cities to identify where to invest in new fulfillment centers and marketing campaigns.

Your role: Data Analyst intern on the Sales Analytics team.

Three Tasks

  • Task 1: Hierarchical report — VP of Sales needs region → state → city drill-down using ROLLUP
  • Task 2: All-dimension report — Chief Strategy Officer wants every geographic combination using CUBE
  • Task 3: Custom report — Finance team wants exactly 4 specific grouping levels using GROUPING SETS

Tables used: ex_transactions → ex_orders → ex_customers → ex_locations  |  Filter: order_status = 'delivered'

Database Setup: The 4-Table Join

All three tasks need geographic data. Build the foundation join first:

-- Phase 1: Verify the 4-table join
SELECT
    l.region,
    l.state,
    l.city,
    t.sales_amount
FROM ex_transactions t
JOIN ex_orders o     ON t.order_id   = o.order_id   -- transactions → orders
                       AND o.order_status = 'delivered'  -- filter early in JOIN
JOIN ex_customers c ON o.customer_id = c.customer_id -- orders → customers
JOIN ex_locations l ON c.postal_code = l.postal_code -- customers → locations (has city)
ORDER BY l.region, l.state, l.city;

Task 1: Hierarchical Sales Report with ROLLUP

Business ask: The VP of Sales needs a report that rolls up from city level → state level → region level → grand total. Delivered orders only.

Expected output format:

regionstatecitytotal_sales
CentralIllinoisChicago125,000
CentralIllinoisNULL250,000 ← state total
CentralNULLNULL500,000 ← region total
NULLNULLNULL2,500,000 ← grand total

NULL = rolled up / "all values in this column"

Build approach (4 phases):

  • 1 Join all 4 tables, verify data
  • 2 Add filter + select needed columns
  • 3 Apply ROLLUP and SUM aggregation
  • 4 Add ROUND() and ORDER BY

Task 1 Solution — ROLLUP

-- Task 1: Hierarchical sales report — city → state → region → grand total
SELECT
    l.region,
    l.state,
    l.city,
    ROUND(SUM(t.sales_amount), 2) AS total_sales
FROM ex_transactions t
JOIN ex_orders o     ON t.order_id   = o.order_id   AND o.order_status = 'delivered'
JOIN ex_customers c ON o.customer_id = c.customer_id
JOIN ex_locations l ON c.postal_code = l.postal_code
GROUP BY ROLLUP(l.region, l.state, l.city)  -- 4 levels: detail → state → region → grand
ORDER BY l.region, l.state, l.city;
Common mistakes:
  • Forgetting order_status = 'delivered' → includes cancelled orders
  • Wrong column order in ROLLUP → wrong hierarchy
  • Missing ROUND() → too many decimal places
  • Using locations_01 instead of ex_locations → no city column

Task 2: Comprehensive Analysis with CUBE

Business ask: The Chief Strategy Officer wants to explore ALL possible combinations — not just the hierarchy. They want sales by city across all regions, by state across all regions, etc. (exploratory analysis).

What CUBE adds over ROLLUP:

For 3 columns (region, state, city): CUBE produces 2³ = 8 groupings

When does (state) without (region) matter?

Question: "How much does Illinois sell nationally, across ALL regions?" — This is the (state) grouping with region=NULL. ROLLUP can't answer this. CUBE can.

Task 2 Solution — CUBE

-- Task 2: All possible geographic combinations — 2³ = 8 groupings
SELECT
    l.region,
    l.state,
    l.city,
    ROUND(SUM(t.sales_amount), 2) AS total_sales
FROM ex_transactions t
JOIN ex_orders o     ON t.order_id   = o.order_id   AND o.order_status = 'delivered'
JOIN ex_customers c ON o.customer_id = c.customer_id
JOIN ex_locations l ON c.postal_code = l.postal_code
GROUP BY CUBE(l.region, l.state, l.city)    -- 8 groupings: every subset
ORDER BY l.region, l.state, l.city;
ROLLUP vs CUBE output comparison:
  • ROLLUP: rows where region set, state is NULL, city is NULL (region totals only)
  • CUBE: also rows where region=NULL, state set (state national totals)
  • CUBE: also rows where region=NULL, city set (city national totals)
  • CUBE: also rows where region set, state=NULL, city set (unusual combos)

Task 3: Custom Report with GROUPING SETS

Business ask: Finance team has a specific requirement for their budget allocation model. They need exactly 4 grouping levels — no more, no less. ROLLUP gives 4 but in fixed hierarchy. GROUPING SETS gives control.

Finance team requires exactly these 4 groupings:

#GroupingPurpose
1(region, state, city)City-level sales detail
2(region, state)State subtotals within region
3(region)Region subtotals
4()Grand total

Wait — isn't this just ROLLUP? Yes! For this specific case. But GROUPING SETS lets Finance exclude any level or add non-hierarchical ones without rewriting the entire query structure.

GROUPING SETS syntax pattern:

GROUP BY GROUPING SETS (
    (region, state, city),  -- grouping 1
    (region, state),         -- grouping 2
    (region),                -- grouping 3
    ()                        -- grouping 4: grand total
)

Task 3 Solution — GROUPING SETS

-- Task 3: Finance team's exact 4-level custom report
SELECT
    l.region,
    l.state,
    l.city,
    ROUND(SUM(t.sales_amount), 2) AS total_sales
FROM ex_transactions t
JOIN ex_orders o     ON t.order_id   = o.order_id   AND o.order_status = 'delivered'
JOIN ex_customers c ON o.customer_id = c.customer_id
JOIN ex_locations l ON c.postal_code = l.postal_code
GROUP BY GROUPING SETS (
    (l.region, l.state, l.city),  -- city detail
    (l.region, l.state),           -- state subtotal within region
    (l.region),                     -- region subtotal
    ()                               -- grand total
)
ORDER BY l.region, l.state, l.city;
Common mistakes:
  • Missing () → no grand total row
  • Wrong parentheses nesting → syntax error
  • Adding extra groupings the Finance team didn't ask for
  • Forgetting commas between grouping sets

The CFO asks: "Show me total sales for (region, state) combinations and (state) alone in one query — but NOT by city or a grand total." Which operator do you use?

GROUPING SETS — because you need a non-hierarchical, custom combination. ROLLUP won't produce (state) without (region). CUBE produces too many combos including ones they don't want.

GROUP BY GROUPING SETS ((l.region, l.state), (l.state))
