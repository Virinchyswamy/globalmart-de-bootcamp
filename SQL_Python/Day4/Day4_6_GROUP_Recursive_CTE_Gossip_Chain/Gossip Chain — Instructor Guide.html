Full Answer — Always Visible

Correct SQL + What to Look For

WITH rumour_trail AS (

    -- BASE CASE: Yogesh's direct tell
    SELECT
        from_person,
        to_person,
        CAST(from_person + ' → ' + to_person AS VARCHAR(MAX)) AS chain,
        1 AS level
    FROM  #gossip_chain
    WHERE from_person = 'Yogesh'

    UNION ALL

    -- RECURSIVE CASE: who did each person tell next?
    SELECT
        g.from_person,
        g.to_person,
        CAST(rt.chain + ' → ' + g.to_person AS VARCHAR(MAX)) AS chain,
        rt.level + 1
    FROM #gossip_chain g
    JOIN rumour_trail rt
        ON g.from_person = rt.to_person
    WHERE rt.level < 20
)
SELECT
    to_person  AS person_who_heard_it,
    level      AS hops_from_yogesh,
    chain      AS how_they_heard_it
FROM   rumour_trail
ORDER BY level, to_person

Verify checklist — walk to their screen and check:

Exactly 9 rows in output
Column names: person_who_heard_it, hops_from_yogesh, how_they_heard_it
hops_from_yogesh values are 1 through 9
Row 1: Sujit, hop 1, "Yogesh → Sujit"
Last row: Gaurav, hop 9
Ordered by hops ASC
chain column shows full path with " → " separators

Common mistakes to watch for:

  • CTE name mismatch (skeleton says ___, they forget to name it)
  • JOIN condition reversed: rt.to_person = g.from_person is same — both fine
  • Missing WHERE rt.level < 20 — gets MAXRECURSION error
  • Using UNION instead of UNION ALL — may lose rows

SELECT from_person, COUNT(*) AS total_reached
FROM (... full rumour_trail CTE without WHERE ...)

Discussion question after bonus:

"Why does the recursive case need WHERE rt.level < 20? What would happen if this gossip table had cycles — like if Gaurav told Yogesh? What would the query do?"

Answer: Without the guard, cycles cause infinite recursion. SQL Server hits MAXRECURSION 100 and throws an error. The level guard stops it at 20 hops regardless of cycles.

Act 3 · Debrief

Debrief Notes — What to Emphasise

The 3 things they must leave knowing:

1
Base Case = the starting seed. WHERE from_person = 'Yogesh' gave one row. Runs once.
2
Recursive Case = takes to_person from previous result, finds who THEY told. The JOIN is the chain link.
3
Stops automatically when the JOIN finds nothing — the recursion returns 0 rows and SQL stops. No code needed to stop it (except the safety guard).

One sentence to leave them with:

"Recursive CTE is nothing but a loop with a memory. Each iteration knows what the previous one found, and uses that to find the next step."
