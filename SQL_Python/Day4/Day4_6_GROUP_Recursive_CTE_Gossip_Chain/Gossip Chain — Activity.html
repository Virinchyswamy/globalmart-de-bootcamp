The Story

Someone Started a Rumour at GlobalMart

"Did you hear? The CEO is relocating the entire office to Antarctica. Free penguins for everyone."

Someone said this to a colleague. That colleague told another. And another. And another.

We have a table that tracks who told whom:

from_personto_person
YogeshSujit
SujitSukrit
SukritSushant
SushantNikshitha
NikshithaRaj
… 22 rows total

The question we need to answer:

Starting from Yogesh — who are ALL the people who eventually heard this rumour, directly or indirectly?
And how many hops did it take to reach each person?

Why can't normal SQL do this?

We don't know in advance how long the chain is. Yogesh → Sujit is hop 1. Sujit → Sukrit is hop 2. The chain could be 3 or 10 or 20 long. We need the query to keep going automatically until the chain ends.

How to Play Chinese Whispers

1
Stay in your group. Sit in a line next to each other.
2
When instructor says "GO" — first person in your group goes to the next slide and reads the phrase silently. Do NOT say it out loud.
3
Whisper the phrase to the next person. One whisper only. No repeats allowed.
4
Pass it down the line. The last person says aloud exactly what they heard — no matter how different it sounds!

Strict rules:

  • NO phones — NO writing it down
  • NO showing the phrase to another group
  • NO asking "what?" or requesting a repeat
  • Last person MUST say something — even if unsure

After everyone has whispered: The instructor will reveal the original phrase. Compare it to what your last person heard. The bigger the difference — the better the lesson coming up!

Humans distort. SQL doesn't.

You just proved it with Chinese Whispers.

Chinese Whispers — just now

1
Person 1 reads a phrase and whispers it
2
Person 2 hears it imperfectly — distortion begins
3
Each hop = new chance of error — errors compound
N
Last person has a completely different message

Recursive CTE — you're about to build this

1
Base Case: anchor row — exact
2
Iteration 1: JOINs back to previous result — perfect
3
Each UNION ALL hop is deterministic — no distortion
N
Result at hop 9 is as accurate as hop 1 — always

Each UNION ALL iteration is a perfect whisper. Your SQL is going to trace 22 names — without losing a single word.

⌨️ Act 2 · SQL Challenge · 12 minutes

Write the Recursive CTE

The Challenge:

Write a Recursive CTE on #gossip_chain that finds all people who heard the rumour starting from Yogesh. Show the person's name, how many hops away they are, and the full chain path.

Your output must match this format:

person_who_heard_ithops_from_yogeshhow_they_heard_it
Sujit1Yogesh → Sujit
Sukrit2Yogesh → Sujit → Sukrit
Sushant3Yogesh → Sujit → Sukrit → Sushant
… continues until chain ends

Fill in the blanks — skeleton:

WITH ___________ AS (

    -- BASE CASE
    SELECT from_person, to_person,
           CAST(___ + ' → ' + ___ AS VARCHAR(MAX)) AS chain,
           1 AS level
    FROM  #gossip_chain
    WHERE ___ = 'Yogesh'

    UNION ALL

    -- RECURSIVE CASE
    SELECT g.from_person, g.to_person,
           CAST(___ + ' → ' + ___ AS VARCHAR(MAX)),
           ___ + 1
    FROM #gossip_chain g
    JOIN ___________ rt
        ON g.___ = rt.___
    WHERE ___ < 20
)
SELECT to_person AS person_who_heard_it,
       level     AS hops_from_yogesh,
       chain     AS how_they_heard_it
FROM ___________
ORDER BY level

Think Before You Code — 3 Questions

Discuss with your group for 2 minutes. Answer these before writing a single line of SQL.

1 — What is the Base Case?

Where does the chain start? What WHERE clause goes in the Base Case? How many rows will the Base Case produce for this data?

2 — What is the Recursive Case doing?

It takes the previous result and finds "who did this person tell next?" — what is the JOIN condition? Which column from the CTE connects to which column in #gossip_chain?

3 — When and why does the recursion stop?

Gaurav heard the rumour but told nobody. When the Recursive Case tries to find rows where from_person = 'Gaurav' — what does it return? And why does that make the whole recursion stop?

Hint 1 — The Base Case

Base Case = the starting seed

The Base Case is just a normal SELECT ... FROM #gossip_chain WHERE .... Ask yourself: who started the rumour? Filter for that person as the from_person. That gives you the very first row — the anchor the recursion starts from.

You also need to track the chain path and hop count:

The chain column should start as from_person + ' → ' + to_person. Use CAST(... AS VARCHAR(MAX)) so it can keep growing. The level column starts at 1.

Name your CTE — you'll reference it in the recursive part:

WITH your_cte_name AS ( ... UNION ALL ... )
Pick a name that makes sense for what this CTE represents.

Hint 2 — The Recursive Case

Recursive Case = "who did this person tell next?"

The Recursive Case JOINs #gossip_chain back to the CTE result. The key is the connection rule: the person who received the message in the previous step is now the sender in the next step. Which column from the CTE equals which column in #gossip_chain?

Growing the chain string:

At each hop, append the new receiver to the chain: previous_chain + ' → ' + new_to_person. Wrap in CAST(... AS VARCHAR(MAX)) again so it keeps growing.

Safety guard — don't forget this:

Add WHERE level < 20 in the Recursive Case. Without it, if the data had a cycle (A → B → A), the query would loop forever and hit SQL Server's recursion limit.

The Full Answer

WITH rumour_trail AS (

    -- ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    -- BASE CASE: Yogesh started the rumour
    -- ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    SELECT
        from_person,
        to_person,
        CAST(from_person + ' → ' + to_person AS VARCHAR(MAX)) AS chain,
        1 AS level
    FROM  #gossip_chain
    WHERE from_person = 'Yogesh'

    UNION ALL

    -- ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    -- RECURSIVE CASE: who did each person tell?
    -- ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
    SELECT
        g.from_person,
        g.to_person,
        CAST(rt.chain + ' → ' + g.to_person AS VARCHAR(MAX)) AS chain,
        rt.level + 1
    FROM #gossip_chain g
    JOIN rumour_trail rt
        ON g.from_person = rt.to_person
    WHERE rt.level < 20
)
SELECT
    to_person   AS person_who_heard_it,
    level       AS hops_from_yogesh,
    chain       AS how_they_heard_it
FROM   rumour_trail
ORDER BY level, to_person

Wrap-Up

What You Just Built — In Plain English

🏁

Base Case

The starting row. WHERE from_person = 'Yogesh'. Runs once. Produces hop 1.

🔄

Recursive Case

Extends the chain one hop at a time. g.from_person = rt.to_person is the connection rule. Runs once per hop.

🛑

Termination

When Gaurav's row is in the CTE, SQL looks for from_person = 'Gaurav' — finds nothing. Recursive Case returns 0 rows. SQL stops automatically.
