Aircraft Journey Mapper Using Recursive CTE

SkyConnect Airways needs the longest connected flight path for any aircraft, any day. Aditi already knows how to do this — Module 17's patient pathway logic, just wearing a pilot's uniform.

Module 15 Day 4 Trainer-Led Session
The Assignment

Same Shape of Problem, New Domain ✈️

Anuj Khokhar's Request

SkyConnect Airways runs multiple aircraft across different routes daily. Each aircraft makes several hops — stopping at airports before its final destination. Anuj, from Operations Control, needs the longest connected flight path for any aircraft on any given date.

Why it matters: maintenance scheduling, fuel planning, crew assignments, passenger routing — all of it depends on knowing an aircraft's full day, not just its next leg.

What Makes This Hard for Standard SQL

  • Each hop is a separate row in the table
  • Rows must be chained where one hop's destination = the next hop's source
  • Nobody knows the chain depth in advance — 2 hops today, 6 tomorrow
  • Standard SQL retrieves one level at a time. It cannot iterate on its own.

Solution: Recursive CTE — a query that references itself to build chains iteratively. If this sounds familiar, that's because it's exactly Module 17's pattern.

Connection rule: two hops connect if hop1.destination = hop2.source, for the same aircraft, same day. B737 on Jan 16: ORD → JFK → BOS → LGA — 3 hops, one aircraft, one very long day.

Recursive CTE Anatomy — Same Skeleton as Always

Two mandatory parts, connected by UNION ALL. If you can write this template with your eyes closed after Module 17, this whole session is just relabeling columns.

Template
WITH cte_name AS (

    -- PART 1: BASE CASE (Anchor Member)
    -- Does NOT reference the CTE itself
    -- Produces the initial rows recursion builds upon
    SELECT starting_columns, 1 AS hop_count
    FROM FlightTrips
    WHERE date = '2025-01-16'

    UNION ALL     -- combines base and recursive results

    -- PART 2: RECURSIVE CASE (Recursive Member)
    -- References the CTE from the PREVIOUS iteration
    -- Extends existing paths by connecting the next hop
    SELECT extended_columns, cte.hop_count + 1
    FROM FlightTrips f
    JOIN cte_name cte
        ON f.source_airport = cte.destination_airport  -- next starts where last ended
        AND f.aircraftcode  = cte.aircraftcode          -- same aircraft
        AND f.date          = cte.date                    -- same day
    WHERE cte.hop_count < 100                                -- termination guard
)
SELECT * FROM cte_name;

Notice what changed from the patient pathway version: column names. That's it. from_department became source_airport, patient_id became aircraftcode. The mechanism underneath never moved.

The Full Recursive CTE

Base + UNION ALL + recursive case + ROW_NUMBER() to pick the winner
SkyConnectOps
WITH flightpath AS (
    -- Base Case
    SELECT
        date, aircraftcode, source_airport, destination_airport,
        CAST(source_airport AS VARCHAR(MAX)) + ' > ' + CAST(destination_airport AS VARCHAR(MAX)) AS path,
        destination_airport AS last_airport, 1 AS hop_count
    FROM FlightTrips
    WHERE date = '2025-01-16'

    UNION ALL

    -- Recursive Case: extend each path by one more connected hop
    SELECT
        f.date, f.aircraftcode,
        fp.source_airport,                    -- keep original source
        f.destination_airport,               -- new end airport
        fp.path + ' > ' + CAST(f.destination_airport AS VARCHAR(MAX)) AS path,
        f.destination_airport AS last_airport,
        fp.hop_count + 1 AS hop_count
    FROM FlightTrips f
    INNER JOIN flightpath fp
        ON  f.source_airport = fp.destination_airport  -- new starts where last ended
        AND f.aircraftcode  = fp.aircraftcode
        AND f.date          = fp.date
    WHERE fp.hop_count < 100                           -- termination guard
)
-- Get the longest path per aircraft
SELECT aircraftcode, path AS longest_day_path
FROM (
    SELECT aircraftcode, path,
           ROW_NUMBER() OVER(PARTITION BY aircraftcode ORDER BY hop_count DESC) AS rn
    FROM flightpath
    WHERE date = '2025-01-16'
) ranked
WHERE rn = 1;

How Iteration Works — B737 on 2025-01-16

IterationActionPaths built
BaseRead all flights for this dateORD>JFK, JFK>BOS, BOS>LGA (hop=1)
Round 1Connect: source = previous destinationORD>JFK>BOS, JFK>BOS>LGA (hop=2)
Round 2Continue extendingORD>JFK>BOS>LGA (hop=3)
Round 3No more connected flights0 rows → STOP

Final result for B737:

ORD > JFK > BOS > LGA

ROW_NUMBER() PARTITION BY aircraft ORDER BY hop_count DESC picks the longest path (hop=3, rn=1).

Two termination mechanisms working together:

  • Natural: when no more connected flights exist, the recursive case returns 0 rows and stops on its own
  • Guard: WHERE hop_count < 100 catches you if the data ever has a genuine cycle — a plane that, somehow, flies in a circle forever

🚫 Common Mistakes on This Pattern

MistakeWhat Goes WrongFix
Missing the aircraftcode guard in the JOINB737's route quietly chains onto A320's flights — different aircraft, same airport, false connectionAlways AND on aircraftcode (and date) alongside the airport match
Forgetting CAST(... AS VARCHAR(MAX))Path string silently truncates at the source column's original lengthCast in the base case; the recursive case then inherits the wider type automatically
Filtering the date only in the outer SELECTRecursion runs across every date in FlightTrips before you ever filter — slow, and possibly wrong if two dates share airport codesFilter date in the base case's WHERE, same as Module 17's patient/date guard
No hop_count ceilingA genuine data cycle (rare, but happens) spins forever — Anuj's dashboard never loads, everyone assumes the network is downWHERE hop_count < 100 or OPTION (MAXRECURSION n)

Quiz 2 & Recap

Filtering by Starting Point ⚡

-- Same recursive CTE as before, then:
SELECT date, aircraftcode, longest_day_path
FROM (
    SELECT date, aircraftcode, path AS longest_day_path,
        ROW_NUMBER() OVER (PARTITION BY date, aircraftcode ORDER BY hop_count DESC) AS rn
    FROM flightpath
    WHERE date = '2025-01-15' AND source_airport = 'PHX'   -- paths that START from PHX
) ranked
WHERE rn = 1;

On 2025-01-15, which aircraft had the longest flight path starting from PHX?

A A320
B CRJ700
C B757
D B737
✅ A — A320. On 2025-01-15, the A320 operated the longest connected path beginning at PHX, tracing through multiple hops before landing for the night.

The takeaway Anuj actually cares about: whether it's patients moving through a hospital or aircraft moving through airports, the recursive CTE template doesn't change — base case, UNION ALL, recursive case with a self-JOIN, termination guard. Learn the shape once, relabel columns forever.
