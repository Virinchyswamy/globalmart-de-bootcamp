Sarah, Data Analyst intern at GlobalMart, received her first major assignment from the VP of Sales ahead of the Quarterly Business Review (QBR).

Leadership needed one report showing all of:

  • Sales per store within each region
  • Region subtotals (all stores combined)
  • Category subtotals across all regions

The Problem: The Messy UNION ALL Approach

The analytics team was writing multiple separate queries stitched together with UNION ALL — slow, error-prone, and hard to maintain:

-- Query 1: Sales by region and store
SELECT region, store, SUM(sales) FROM sales_data GROUP BY region, store

UNION ALL

-- Query 2: Sales by region only
SELECT region, NULL, SUM(sales) FROM sales_data GROUP BY region

UNION ALL

-- Query 3: Grand total
SELECT NULL, NULL, SUM(sales) FROM sales_data;
Problems with this approach:
  • Must write and maintain N separate queries
  • Manually insert NULL placeholders for alignment
  • One missing query breaks the entire report
  • Performance hit from scanning the table N times
The SQL solution:

ROLLUP, CUBE, and GROUPING SETS are extensions of GROUP BY that generate all these levels in a single query, in a single table scan. SQL produces the NULL values automatically — no manual placeholder insertion needed.

ROLLUP — Hierarchical Subtotals

ROLLUP creates a hierarchy of subtotals rolling from most detailed → grand total. For n columns → n+1 grouping levels.

GROUP BY ROLLUP(region, state, city)

-- 3 columns → 3+1 = 4 levels:
-- Level 1: (region, state, city)  ← most detailed
-- Level 2: (region, state)        ← state subtotal
-- Level 3: (region)               ← region subtotal
-- Level 4: ()                     ← grand total

-- ROLLUP always rolls up right-to-left.
-- Column order defines the hierarchy.
Key tip: NULL in the output = subtotal or grand total. NULL is not missing data — its position tells you the aggregation level.

Example output for ROLLUP(region, state, city):

regionstatecitytotal_sales
EastNew YorkNYC320,000
EastNew YorkNULL450,000 ← state subtotal
EastNULLNULL850,000 ← region subtotal
NULLNULLNULL2,500,000 ← grand total

CUBE — All Possible Combinations

CUBE generates every possible subset of groupings. For n columns → 2ⁿ grouping combinations.

GROUP BY CUBE(region, state, city)

-- 3 columns → 2³ = 8 combinations:
#GroupingDescription
1(region, state, city)Full detail
2(region, state)Region + state
3(region, city)Region + city
4(region)Region only
5(state, city)State + city
6(state)State only (cross-region!)
7(city)City only (cross-region!)
8()Grand total
Caution — exponential growth:
  • 3 columns → 8 groupings
  • 4 columns → 16 groupings
  • 5 columns → 32 groupings
  • Use CUBE judiciously on large datasets
ROLLUP vs CUBE:

ROLLUP produces 4 of the 8 combinations. CUBE adds 4 extra including "state totals across ALL regions" and "city totals across ALL regions" — cross-dimensional views ROLLUP cannot produce.

GROUPING SETS — Precisely What You Need

GROUPING SETS lets you define exactly which combinations to compute — the most efficient and explicit option.

Finance team needs exactly 3 levels (not all of CUBE's 8):

SELECT
    region,
    store,
    SUM(sales_amount) AS total_sales
FROM sales_data
GROUP BY GROUPING SETS (
    (region, store),  -- ① detailed: region+store
    (region),          -- ② regional summary
    ()                  -- ③ grand total
    -- ✗ no store-only rows (Finance doesn't need)
)
ORDER BY region, store;

Output (no store-across-regions row):

regionstoretotal_sales
CentralChicago180,000
CentralDallas200,000
CentralNULL380,000 ← region total
EastNew York225,000
EastNULL350,000 ← region total
NULLNULL1,250,000 ← grand total
Notice what's missing: No rows with region=NULL and a store value — Finance didn't ask for store totals across all regions, so GROUPING SETS excludes them.

Live Demo — All Three Operators on GlobalMart Data

-- Run each block separately and compare row counts

-- ROLLUP: 4 levels (region+state detail, region subtotal, grand)
SELECT l.region, l.state, ROUND(SUM(t.sales_amount),2) AS total_sales
FROM ex_transactions t
JOIN ex_orders o     ON t.order_id   = o.order_id   AND o.order_status = 'delivered'
JOIN ex_customers c ON o.customer_id = c.customer_id
JOIN ex_locations l ON c.postal_code = l.postal_code
GROUP BY ROLLUP(l.region, l.state) ORDER BY l.region, l.state;

-- CUBE: change just one word → observe extra rows where region=NULL, state=value
-- GROUP BY CUBE(l.region, l.state)

-- GROUPING SETS: custom — only region+state and grand total
-- GROUP BY GROUPING SETS ((l.region, l.state), ())
What to observe:
  • ROLLUP: rows with state=NULL → region totals. Final NULL,NULL row → grand total
  • CUBE: additional rows with region=NULL, state set → state totals nationally
  • GROUPING SETS: only exactly the rows you specified

Quiz 1 — Choose the Right Operator

Scenario: A retail company needs a hierarchical sales report showing sales by region, then by state within each region, then by city within each state — with subtotals at each level and a grand total.

Which aggregation operator should be used?

A — GROUPING SETS
B — CUBE
C — UNION ALL
D — ROLLUP

D — ROLLUP.

ROLLUP is designed for hierarchical aggregations. ROLLUP(region, state, city) generates exactly 4 levels: (region, state, city) → (region, state) → (region) → () grand total — the standard drill-down hierarchy the report requires.

CUBE produces 8 combinations including cross-regional totals the report doesn't need. GROUPING SETS requires explicit specification of each level. UNION ALL needs 4 separate queries.

Quiz 2 — True Statements about GROUPING SETS

Which of the following statements about GROUPING SETS are TRUE? (Select 2)

A — It is more efficient than CUBE when you need specific groupings
B — It allows you to specify exactly which groupings you need
C — It can only be used with two columns maximum
D — It generates all possible combinations automatically

A and B are TRUE.

✓ A: GROUPING SETS computes only the groupings you specify, making it more efficient than CUBE which computes 2ⁿ combinations — many of which you may not need.

✓ B: You explicitly list each grouping set — precise control over the report output.

✗ C: False — GROUPING SETS works with any number of columns.
✗ D: False — automatic combination generation is CUBE's behavior, not GROUPING SETS.

Quiz 3 — Reading NULL Values

In a ROLLUP output with columns (region, state, city), you see a row where region = 'East', state = NULL, city = NULL. What does this row represent?

A — Grand total row for all regions
B — The query has an error and should be fixed
C — The state and city data is missing from the database
D — Subtotal for the East region (all states and cities combined)

D — Subtotal for the East region.

In ROLLUP output, NULL means "aggregated across all values" — NOT missing data. When region='East', state=NULL, city=NULL → this is the East region subtotal (all states + cities within East combined). The grand total would have NULL in all three columns.
