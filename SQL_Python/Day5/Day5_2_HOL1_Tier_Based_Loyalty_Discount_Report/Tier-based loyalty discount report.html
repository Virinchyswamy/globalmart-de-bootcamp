Why orders + transactions are separate

orders gives us the date and customer link. transactions gives us the money. They share order_id — we join them first to get everything in one place before filtering and aggregating.

import pandas as pd

# Load all three datasets
customers_df = pd.read_excel("globalmart.xlsx", sheet_name='customers')
orders_df    = pd.read_excel("globalmart.xlsx", sheet_name='orders')
trans        = pd.read_excel("globalmart.xlsx", sheet_name='transactions')

# Step 0: Combine orders + transactions on order_id
order_trans_df = orders_df.merge(trans, on='order_id', how='inner')

Step 1 — Filter Last 6 Months

We don't want all-time history — only what customers have done in the last 6 months. This reflects current loyalty, not purchases from 3 years ago.

# Convert date column to datetime first
order_trans_df['order_purchase_date'] = pd.to_datetime(
    order_trans_df['order_purchase_date']
)

# Establish cutoff relative to latest order in data
# NOT today's date — use max date in dataset!
cutoff_date = (
    order_trans_df['order_purchase_date'].max()
    - pd.DateOffset(months=6)
)

# Filter rows where date >= cutoff
recent_orders = order_trans_df[
    order_trans_df['order_purchase_date'] >= cutoff_date
]

print(len(recent_orders))   # Should be 4,120
⚠️ Common Mistake — Using datetime.today() as the reference date. If the dataset is historical (e.g., ends in 2023), filtering from today gives 0 rows. Always use order_purchase_date.max() to get the most recent date in the data.
📊 Expected Result — After the 6-month filter, 4,120 orders remain. If you get ~9,818 rows, the filter didn't apply. If you get ~3,490, check that you're using >= not >.

❓ Why do we use pd.DateOffset(months=6) instead of timedelta(days=180)?

✅ DateOffset(months=6) respects calendar months exactly — 6 months back from March 15 = September 15. timedelta(days=180) is an approximation (6×30=180, but months vary). For business use cases, DateOffset is more accurate.

Step 2 — Aggregate Per Customer

We need two metrics per customer: how much they spent, and how many orders they placed — in the last 6 months.

# Aggregate: one row per customer
# total_spending = sum of sales_amt
# order_count   = count of order_id
customer_summary = recent_orders.groupby('customer_id').agg(
    total_spending = ('sales_amt', 'sum'),
    order_count   = ('order_id',  'count')
).reset_index()

# preview

#   C002         380.00          7
#   C003         5200.00         25

Named aggregation syntax

# new_col_name = (source_col, aggfunc)
agg(
    total_spending = ('sales_amt', 'sum'),
    order_count   = ('order_id',  'count')
)

groupby().agg() — what happens

Input rows→Output rows
Many orders per customer→One row per customer
sales_amt per order→total_spending (sum)
order_id per row→order_count (count)
💡 Why reset_index()? — groupby() makes customer_id the index. .reset_index() converts it back to a regular column so we can use it in later joins and functions.

❓ A customer placed 15 orders totalling ₹450. What tier and discount do they get? (Preview the rules before clicking)

✅ Silver tier (spending < 500) + 4% discount (order_count ≥ 10 → higher Silver tier discount). Always check BOTH spending AND order count — they interact.

The Tier Rules — assign_tier Function

The tier is determined by total spending alone. The order count only affects the discount within a tier.

Loyalty Tier Rules — Full Matrix

TierTotal SpendingOrders < 10Orders ≥ 10
Silver < 500 2% 4%
Gold 500 – 2000 6% 8%
Platinum > 2000 10% 15%
⚠️ Edge case — spending of exactly 500 → Gold (NOT Silver). Silver is strictly < 500. Use < for Silver boundary, <= for Gold upper boundary. 
# assign_tier — uses only total_spending
def assign_tier(row):
    if row['total_spending'] < 500:    # < 500
        return 'Silver'
    elif row['total_spending'] <= 2000: # 500 to 2000
        return 'Gold'
    else:                                # > 2000
        return 'Platinum'

# Apply to every row — axis=1 means row-wise
customer_summary['tier'] = (
    customer_summary.apply(assign_tier, axis=1)
)

# axis=0 → apply column-wise (default)
# axis=1 → apply row-wise (what we need here)

❓ A customer's total_spending is exactly 2000. What tier do they get?

✅ Gold — because 2000 <= 2000 is True (the Gold elif catches spending from 500 to 2000 inclusive). Platinum needs spending STRICTLY greater than 2000.

Step 3 — assign_discount Function

Now that every customer has a tier, we look at their order count within that tier to determine the exact discount percentage.

def assign_discount(row):
    if row['tier'] == 'Silver':
        return 4 if row['order_count'] >= 10 else 2
    elif row['tier'] == 'Gold':
        return 8 if row['order_count'] >= 10 else 6
    else:  # Platinum
        return 15 if row['order_count'] >= 10 else 10

# Apply discount function — needs 'tier' column first!
customer_summary['discount_applicable'] = (
    customer_summary.apply(assign_discount, axis=1)
)

Using ternary inside return

# This pattern: value_if_true if condition else value_if_false
return 4 if row['order_count'] >= 10 else 2

# Equivalent to:
if row['order_count'] >= 10:
    return 4
else:
    return 2
📝 Order matters — assign_tier must run first. assign_discount reads the 'tier' column, which doesn't exist until assign_tier creates it. Always tier → then discount.

❓ A Platinum customer with exactly 10 orders gets which discount?

✅ 15% — the threshold is order_count >= 10, so exactly 10 qualifies for the higher discount. The note in the scenario says "10 or more orders" → higher discount.

Step 4 — Build the Customer Loyalty Tier Report

We have customer_id, spending, order_count, tier, and discount. Now we bring in customer names by joining with the customers table.

# Join with customers_df to get customer names
# Left join: keep all customers from summary,
# even if they don't have a name in customers_df
loyalty_report = customer_summary.merge(
    customers_df[['customer_id', 'customer_name']],
    on='customer_id',
    how='left'
)

# Reorder columns for clean output
loyalty_report = loyalty_report[[
    'customer_id',
    'customer_name',
    'total_spending',
    'order_count',
    'tier',
    'discount_applicable'
]]

Why left join here?

We want to keep all customers who have orders in the last 6 months — even those whose details (customer_name) might be missing from the customers table. A left join keeps all rows from the left DataFrame.

Join typeKeeps rows where
left joinAll left rows + matches from right
inner joinOnly matching rows both sides
🔍 Selecting columns from right table — customers_df[['customer_id', 'customer_name']] brings only 2 columns from the customer table. Without this, you'd get all customer columns merged in — unnecessary noise.

❓ A customer has spending=480, orders=11. What are their tier and discount?

✅ Silver tier (480 < 500) with 4% discount (11 orders ≥ 10 → higher Silver rate). High order count, but low spending keeps them at Silver.

Step 5 — Load New Orders and Merge

The loyalty report is ready. Now we bring in the new orders and attach each customer's discount to their upcoming purchases.

# Step 5A: Load new orders dataset
new_orders_url = "https://...neworders.csv"
new_orders_df = pd.read_csv(new_orders_url)

# Normalize column names (avoid case mismatches)
new_orders_df.columns = new_orders_df.columns.str.lower()

# Step 5B: Left merge — new orders as base
# Why left? Keep ALL new orders, even if
# the customer has no loyalty history yet.
pricing_report = new_orders_df.merge(
    loyalty_report[[
        'customer_id', 'customer_name',
        'tier', 'discount_applicable'
    ]],
    on='customer_id',
    how='left'           # all new orders retained
)
✅ Always use left join for new orders — Some customers placing new orders may be brand-new with no purchase history. A left join retains all new order rows; an inner join would lose new customers entirely.

Handle new / unmatched customers

# New customers will have NaN for discount and tier
# Fill NaN: 0% discount, 'No Tier' label
pricing_report['discount_applicable'] = (
    pricing_report['discount_applicable'].fillna(0)
)
pricing_report['tier'] = (
    pricing_report['tier'].fillna('No Tier')
)

❓ After merging, 13 rows have NaN in customer_name. What does that mean?

✅ 13 orders in the dataset have a customer_id that doesn't match any entry in the customers table. This is a data quality issue — those customers exist in orders but not in the customer details file. That's why we use fillna(0) for discount so the math still works.

Step 6 — Calculate Discounted Price

Apply the formula and build the final output report.

The Formula

Discounted Price = Original Price × (1 − Discount% / 100)

Example: ₹1000 with 8% → 1000 × (1 − 0.08) = ₹920.00

# Calculate discounted price
pricing_report['discounted_price'] = (
    pricing_report['original_price']
    * (1 - pricing_report['discount_applicable'] / 100)
)

# Round to 2 decimal places
pricing_report['discounted_price'] = (
    pricing_report['discounted_price'].round(2)
)

# Final output — select and reorder columns
pricing_report = pricing_report[[
    'order_id', 'customer_id', 'customer_name',
    'original_price', 'discount_applicable', 'discounted_price'
]]

Full Solution — End to End

import pandas as pd

# Load data
customers_df = pd.read_excel("globalmart.xlsx", sheet_name='customers')
orders_df    = pd.read_excel("globalmart.xlsx", sheet_name='orders')
trans        = pd.read_excel("globalmart.xlsx", sheet_name='transactions')

# Combine orders + transactions
df = orders_df.merge(trans, on='order_id', how='inner')
df['order_purchase_date'] = pd.to_datetime(df['order_purchase_date'])

# Filter last 6 months
cutoff = df['order_purchase_date'].max() - pd.DateOffset(months=6)
recent = df[df['order_purchase_date'] >= cutoff]

# Aggregate
summary = recent.groupby('customer_id').agg(
    total_spending=('sales_amt','sum'), order_count=('order_id','count')
).reset_index()

# Tier + discount functions
def assign_tier(row):
    if   row['total_spending'] <   500: return 'Silver'
    elif row['total_spending'] <= 2000: return 'Gold'
    else: return 'Platinum'

def assign_discount(row):
    hi = row['order_count'] >= 10
    if   row['tier'] == 'Silver':   return 4  if hi else 2
    elif row['tier'] == 'Gold':     return 8  if hi else 6
    else:                           return 15 if hi else 10

summary['tier']              = summary.apply(assign_tier, axis=1)
summary['discount_applicable'] = summary.apply(assign_discount, axis=1)
loyalty_report = summary.merge(customers_df[['customer_id','customer_name']], on='customer_id', how='left')

# New orders
new_orders = pd.read_csv("new_orders.csv")
new_orders.columns = new_orders.columns.str.lower()
pricing = new_orders.merge(loyalty_report[['customer_id','customer_name','tier','discount_applicable']], on='customer_id', how='left')
pricing['discount_applicable'] = pricing['discount_applicable'].fillna(0)
pricing['discounted_price'] = (pricing['original_price'] * (1 - pricing['discount_applicable']/100)).round(2)

❓ After filtering, how many orders remain? And how many have no matching customer details?

✅ 4,120 orders remain after the 6-month filter. 13 orders have no matching customer details (NaN in customer_name after the left merge). These get 0% discount automatically via fillna(0).

❓ Which join type should you use when merging new orders with the loyalty report?

✅ Left join (how='left') — new_orders is the left table. This keeps ALL new orders, including orders from brand-new customers who have no loyalty history. An inner join would silently drop those orders.
