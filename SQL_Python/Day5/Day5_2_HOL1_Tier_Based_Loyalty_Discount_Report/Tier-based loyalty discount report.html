Step 1 — Summarize Customer History

Filter to the last 6 months of orders, then get each customer's total spending and order count.

SQL shapewhat we're computing
SELECT customer_id,
       SUM(sales_amt)   AS total_spending,
       COUNT(order_id) AS order_count
FROM   orders JOIN transactions USING(order_id)
WHERE  order_purchase_date >= 'cutoff_date'
GROUP BY customer_id;
↓ same shape, pandas syntax
python
order_trans_df = orders_df.merge(trans, on='order_id', how='inner') # the JOIN

order_trans_df['order_purchase_date'] = pd.to_datetime(order_trans_df['order_purchase_date'])
cutoff_date = order_trans_df['order_purchase_date'].max() - pd.DateOffset(months=6)
recent_orders = order_trans_df[order_trans_df['order_purchase_date'] >= cutoff_date]  # the WHERE

customer_summary = recent_orders.groupby('customer_id').agg(       # the GROUP BY
    total_spending=('sales_amt', 'sum'),
    order_count=('order_id', 'count')
).reset_index()

Step 3 — Turning Rules into Code

This is the cleanest SQL-to-Python bridge of the whole lab: a chain of conditions is a chain of conditions, whichever language you write it in.

SQL shapetier assignment as CASE WHEN
CASE
  WHEN total_spending < 500  THEN 'Silver'
  WHEN total_spending <= 2000 THEN 'Gold'
  ELSE 'Platinum'
END AS tier
↓ same shape, pandas syntax
python
def assign_tier(row):
    if row['total_spending'] < 500:
        return 'Silver'
    elif row['total_spending'] <= 2000:
        return 'Gold'
    else:
        return 'Platinum'

def assign_discount(row):
    if row['tier'] == 'Silver':
        return 4 if row['order_count'] >= 10 else 2
    elif row['tier'] == 'Gold':
        return 8 if row['order_count'] >= 10 else 6
    else: # Platinum
        return 15 if row['order_count'] >= 10 else 10

customer_summary['tier'] = customer_summary.apply(assign_tier, axis=1)
customer_summary['discount_applicable'] = customer_summary.apply(assign_discount, axis=1)

Step 4 — Finish the Loyalty Tier Report

One thing's still missing: names. customer_summary only knows IDs.

SQL shapebring in the customer name
SELECT s.*, c.customer_name
FROM   customer_summary s
LEFT JOIN customers c ON s.customer_id = c.customer_id;
↓ same shape, pandas syntax
python
loyalty_report = customer_summary.merge(
    customers_df[['customer_id', 'customer_name']],
    on='customer_id', how='left'
)

loyalty_report = loyalty_report[[
    'customer_id', 'customer_name', 'total_spending',
    'order_count', 'tier', 'discount_applicable'
]]

📌 Report 1 is now complete: customer_id | customer_name | total_spending | order_count | tier | discount_applicable

Step 5 — Price the New Orders

Merge the loyalty report onto new orders, then apply: discounted_price = original_price × (1 − discount / 100)

SQL shapeleft join, keep every new order
SELECT n.order_id, n.customer_id, l.customer_name,
       n.original_price,
       COALESCE(l.discount_applicable, 0) AS discount_applicable
FROM      new_orders n
LEFT JOIN loyalty_report l ON n.customer_id = l.customer_id;
↓ same shape, pandas syntax
python
pricing_report = new_orders_df.merge(
    loyalty_report[['customer_id', 'customer_name', 'tier', 'discount_applicable']],
    on='customer_id', how='left'                          # the LEFT JOIN
)

# new customers with no history → COALESCE equivalent
pricing_report['discount_applicable'] = pricing_report['discount_applicable'].fillna(0)
pricing_report['tier'] = pricing_report['tier'].fillna('No Tier')

pricing_report['discounted_price'] = (
    pricing_report['original_price'] * (1 - pricing_report['discount_applicable'] / 100)
).round(2)

💡 Why left join and not inner? A brand-new customer with zero order history still needs a price on their first order — they just get 0% until they earn a tier. Drop them with an inner join and Robert's checkout page shows nothing.

Checkpoint — Before You Touch the Notebook

Four quick ones. Click an option.

Q1. After a left join from orders to customer details on customer_id, how many orders have no matching customer?

13 rows come back with NaN in customer_name after the merge — real-world referential gaps, not a bug in your join.

Q2. After filtering to the last 6 months, how many orders remain?

4,120. If you get 9,818 or 9,201, your cutoff is off — it should be max(order_purchase_date) − 6 months, not today's date.

Q3. Which loyalty tier offers the highest possible discount?

Platinum, at 15% (10+ orders). Gold tops out at 8%, Silver at 4%. If an earlier version of this deck said Gold — that was wrong, this is the correction.

Q4. A customer spent exactly 500 in the window. Which tier?

Gold. Silver is strictly < 500. Since 500 is not less than 500, it falls straight into Gold — same boundary logic as a SQL CASE WHEN evaluated top to bottom.

Where This Lab Usually Breaks

Comparing dates before converting them

If order_purchase_date is still a string when you compute cutoff_date, the comparison silently does the wrong thing. Always pd.to_datetime() first.

Using today's date instead of the dataset's max date

This is historical data — "6 months ago" means 6 months before the latest order in the file, not 6 months before today.

Inner-joining new orders to the loyalty report

Silently drops every brand-new customer who has no order history yet. You want how='left', then fillna() the gaps.

Reversing the tier boundary (< vs ≤)

Gold is 500 to 2000 inclusive at the bottom. A spend of exactly 500 is Gold, not Silver — the same off-by-one trap SQL CASE WHEN chains have.
