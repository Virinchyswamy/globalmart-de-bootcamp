Quick Recap — List Comprehension

You saw this in Module 1: a comprehension is a one-line SELECT ... WHERE. It comes back today because good reusable code is often a small function wrapped around a comprehension.

python
# GlobalMart: customers whose name starts with "Alan"
customer_name = data['customer_name']
alan_fname = [name for name in customer_name
              if name.startswith("Alan")]
print('Customers named Alan:', len(alan_fname))  # 6
list comp = SELECT expr FROM iterable WHERE condition

This is still the fastest way to filter-and-transform a list in one line. Today's twist: what if you need to run this exact filter on ten different columns, in ten different notebooks? A comprehension alone can't help you reuse it across files — a function can.

What Is a Function? — Syntax

A function is a recipe: it takes ingredients (inputs), follows steps (logic), and produces a dish (output). Same recipe, same result, every time — that consistency is the entire point.

python
def add(x, y):
    print(f'Arguments passed are {x} and {y}')
    return x + y

Three parts of a function definition

PartWhat it is
defKeyword that starts a function definition
ParametersPlaceholders in parentheses — (x, y)
BodyIndented block after : — the actual logic

❓ Is a return statement mandatory in every function?

✅ No. If the function's job is to do something (print, save, log) rather than hand back a value, you can skip return entirely. greet("Enqurious") that only prints doesn't need one.

Calling a Function — and What "return" Really Does

python
def welcome_message(first_name):
    print("Welcome to our platform, " + first_name + "!")

This function is broken for an email system

It prints the message — it never returns it. A print statement produces console output, not a value you can hand to an email client. Swap print for return and the function suddenly becomes reusable anywhere, not just in a terminal.

The call flow

1. Control shifts to the function  →  2. The body executes  →  3. If a return is hit, control shifts back with that value

python
def welcome_message(first_name):
    return "Welcome to our platform, " + first_name + "!"

msg = welcome_message("Kriti")
send_email(msg)   # now this actually works

Parameters vs Arguments

The single most-confused pair of terms in this whole module. Here's the rule that never fails.

Parameter — the placeholder

def add(a, b):   # a, b = parameters
    return a + b

Declared in the function definition. It's a name waiting for a value.

Argument — the real value

add(2, 4)   # 2, 4 = arguments

Passed at the function call. It's the actual data the function operates on. Here, a=2, b=4, so a+b returns 6.

❓ welcome_name = "John"; greet(welcome_name) — is welcome_name a parameter or an argument at the call site?

✅ Argument. It's the value being handed to greet() at the moment of the call. The parameter is whatever name greet's definition uses internally (e.g. name).

Types of Parameters

python
# Positional — matched by position
def add(a, b): return a + b
add(10, 30)         # a=10, b=30

# Keyword — matched by name, order doesn't matter
add(b=30, a=10)     # same result

# Default — used automatically if no argument is given
def call_api(url = "https://www.api.com"):
    request.get(url)

call_api()                       # uses the default
call_api("https://custom.com")  # overrides it

When to use which

TypeUse it when
PositionalOrder is obvious and unlikely to be confused
KeywordMany parameters — clarity beats brevity
DefaultMost calls use the same value, occasionally overridden

❓ You need call_api() to work whether or not a URL is passed. Which design is correct — a required positional parameter, no parameter at all, or a default parameter?

✅ Default parameter. A required positional url errors out if nothing is passed; no parameter at all can't accept an override. Only def call_api(url="https://www.api.com") handles both cases.

Global vs Local Variable — Where Did My Data Go?

Dev Jaishwal: Swarna, I'm getting a NameError. Here's my code —

python — broken
def get_data(url = "https://www.api.com"):
    data = request.get(url)

get_data()
print(data)   # ❌ NameError: data is not defined

Swarna's diagnosis: data is a local variable — it only exists inside get_data's own scope. The moment the function returns, that name is gone. Printing it outside is asking for something that was never in this room.

python — fixed
def get_data(url="https://www.api.com"):
    data = request.get(url)
    return data          # hand it back

data = get_data()      # now it's a global name
print(data)         # ✅ works

Lambda Functions — One-Line, Anonymous

Dev Jaishwal: Defining a whole named function for something this small feels excessive:

def add(a, b):
    return a + b

Swarna Choudhury: That's exactly what lambdas are for — a one-off function you don't need a name and a whole def block for.

python
add = lambda a, b: a + b
add(5, 6)    # 11

# Or call it immediately, no name needed
(lambda a, b: a + b)(5, 6)  # 11

def vs lambda

deflambda
Named, reusableAnonymous, throwaway
Multiple statements OKSingle expression only
Can have loops, if/else blocksOne expression, no statements

💡 Lambdas shine as inline arguments — passed straight into map(), filter(), or sorted(key=...) without ever being named.

Debug It
Find the Bug — GlobalMart Discount Script
This code runs without crashing. It's still wrong. Spot it before revealing.
python — buggy
orders = [250, 450, 150, 500]
apply_discount = lambda x: x * 0.9
discounted_orders = []

for order in orders:
    discounted_orders.append(lambda order: apply_discount(order))

print("Discounted Orders:", discounted_orders)
# [<function>, <function>, <function>, <function>] ← not prices!

The bug: wrapping apply_discount(order) in another lambda just builds and appends new lambda objects — they're never called. The list fills with function objects, not numbers.

python — fixed
orders = [250, 450, 150, 500]
apply_discount = lambda x: x * 0.9
discounted_orders = []

for order in orders:
    discounted_orders.append(apply_discount(order))  # call it directly

print("Discounted Orders:", discounted_orders)
# [225.0, 405.0, 135.0, 450.0]
