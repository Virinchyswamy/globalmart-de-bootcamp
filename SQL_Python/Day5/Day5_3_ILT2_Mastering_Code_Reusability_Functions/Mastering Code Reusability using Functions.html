The Problem — Why We Need Functions

❌ Mark's code before functions

# Order 1 — Electronics
total1 = 1200 * 2
disc1  = total1 * 0.10
final1 = total1 - disc1
print(f"Order 1: ₹{final1}")

# Order 2 — Furniture
total2 = 800 * 3
disc2  = total2 * 0.10
final2 = total2 - disc2
print(f"Order 2: ₹{final2}")

# Order 3 — Clothing ...
# Order 4 — Shoes ...
# Imagine 100 more orders 😰

3 problems with this approach

1

Code Redundancy — The same discount logic is copy-pasted everywhere. If you have 100 orders, it appears 100 times.

2

Maintenance Nightmare — If the discount changes from 10% to 12%, you have to update it in 100 places. Miss even one = wrong results.

3

Readability Issues — As the code grows, it becomes impossible to understand at a glance what it's doing.

✅ The solution — write once, use anywhere

def calculate_final(price, qty, disc=0.10):
    total = price * qty
    return total * (1 - disc)

calculate_final(1200, 2)  # ₹2160.0
calculate_final(800, 3)   # ₹2160.0
# Discount change? Edit in ONE place ✅

List Comprehension — The Pythonic Filter

Jane at GlobalMart
"Mark, I need to find all customers whose first name starts with 'Alan' — I'll write a for loop and append each one."
Mark
"Good thinking, Jane — but there's a cleaner, more Pythonic way. One line instead of four."
# ❌ The verbose way (4 lines)
customer_name = data['customer_name']
alan_names = []
for name in customer_name:
    if name.startswith("Alan"):
        alan_names.append(name)

# ✅ List comprehension (1 line)
alan_fname = [
    name for name in customer_name
    if name.startswith("Alan")
]
print(len(alan_fname))  # 6

# High-value electronics (two conditions)
high_value = [
    s["product_name"]
    for s in sales_data
    if s["sales_amt"] > 500
    and s["category"] == "Electronics"
]
# ['Laptop', 'Headphones']

What Are Functions? The Recipe Analogy

🍪 The Cookie Recipe

Without a recipe, every batch of cookies turns out differently — different shapes, different taste. With a recipe, every batch is consistent, no matter who's baking or how many times you make them.

A function is the same idea. It takes ingredients (inputs → parameters), follows steps (the function body), and produces a result (output → return value).

3 benefits of using functions

1

Reduced Redundancy — Write the logic once. Call it 100 times.

2

Easy Maintenance — Change the discount from 10% to 12% in one place. It works everywhere instantly.

3

Improved Readability — Main code reads like plain English: "calculate_total → apply_discount → print_report"

# ❌ BEFORE — redundant logic everywhere
cost_order1 = (1200 * 2) * (1 - 0.10)
cost_order2 = (800  * 3) * (1 - 0.10)
cost_order3 = (500  * 1) * (1 - 0.10)
# ... repeated 97 more times


# ✅ AFTER — function does the work
def calculate_total(price, qty):
    return price * qty

def apply_discount(total, disc_pct=10):
    return total * (1 - disc_pct / 100)

# Main code — clean and readable
orders = [(1200, 2), (800, 3), (500, 1)]
for price, qty in orders:
    total = calculate_total(price, qty)
    final = apply_discount(total)
    print(f"Final: ₹{final}")

❓ If the discount changes from 10% to 15%, how many lines of code change in the AFTER version?

✅ Just 1 line — change disc_pct=10 to disc_pct=15 in the apply_discount definition. All 100 calls update automatically.

Function Syntax — How to Define a Function

Every Python function has 4 parts: the keyword def, a name, parameters in parentheses, and a body (indented).

# ┌─── keyword ─────────────────────────────┐
def greet(name):
#   ↑      ↑
#  name  parameter (placeholder)
    print("Hello, " + name)   # body (indented!)
    # No return needed here

# ─────── Function with return ────────────
def add(x, y):
    print(f"Arguments: {x} and {y}")
    return x + y  # sends result back to caller

# ─────── Calling functions ───────────────
greet("Enqurious")    # Hello, Enqurious
result = add(2, 4)   # result = 6
print(result)         # 6

❓ Is this function definition correct for sending welcome emails?

def welcome_message(first_name):
        print("Welcome to the platform, " + first_name)
✅ No — this only prints to screen. To send an email, you need to pass the message to an email function. It must return the string instead of printing it:

return "Welcome to the platform, " + first_name

Parameters vs Arguments

This is one of the most commonly confused concepts. Both relate to function inputs, but they are NOT the same thing.

Parameters — in the definition

Parameters are placeholders (variable names) written inside the parentheses when defining a function. They don't have actual values yet.

def add(a, b):
         ↑  ↑
     parameters — just placeholders
    return a + b

Arguments — in the function call

Arguments are the actual values you pass in when calling the function. They replace the parameter placeholders.

add(2, 4)
    ↑  ↑
arguments — real values (a=2, b=4)
# result = 2 + 4 = 6

Summary

ParametersArguments
WhereIn function definitionIn function call
What they arePlaceholdersActual values
Exampledef add(a, b)add(2, 4)
# Full example: greet a new user
def greet(name):                  # name = parameter
    return f"Welcome {name}!"

welcome_name = "John"            # a variable
greet(welcome_name)              # welcome_name is the ARGUMENT
# welcome_name → argument (value passed in)
# name         → parameter (receives the value)

❓ In greet(welcome_name), is welcome_name a parameter or an argument?

✅ Argument — it's the actual value passed to the function during the call. name inside the function definition is the parameter.

Types of Parameters

Python functions support 3 types of parameters, each offering different levels of flexibility.

1. Positional

Order matters. Arguments are matched to parameters by their position.

def add(a, b):
    return a + b

add(10, 30)  # a=10, b=30 → 40
add(30, 10)  # a=30, b=10 → 40
# same result here, but matters
# for non-commutative operations!

2. Keyword

Pass arguments by name — order doesn't matter anymore.

def add(a, b):
    return a + b

# Both calls produce same result
add(a=10, b=30)  # 40
add(b=30, a=10)  # 40 — order flipped ✅
# Named args = explicit & clear

3. Default

Pre-set value used if caller doesn't provide one.

def call_api(url="https://api.com"):
    return requests.get(url)

# Works with or without URL
call_api()                   # uses default
call_api("https://alt.com")  # overrides
# No argument? Use default ✅

GlobalMart example — combining all three types

def apply_discount(total, tier="Silver", discount=2):
    # total: positional — must always be provided
    # tier, discount: default — use defaults if not passed
    return total * (1 - discount / 100)

apply_discount(1500)                          # positional only → 1500 * 0.98
apply_discount(1500, tier="Gold", discount=8)  # keyword args, override defaults

❓ Which parameter type should you use if an API function should work with a default URL but allow overriding it?

✅ Default parameter — def call_api(url="https://www.api.com"): If no URL is passed, it uses the default. If a URL is passed, it overrides. Positional would require a URL every time; default provides flexibility.

Global vs Local Variables — Variable Scope

Every variable in Python lives in a "scope" — the region where it's accessible. Variables created inside a function are local; variables outside are global.

❌ Jane's broken code

def get_data(url="https://api.com"):
    data = requests.get(url)  # local var

get_data()
print(data)   # ❌ NameError: 'data' not defined!
# 'data' was created inside the function.
# It dies when the function ends.
# It's NOT accessible outside.

✅ Mark's fix — return the value

def get_data(url="https://api.com"):
    data = requests.get(url)
    return data        # send it out!

data = get_data()   # catch it in a global var
print(data)         # ✅ works now!

Global vs Local — key rules

Local VariableGlobal Variable
DefinedInside a functionOutside all functions
AccessibleOnly inside functionAnywhere in the file
LifetimeExists during call onlyExists until program ends
# Visual demonstration of scope
city = "Chennai"        # global — accessible everywhere

def show_city():
    zone = "South"      # local — only inside this fn
    print(city)         # ✅ can read global
    print(zone)         # ✅ local is accessible here

show_city()
print(city)            # ✅ global still accessible
print(zone)            # ❌ NameError — zone is LOCAL!

❓ A function calculates bonus but doesn't return it. The code prints bonus outside. What error?

✅ NameError: name 'bonus' is not defined — bonus is a local variable. It only exists inside the function. Fix: add return bonus and store it: bonus = calculate_bonus()

Lambda Functions — Anonymous One-Liners

Jane
"Mark, for a simple add function, using def feels excessive. What if I just need it once?"
Mark
"That's exactly what lambda functions are for — small, single-use functions with no def, no name, no return statement needed."
# Regular function — 3 lines
def add(a, b):
    return a + b

# Lambda equivalent — 1 line
add = lambda a, b: a + b
#        ↑      ↑   ↑
#     params  colon  expression (auto-returned)

# Calling a named lambda
result = add(5, 6)    # 11

# Calling without assigning to variable
(lambda a, b: a + b)(5, 6)   # 11

Regular def vs lambda

Multi-line?YesNo (single expression)
Best forComplex logicSimple one-off tasks

GlobalMart: apply_discount as lambda

# Apply 10% discount to any order
apply_discount = lambda x: x * 0.9

orders = [250, 450, 150, 500]
discounted = [apply_discount(o) for o in orders]
# [225.0, 405.0, 135.0, 450.0]

❓ What does (lambda x: x**2)(5) return?

✅ 25 — the lambda squares x, and it's immediately called with x=5. 5² = 25. This is a lambda defined and called in one shot (no variable assignment).

Lambda Debugging Exercise — Find the Bug

A classic mistake when using lambdas inside a loop. Read carefully before revealing.

❌ Buggy Code

orders = [250, 450, 150, 500]

apply_discount = lambda x: x * 0.9
discounted_orders = []

for order in orders:
    discounted_orders.append(
        lambda order: apply_discount(order)
    )

print("Discounted Orders:", discounted_orders)

❓ What does the print statement actually output? Why?

✅ It prints a list of lambda function objects, not discounted prices — something like [<function <lambda> at 0x...>, ...]. The code is appending the lambda function itself to the list, not calling it. The lambda takes an argument but it's never invoked!

✅ Fixed Code

orders = [250, 450, 150, 500]

apply_discount = lambda x: x * 0.9
discounted_orders = []

for order in orders:
    discounted_orders.append(
        apply_discount(order)  # ← CALL it!
    )
# [225.0, 405.0, 135.0, 450.0] ✅

# Even cleaner with list comprehension:
discounted_orders = [
    apply_discount(order)
    for order in orders
]

What went wrong?

The original code passed a new lambda expression to .append(). That appends the function object, not its result.

The fix: call the lambda (apply_discount(order)) and append its return value.

Lambda — Advantages and When to Use

✅ Advantages of Lambda

1

Concise — No def, no return keyword, no function name needed. Write and done in one line.

2

Inline definition — Can be written right where it's needed, especially as arguments to other functions.

3

Less overhead — Perfect for simple one-time operations where naming a full function would be overkill.

⚠️ When NOT to use lambda

If the logic has multiple steps, conditions, or loops — use a proper def function. Lambda is limited to a single expression.

# ❌ Don't force complex logic into lambda
f = lambda x: "Gold" if x >= 500 else "Silver" if x >= 200 else "Bronze"
# Hard to read — use def for this

Lambda in practice

# Sorting with lambda — key function
customers = [
    {"name": "Ravi",  "spending": 1500},
    {"name": "Priya", "spending":  800},
    {"name": "Ajay",  "spending": 3200},
]
# Sort by spending, highest first
sorted(customers, key=lambda c: c["spending"], reverse=True)

# map() — apply function to every element
prices = [100, 200, 300]
discounted = list(map(lambda x: x * 0.9, prices))
# [90.0, 180.0, 270.0]

# filter() — keep only matching elements
high = list(filter(lambda x: x > 150, prices))
# [200, 300]

❓ What does list(map(lambda x: x**2, [1,2,3,4])) return?

✅ [1, 4, 9, 16] — map() applies the lambda to every element: 1²=1, 2²=4, 3²=9, 4²=16. map() returns an iterator so we wrap with list() to see the results.
