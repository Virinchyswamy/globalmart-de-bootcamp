Why Bronze Alone Isn't Enough

GlobalMart's Bronze layer has 4 sources, ingested two different ways — and that difference is the whole reason a Silver layer exists.

SourceIngestion pathColumn casing landed in Bronze
orders, order_items (Postgres/Supabase)Lakeflow Connect (CDC)orderid — Lakeflow lowercases everything
customers, products, address, payments, payment_methods (ADLS files)AutoloaderCustomerID — keeps the source file's original casing
Two ingestion tools, two naming conventions, one catalog. Gold can't join bronze.orders.customerid to bronze.customers.CustomerID without translation — that's exactly what conform fixes.

1 Standardize — Fix the Values

The row is in the right table, right column — but the value itself is malformed: wrong type, extra characters, inconsistent format.

Real example — PhoneNumber format (bronze.customers)

Every phone number is 12 digits: GlobalMart's form prepends 91 but drops the + and the dash. Not wrong data — an unstandardized format.

standardized_phone = (
    bronze_customers
    .withColumn("PhoneNumber", col("PhoneNumber").cast("string"))
    .withColumn("PhoneNumber",
        when(
            (length(col("PhoneNumber")) == 12) & col("PhoneNumber").startswith("91"),
            concat(lit("+91-"), col("PhoneNumber").substr(3, 10))
        ).otherwise(col("PhoneNumber"))
    )
)

Real example — Email formatting errors

Standardize, don't discard. Both are recoverable format issues — quarantining these customers loses real people over a keyboard quirk.

2 Conform — One Vocabulary Across 4 Sources

GlobalMart's rule: every Silver table uses lowercase snake_case columns, no matter what casing the source or ingestion tool used.

Lakeflow source (small rename)

conformed_orders = bronze_orders \
  .withColumnRenamed("orderid", "order_id") \
  .withColumnRenamed("customerid", "customer_id")

Autoloader source (bigger rename)

conformed_customers = bronze_customers \
  .withColumnRenamed("CustomerID", "customer_id") \
  .withColumnRenamed("FirstName", "first_name")

Conforming a value, not just a name

bronze.address has underscore-for-space corruption in both State and AddressType (Tamil_Nadu). Fixing this is still conform — it's not correcting a wrong value, it's aligning representation with every other Silver text field.

conformed_address = bronze_address \
  .withColumn("State", regexp_replace(col("State"), "_", " ")) \
  .withColumn("AddressType", regexp_replace(col("AddressType"), "_", " "))

3 Enrich — Add Business Value That Doesn't Exist Yet

The rule: if multiple Gold tables or reports need the same derived value, compute it once — in Silver.

Real example — customer_tenure_days

Gold, BI dashboards, and Genie will all eventually ask for segments like New (<90 days), Regular (90–365), Loyal (>365). Computing tenure once in Silver means nobody repeats datediff(current_date(), registration_date) five different ways.

enriched_customers = bronze_customers \
  .withColumn("age", floor(datediff(current_date(), col("DateOfBirth")) / 365.25).cast("int")) \
  .withColumn("customer_tenure_days", datediff(current_date(), col("RegistrationDate")).cast("int"))

Real example — order fulfillment KPIs

None of the 4 raw date columns on an order is itself a metric — but the gaps between them are exactly what Operations' delivery-SLA dashboard needs.

Putting It Together — The Order Matters

1. Standardize
Fix values first
While logic is still easy to reason about
2. Conform
Align naming
Once values are trustworthy, joins across sources get simple
3. Enrich
Derive last
Build on data that's already clean and consistently named
