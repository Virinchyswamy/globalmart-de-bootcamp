Before You Start

The Pattern, Once

Every source in this lab follows the same 7 steps. Work through sources in order — order_items and payments check referential integrity against Silver tables you build earlier in this same notebook, so don't skip ahead.

StepWhat Happens
1Read Bronze, inspect schema
2DQ scan — tag every row with its first failing rule
3Investigate flagged rows — don't fix blind
4Fix / flag / quarantine — pick correctly (Day 5 ILT 2)
5Transform — standardize, conform, enrich
6Write to Silver (+ quarantine table if needed)
7Verify

Table-by-Table Summary

SourceSCD TypeKey Challenge
customersSCD2Email/phone fixes, under-18 quarantine (HOL 1)
productsSCD2 (initial load)Semi-structured — flatten structs, keep tags array
addressSCD1 (immutable)Recover PinCode leading zeros from duplicate text
ordersSCD1 (MERGE)Lakeflow lowercases columns; DELIVERY_BEFORE_SHIP flagged

paymentsSCD1 (overwrite)Conditional-null business rule (GiftCard/Coupon)

Why customers and products get SCD2: both are dimensions whose attributes can change over time (an email, a price). Orders and payments have one current truth at any moment — SCD1 is enough.

SOURCE 2 · SEMI-STRUCTURED

Products — Not a Flat Table

Think of bronze.products like a shipping manifest: most fields are plain text, but specs and supplier_info are folders-within-the-folder (structs), and tags is a list taped to the box (array). Inspect the real shape before assuming anything.

bronze_products = spark.table("gbmart.bronze.products")
bronze_products.printSchema()

# Autoloader routes unmatched fields to _rescued_data
# instead of silently dropping them -- check it stays empty.
rescued = bronze_products.filter(
    col("_rescued_data").isNotNull()).count()

SOURCE 3 · RECOVER A CORRUPTED VALUE

Address — Recovering PinCode

Autoloader inferred PinCode as numeric — any PIN starting with 0 already lost that digit before Spark showed it to us. Like a torn label rewritten elsewhere on the package: AddressLine1 embeds the same PIN as plain text (e.g. Guntur_082130), and text never strips leading zeros.

recovered_address = bronze_address.withColumn(
    "PinCode",
    when(pincode_len < 6,
        regexp_extract(col("AddressLine1"),
            r"(\d{5,6})\s*$", 1))
    .otherwise(col("PinCode")
        .cast("long").cast("string"))
)
SOURCE 3 · REMOVE DUPLICATION, THEN WRITE

Address — Clean AddressLine1, Write Silver

AddressLine1 embeds a duplicate of City/PinCode at the end, joined with inconsistent separators. Since City/PinCode already exist as clean columns, remove everything after the last comma or line break.

cleaned_address = recovered_address \
    .withColumn("AddressLine1",
        regexp_replace(col("AddressLine1"),
            r"[,\n][^,\n]*$", "")) \
    .withColumn("State",
        regexp_replace(col("State"), "_", " "))

Naming note: the Silver table is singular — silver.address, not silver.addresses — matching the real gbmart workspace convention that later Gold builds already read from.

SOURCE 4 · SCD1 VIA MERGE

Orders — One Current Truth

Lakeflow Connect lowercases every Postgres column (OrderID → orderid). An order has one current truth at any moment, so this is SCD1: matched rows get overwritten, unmatched rows get inserted — unlike customers/products, no history kept.

deltaTable.alias("tgt").merge(
    silver_orders_df.alias("src"),
    "tgt.order_id = src.order_id"
) \
 .whenMatchedUpdateAll() \
 .whenNotMatchedInsertAll() \
 .execute()
SOURCE 4 · APPLYING ILT 2'S LESSON

DELIVERY_BEFORE_SHIP — Flagged, Not Quarantined

Do not quarantine these rows. The full ILT 2 investigation found the 114 flagged orders are a timezone-cast artifact (UTC vs. IST), not real data errors — quarantining them previously orphaned 352 downstream order_items.

Keep every order. Add a _data_note = 'POSSIBLE_TIMEZONE_OFFSET_1DAY' column instead — fully joinable for revenue, still filterable for SLA analysis.

SOURCE 5 · REFERENTIAL INTEGRITY

Order Items — The Grain of fact_sales

No derived columns needed — pricing and totals get computed when joined with products at Gold. The important step: every order_id/product_id here must exist in the Silver tables you already built.

orphans = bronze_order_items.join(

    bronze_order_items.orderid == orders_df.order_id,

print(f"Orphans: {orphans.count():,}")  # must be 0
SOURCE 6 · A BUSINESS RULE, NOT A DQ GAP

Payments — Conditional-Null Columns

GiftCardAmount/CouponAmount are only populated when the matching *Usage flag is "Yes". Before assuming that's a data gap, confirm it's actually a clean, consistent rule.

bronze_payments.groupBy("GiftCardUsage").agg(
    count(when(col("GiftCardAmount").isNull(), 1))
        .alias("amount_null"),
    count(when(col("GiftCardAmount").isNotNull(), 1))
        .alias("amount_populated")
).show()

Expected: Usage='No' → amount always null; Usage='Yes' → amount always populated. Zero violations means it's a clean business rule, not a DQ issue.

SOURCE 7 · BUILT FRESH IN THIS LAB

Payment Methods — A Small Lookup Table

A small reference table (PaymentMethodID → MethodName) — exactly what a Gold payment-method dimension needs, and what silver.payments joins against to display "Credit Card" instead of PM-001.

Unlike the other 6 sources, Day 4 never ingested this one into Bronze. This lab builds gbmart.bronze.payment_methods first, using the identical Autoloader pattern used everywhere else in this course, before conforming it into Silver.
